## 1. 项目简介

光阴砚 AEONQUILL 的规划目标是一款高集成度的 Web 端多 Agent 视觉创作产品。正式品牌表达固定为：

- **以光为墨，以时为卷。**
- **一念落砚，万象成章。**
- **Shape Light. Weave Time.**

产品以统一项目、资产、任务和本地运行时为底座，通过三个模式入口组织核心创作能力：

- **均衡模式**：接近 Lovart 使用方式的无限画布、图像导入、排版、语义编辑与图像/视频生成工作流。
- **像素模式**：接近 Meowa、Aseprite 使用方式的像素绘制、图层与帧、调色板、角色资产和 Sprite 工作流。
- **智能视频**：从灵感或剧本开始，由文本模型生成结构化故事、角色、场景与镜头计划，再调用受控 ComfyUI 图像/视频模板和后期工具形成成片。

产品计划同时利用浏览器确定性图像算法、本机运行时和第三方生成 API：低成本、可逆的处理尽量在浏览器或本机完成；需要生成模型的任务通过本机推理或云端 API 执行。多个专业 Agent 负责理解目标和编排工具，但必须通过统一命令与工作流系统修改资产和画布。

旧名“妙绘”以及 `.miaohui`、`MIAOHUI_*` 等标识只作为现有项目包、环境变量和运行时的迁移兼容层；对外产品名称以“光阴砚 AEONQUILL”为准。兼容标识必须在有迁移、回滚和旧项目验证的独立任务中修改。

## 2. 宏观背景

通用图片生成服务通常擅长产生单次结果，但很难持续完成“生成—编辑—人工修正—版本比较—开发资产导出”的完整链路。像素画、Sprite Sheet 和游戏美术还要求确定的尺寸、调色板、透明边缘、帧布局和可重复导出，不能完全依赖生成模型。

AEONQUILL 因此不把核心价值限定为“接入更多模型”，而是建立以下统一基础：

1. 用无限画布表达内容、空间关系和创作上下文。
2. 用结构化元件表达图片、文字、像素画、画框和后续媒体对象。
3. 让人工操作与 Agent 操作共用受控命令。
4. 用工作流图编排浏览器、本机和云端处理。
5. 用不可变资产版本保存处理来源，避免覆盖原始素材。

## 3. 产品目标与能力边界

### 3.1 已确认的规划目标

| 领域 | 规划目标 |
| --- | --- |
| 创作界面 | 在一个无限画布内完成素材组织、选择、变换、编辑、比较和导出 |
| 图像处理 | 组合裁剪、颜色调整、蒙版、抠图、超分、重绘、扩图等能力 |
| 像素工作流 | 支持像素绘制、调色板、颜色量化、Dithering、Sprite 与后续游戏资产工作流 |
| 多 Agent | 使用主管 Agent 和专业 Agent 规划任务，通过受控工具执行，不直接写入任意画布 JSON |
| 混合计算 | 同时容纳浏览器算法、本机 ComfyUI 或图像 Worker、第三方生成 API |
| 商业化 | 面向正式发布与盈利，后续需要账号、额度、计费、成本追踪、许可证与合规体系 |

### 3.2 当前没有实现的范围

以下内容属于规划目标，不得视为当前能力：

- 云端业务 API、数据库、多租户队列、对象存储和 GPU 集群。
- 第三方模型 API、多供应商路由和云端生成回退。
- 真正的 Agent 推理、工具调用和工作流编译器。
- 多人协作、账号、权限、订阅和积分。
- 已签名公开桌面安装包、自动更新/回滚、生产部署、内容审核、运营监控和完整商业许可证登记。当前只有待 `QA-003` 独立验收的未签名 Tauri 阶段候选与作为回退验证的 Electron 便携目录。

## 4. 大体技术路线

| 层级 | 当前技术 | 规划方向 | 主要作用 |
| --- | --- | --- | --- |
| Web 应用 | React、TypeScript、Vite、CSS、空间索引、DOM 视口裁剪、Canvas 小地图 | 保持 DOM 主画布；仅在固定门槛超标时为高密度图片/像素/动画引入 PixiJS/WebGL 子场景 | 无限画布、属性面板、像素编辑和用户操作 |
| 浏览器图像处理 | Canvas 预览处理器、调整、裁剪、快速去背/插值草稿、K-means 量化与 Bayer 抖动 | Web Worker、OffscreenCanvas、WASM、ONNX Runtime Web | 低延迟草稿、参数预览和人工像素修正 |
| 业务控制面 | 单机 Node 桥接、持久化图片/视频 Job、CPU/GPU 资源调度、SSE、日志、错误、取消、幂等与本地资产 | API 服务、PostgreSQL、多租户队列、对象存储 | 当前统一承载本地图像与 H3 任务；未来承载账号、额度、真实费用和云端进度 |
| 计算执行面 | FFmpeg、rembg/u2netp、Real-ESRGAN NCNN 与按需 ComfyUI H3 | 独立 CPU Worker、隔离 GPU Worker、模型 API Adapter | 当前由统一调度器隔离 CPU/GPU 容量，GPU 任务严格单并发 |
| Agent 与工作流 | 当前仅有本地关键词快捷指令 | Supervisor、专业 Agent、工具注册表、经校验的 DAG | 将自然语言转换为可追踪、可取消、可计费的任务 |
| 桌面封装 | Tauri + 自包含 Node 22 sidecar 的 AEONQUILL Windows x64 未签名候选；Electron 回退壳 | 独立 QA、签名、原子更新/回滚、应用/运行时/模型分包与扩大干净机矩阵 | 把同一 Web/桥接内核封装为个人可试装软件，并继续推进正式分发门禁 |
| 商业系统 | 未实现 | 订阅、积分、配额、成本账本、许可证登记 | 控制毛利、滥用风险和商业使用边界 |

详细方案和实施顺序见[02-项目规划.md 第 2 节](02-项目规划.md#2-目标产品架构)。

## 5. 当前状态

仓库 `package.json` 标记的阶段包产品 SemVer 是 `0.3.0`，工程提交轨道已推进到 `V0.3.4`；两套版本口径分开记录。`V0.2` 原型完善周期已在 2026-08-15 通过独立 `QA-002` 验收并退出；`V0.3` 已完成安装态运行时控制面和发布工程候选收口。`QA-003` 先后发现 V0.3.2 候选的新 H3 产物仍使用旧品牌前缀，以及 V0.3.3 重建候选在关闭真实 Tauri 主窗口后仍后台驻留；`DEV-013` 与 `DEV-014` 已分别修复新产物命名和主窗口退出链。只有从 V0.3.4 干净提交重建的候选再次独立“通过”后本周期才能退出。当前实现已经支持：

- 画布平移、缩放、适应内容和缩略导航。
- 旋转 AABB 空间索引、240 屏幕像素 overscan 视口裁剪、动画帧相机提交和 Canvas 批量小地图；固定 331 元件场景已通过桌面/窄屏性能门槛。
- 元件选择、框选、多选、移动、八向缩放、锁定、显隐、复制、删除和基础属性调整。
- 文字、便签、形状、画框、图片、像素画等元件。
- AEONQUILL 品牌主页、类型化模式注册表、最近项目与真实本机运行时摘要，以及带稳定项目引用的 Hash 深链；三模式具有统一加载、空、失败、重试、恢复和异常边界，刷新、返回与最近项目重开保持真实上下文。
- 独立像素模式的严格像素文档、图层、帧、调色板、洋葱皮和批量单笔撤销；PNG/WebP 可通过最近邻缩放、确定性调色板与三种抖动转换为可编辑像素文档，动画预览不污染 revision/undo，并可成套导出或重开项目 JSON、当前帧 PNG、Sprite Sheet 与 metadata。
- 独立智能视频模式的严格故事 Schema、确定性场景/镜头拆解、角色与场景连续性基准、受控任务 DAG，以及 ready/blocked 执行清单、用户确认、内容寻址帧校验和固定 H3 文生/图生队列适配；外部文本 API 与整部长剧自动成片链路仍未接入。
- 文生视频、图生视频与可播放视频元件；图生首帧会先规范化到目标画幅。
- 图片处理实验室、前后比较、处理任务、派生节点、处理关联线和可开关处理栈。
- 调整、裁剪、浏览器草稿、可变尺寸像素化与人工修正；正式任务支持 FFmpeg Lanczos、调色板像素化、锐化、透明边清理、Alpha 蒙版区域合成、rembg/u2netp 去背景和 Real-ESRGAN 超分。
- Impact SAM 元素提取可按需唤醒 ComfyUI，并把透明元素继续送入确定性的主体突出、背景压暗或背景虚化；每一步都创建独立资产版本和来源关系，原图不覆盖，原图或非 Alpha 派生图不能误入区域编辑。
- 调色板、本地 K-means 量化、Bayer 有序抖动、本地保存、撤销重做和 JSON 导出。
- 桌面端、窄屏抽屉、移动端底部工具栏与移动端实验室布局。
- 固定 MiniMax H3 Turbo API 工作流、ComfyUI/GPU 健康检查、真实节点/采样进度、持久化任务、错误建议、取消、重试、MP4 Range 服务和结果回填；所有新 H3 输出与上传临时文件使用 `AEONQUILL/` 和 `aeonquill-*` 命名，旧协议标识只保留在兼容边界。
- 可配置的统一启动器；ComfyUI 可按任务冷启动，在本地与 Comfy 队列均为空后倒计时关闭，并把日志写入 `.runtime/comfyui.log`。
- 导演控制、图生可选末帧、参数复用，以及标注最低显存与生成/交付尺寸的 8GB 预览、细节、720P 交付和高显存实验档位。
- 图片与视频任务共享持久化资源调度器；CPU 图片任务可按配置并发，GPU 图片与 H3 视频严格单并发并支持优先级、等待取消和超时。光阴砚托管的空闲 ComfyUI 会在图片模型执行前关闭以释放显存，外部 ComfyUI 不会被擅自终止。
- 本机桥接进程重启会轮换会话凭据；浏览器任务流在断线后显式续签、退避重建 SSE，并用服务端完整 Job 快照追平重启期间完成的任务，无需整页刷新。
- 正式图片资产按原始 SHA-256 保持权威，同时懒生成 512px WebP 缩略图和 1600px WebP 预览图；画布不直接解码受管原图，项目 GC 同步清理派生缓存。
- Electron/Tauri 共享同一回环桥接、安全边界和任务内核；Tauri 已收束为 AEONQUILL Windows x64 主候选，发布组验证自包含 Node 22 sidecar、当前用户未签名 NSIS、五类应用数据目录、旧 runtime 数据回退、release manifest/SHA-256 和隔离安装—启动—卸载，Electron 保留为可逆回退壳。

`V0.2.8` 的“通过”只确认上述单机原型链路在独立桌面/窄屏、恢复、导出、错误与安全矩阵下无阻断缺陷，不表示商业系统或 Stage B 已完成。`REL-003` 的发布组自检也不能替代 `QA-003`；两次 QA 退回均使对应安装包哈希立即失效，当前修复仍须重建和复测。阶段包没有 Windows 代码签名、自动更新/回滚或完整第三方许可证/SBOM，不得公开标注为正式商业发行版。既有独立 QA 没有重复消耗显存生成 H3，而是审计已有真实 5 秒产物与空闲关闭证据；隔离环境缺少的 SAM、rembg 与 Real-ESRGAN 依赖保持真实阻塞，未冒充实跑；`AI-001` 每类 20 张的正式算法样本门也仍未达到。
