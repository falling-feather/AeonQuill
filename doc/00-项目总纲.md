## 0. 阅读边界

光阴砚 AEONQUILL 是以统一项目、素材库、本机任务和受管运行时为底座的单机创作软件，提供均衡画布、像素动画与智能视频三个模式。浏览器和Windows桌面共享同一业务内核。

本文只说明产品方向与文档分工。当前功能轨、实际安装源码、运行路径和可执行能力以[01-开发者文档](01-开发者文档.md)为准；未完成范围、模型/数据及人工验收门以[02-项目规划](02-项目规划.md)为准；所有已发生版本、构建和历史验证进入[03-开发历史](03-开发历史.md)。这里不再复制容易过期的版本流水和测试数量。

模型任务需要实际依赖与资源；自动执行结果保留候选与明确批准环节。当前交付面向本机验证，公共发行、自签名历史和早期商业方向不能被当作本轮发布承诺。

## 1. 项目简介

光阴砚 AEONQUILL 的规划目标是一款高集成度的 Web 端多 Agent 视觉创作产品。正式品牌表达固定为：

- **以光为墨，以时为卷。**
- **一念落砚，万象成章。**
- **Shape Light. Weave Time.**

产品以统一项目、资产、任务和本地运行时为底座，通过三个模式入口组织核心创作能力：

- **均衡模式**：接近 Lovart 使用方式的无限画布、图像导入、排版、语义编辑与图像/视频生成工作流。
- **像素模式**：接近 Meowa、Aseprite 使用方式的像素绘制、图层与帧、调色板、角色资产和 Sprite 工作流。
- **智能视频**：从灵感或剧本开始，由文本模型生成结构化故事、角色、场景与镜头计划，再调用受控 ComfyUI 图像/视频模板和后期工具形成成片。

产品计划同时利用浏览器确定性图像算法、本机运行时和第三方生成 API：低成本、可逆的处理尽量在浏览器或本机完成；需要生成模型的任务通过本机推理或云端 API 执行。多个专业 Agent 负责理解目标和编排工具，但必须通过统一命令与工作流系统修改资产和画布。

旧名“妙绘”以及 `.miaohui`、`MIAOHUI_*` 等标识只作为现有项目包、环境变量和运行时的迁移兼容层；对外产品名称以“光阴砚 AEONQUILL”为准。兼容标识必须在有迁移、回滚和旧项目验证的独立任务中修改。

## 2. 宏观背景

通用图片生成服务通常擅长产生单次结果，但很难持续完成“生成—编辑—人工修正—版本比较—开发资产导出”的完整链路。像素画、Sprite Sheet 和游戏美术还要求确定的尺寸、调色板、透明边缘、帧布局和可重复导出，不能完全依赖生成模型。

AEONQUILL 因此不把核心价值限定为“接入更多模型”，而是建立以下统一基础：

1. 用无限画布表达内容、空间关系和创作上下文。
2. 用结构化元件表达图片、文字、像素画、画框和后续媒体对象。
3. 让人工操作与 Agent 操作共用受控命令。
4. 用工作流图编排浏览器、本机和云端处理。
5. 用不可变资产版本保存处理来源，避免覆盖原始素材。

## 3. 产品目标与能力边界

### 3.1 已确认的规划目标

| 领域 | 规划目标 |
| --- | --- |
| 创作界面 | 在一个无限画布内完成素材组织、选择、变换、编辑、比较和导出 |
| 图像处理 | 组合裁剪、颜色调整、蒙版、抠图、超分、重绘、扩图等能力 |
| 像素工作流 | 支持像素绘制、调色板、颜色量化、Dithering、Sprite 与后续游戏资产工作流 |
| 多 Agent | 使用主管 Agent 和专业 Agent 规划任务，通过受控工具执行，不直接写入任意画布 JSON |
| 混合计算 | 同时容纳浏览器算法、本机 ComfyUI 或图像 Worker、第三方生成 API |
| 商业化 | 面向正式发布与盈利，后续需要账号、额度、计费、成本追踪、许可证与合规体系 |

### 3.2 当前没有实现的范围

以下内容属于规划目标，不得视为当前能力：

- 云端业务 API、数据库、多租户队列、对象存储和 GPU 集群。
- 托管式第三方模型账号、自动多供应商路由和云端生成回退；当前仅有用户自带密钥、进程内存保存的受控 Adapter。
- 无人值守跨媒体 Supervisor、完整生成 DAG 和工作流编译；当前已实现严格 `CreativePlan v1`、三模式安全工具目录、服务端有界上下文、单轮 BYOK 文本计划编译，以及智能视频四类文本节点的服务端权威、可干预多轮制片督导，但每轮仍需人工批准，媒体节点不会自动执行，也尚无真实供应商默认接入。
- 多人协作、账号、权限、订阅和积分。
- 受 Windows 公共信任的桌面签名、自动更新/回滚、生产部署、内容审核、运营监控和完整商业许可证登记。当前已有 `REL-012` 自签名 Tauri 开箱即用测试包；该签名可核对完整性和主体，但不能替代受信任的 OV/EV/Trusted Signing。

## 4. 大体技术路线

| 层级 | 当前技术 | 规划方向 | 主要作用 |
| --- | --- | --- | --- |
| Web 应用 | React、TypeScript、Vite、CSS、模式级动态入口、空间索引、DOM 视口裁剪、Canvas 小地图；固定 Edge 冷/暖、三模式与 30 分钟资源门 | 将既有浏览器机器门扩展到 Tauri/跨硬件矩阵；仅在固定画布门槛超标时为高密度图片/像素/动画引入 PixiJS/WebGL 子场景 | 产品壳按需加载三工作台，无限画布、属性面板、像素编辑和用户操作 |
| 浏览器图像处理 | Canvas 预览处理器、调整、裁剪、快速去背/插值草稿、K-means 量化与 Bayer 抖动 | Web Worker、OffscreenCanvas、WASM、ONNX Runtime Web | 低延迟草稿、参数预览和人工像素修正 |
| 业务控制面 | 单机 Node 桥接、持久化图片/视频 Job、CPU/GPU 资源调度、SSE、日志、错误、取消、幂等与本地资产 | API 服务、PostgreSQL、多租户队列、对象存储 | 当前统一承载本地图像与 H3 任务；未来承载账号、额度、真实费用和云端进度 |
| 计算执行面 | FFmpeg、rembg/u2netp、Real-ESRGAN NCNN 与按需 ComfyUI H3 | 独立 CPU Worker、隔离 GPU Worker、模型 API Adapter | 当前由统一调度器隔离 CPU/GPU 容量，GPU 任务严格单并发 |
| Agent 与工作流 | `CreativePlan v1`、三模式安全工具目录、服务端脱敏结构摘要、单轮 BYOK 文本计划编译、智能视频可干预多轮督导、文档副本预览、SHA-256 审批、权威复编与 SQLite 原子回执；H3 已有版本化场景提示词 Agent | 更完整的创作质量校准、成本/审核与模型路由 | 当前允许确定性本机或用户自带文本模型提出计划；智能视频督导可按生产事实逐轮推进四类文本节点，但每轮仍必须经同一执行内核和显式批准，媒体节点通过显式提议、确认、受管Job与候选/试听复核继续执行，不自动接受结果 |
| 桌面封装 | Tauri + 自包含 Node 22 sidecar；主 NSIS 与固定 ComfyUI/Python/H3 运行时拆分离线交付，包根和运行时树均有 SHA-256 清单；`App`/`UserData`/`output` 采用 D 盘同级便携布局，0.6.0 测试版已实装；`REL-012` 已完成 69.27 GiB cu130 独立闭包、唯一下载目录、“falling feather制作”三组件自签名、冷启动、全树与隐私验证 | 受信任 OV/EV/Trusted Signing、原子更新/回滚、运行时增量更新、SBOM 与扩大干净机矩阵 | 把同一 Web/桥接内核封装为个人可试装软件，并继续推进正式分发门禁 |
| 商业系统 | 未实现 | 订阅、积分、配额、成本账本、许可证登记 | 控制毛利、滥用风险和商业使用边界 |

当前方案和实施顺序见[02-项目规划.md 第 4—5 节](02-项目规划.md#4-已批准的中期更新规划)。

## 5. 当前状态

产品已经具备可在本机开发和运行的三模式工程链；本轮目标是交付可由用户验收的本机候选。产品SemVer沿用0.7.1，区分源码与安装态时使用01记录的功能轨及完整source commit，不能单看SemVer。

- 均衡模式具备手动连接、视觉边界对齐、参数化本地效果、蒙版、配方复用与保存失败恢复；语义图像任务依赖受管模型，输出保留不可变身份。
- 像素模式具备关联Cel、选区变换、系统剪贴板、Aseprite互通、动画/游戏资产和有界Worker计算；具体格式支持与限制以[像素手册](01-子文档/17-像素动画片段与跨帧编辑.md)为准。
- 智能视频通过连续性图、镜头候选、声音字幕和跨媒体提议组织创作；支持本机对齐与局部混音，真实媒体仍需逐项复核，未实现口型同步。
- 工作流中心核对节点、共享模型根、权重SHA、LoRA绑定与参数配方。缺少主题、授权素材和验证数据时暂缓本机训练，不以无意义训练或夹具推断模型质量。

本机性能、API、浏览器和原生工程门与人工观感分开记录。更多素材的图像/人物视频一致性、声音准确性和完整跨媒体质量仍需用户复核；没有完成的质量任务保留在02，不因构建成功自动关闭。数据可携带、空间治理、运行时启停、任务归档和诊断均遵循01的当前协议。
