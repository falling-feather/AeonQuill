## 1. 里程碑定义

`V0.2` 的目标不是继续堆叠孤立按钮，而是把 `V0.1.6` 的三模式第一纵切推进为可连续演示、可恢复、可导出、失败可解释并可独立验收的单机原型。

本周期完成时，一名未参与开发的验收者应当只依赖页面提示完成以下动作：

1. 从主页进入任一模式，并在刷新、返回主页和再次打开后恢复可识别的工作状态。
2. 在均衡模式把图片的语义选区转成受控蒙版操作或局部处理任务，并得到不覆盖原图的派生资产。
3. 在像素模式导入图片、确定性像素化、人工修正、预览帧动画并导出可重新打开的项目与 Sprite 产物。
4. 在智能视频模式把灵感或剧本编译成受控镜头计划，识别可执行与缺依赖任务，并把允许的镜头提交给现有本机任务队列。
5. 对冷启动、排队、执行、取消、失败、重试和完成状态获得一致且可操作的界面反馈。

“页面存在”“按钮可点击”“演示数据看起来完整”均不单独构成完成证据。

## 2. 四条必须闭环的纵向链路

### 2.1 统一产品壳与恢复链

```text
主页
→ 选择模式或最近项目
→ 加载/空状态/错误状态
→ 进入工作台
→ 产生可恢复草稿或正式项目变更
→ 返回主页
→ 再次打开并恢复到正确模式与项目
```

产品壳只聚合真实模式、真实本机能力和真实项目摘要。运行时未安装、休眠或报错时必须原样解释，不得以静态“可用”卡片掩盖状态。

### 2.2 均衡模式语义局部编辑链

```text
图片资产
→ 正/负语义点或蒙版笔刷
→ Mask 预览与边缘参数
→ 选择白名单局部操作
→ 参数校验与受控 Job
→ 进度/取消/重试
→ 新 AssetVersion + 派生 Image Node + provenance
```

本周期保证至少一组完全离线、确定性的蒙版操作可执行；生成式 Inpaint 只有在本机受审计模型和节点真实可用时才启用。不可用能力必须给出依赖和恢复动作，禁止返回伪结果。

### 2.3 像素资产生产链

```text
PNG/WebP 导入
→ 尺寸/调色板/抖动参数
→ 严格 PixelDocument
→ 图层与帧编辑
→ 动画预览
→ 项目 JSON + PNG/Sprite Sheet + metadata 导出
→ 重新导入并保持等价
```

像素数据继续以索引数组、图层和帧为权威；禁止为每个像素创建画布元件。导入转换必须可重复，项目往返后文档语义必须等价。

### 2.4 智能视频计划执行链

```text
灵感/剧本
→ 严格故事项目
→ 场景/角色/镜头计划
→ 任务依赖与可执行性检查
→ 用户确认受控执行清单
→ 现有 JobScheduler / 固定 workflow ID
→ 进度/取消/重试/结果资产
```

首轮不追求自动生成整部长剧。必须先证明一个已确认镜头能够从计划进入既有 H3 文生或图生任务；缺少首帧、末帧、模型或显存时保持阻塞并给出原因，不允许把任意 ComfyUI JSON 送入执行面。

## 3. 完成定义与验收矩阵

| 领域 | 必须可观察结果 | 自动证据 | 人工证据 |
| --- | --- | --- | --- |
| 产品壳 | Hash 深链刷新不丢模式；主页可打开真实最近项目；加载、空、错、恢复状态完整 | 路由/状态单元测试、类型、构建 | 1440×900 与 390×844 键盘/触控主流程，无页面级横向溢出 |
| 均衡模式 | 语义点或笔刷生成 Mask；至少一种离线局部操作完成；输出为新版本并保留来源 | 请求白名单、Mask 参数、Job/SSE、取消/重试测试 | 原图与派生图可对比，错误提示可执行，原资产未覆盖 |
| 像素模式 | 图片导入转换、图层/帧编辑、动画预览、项目与 Sprite 往返 | 固定样本哈希、文档迁移、导入导出等价测试 | 用户无需开发工具完成一次导入—修正—导出—重开 |
| 智能视频 | 计划任务显示 ready/blocked；已确认镜头进入现有受控队列并获得状态 | 计划编译、依赖、workflow 白名单、任务映射测试 | 至少一条安全档镜头完成或在真实缺依赖处给出可操作阻塞 |
| 生命周期 | 冷启动、排队、执行、取消、失败、重试、完成用统一语言表达 | Job 恢复、SSE 重连、进程退出与资产保留回归 | 刷新与桥接重启后状态不伪造，已完成资产仍可打开 |
| 质量门禁 | 无高优先级控制台错误、无路径/密钥泄漏、文档与 Git 可追溯 | `validate:quick`、文档校验、项目对接校验 | 独立 QA 按本表给出通过/退回证据 |

阶段结论只允许以下三种：

- **通过**：四条纵向链路全部达到必须结果，且独立 QA 无阻断缺陷。
- **有条件通过**：所有核心链路可用，存在已登记且不影响数据安全和主流程的次要缺陷。
- **退回**：任一链路只能依靠演示数据、静默降级、不可恢复状态或越过白名单完成。

## 4. 共享架构边界

1. `CanvasDocument`、`PixelDocument`、`StoryProject` 各自保持单一状态权威，不互相复制整份状态。
2. 人工按钮、快捷键和未来 Agent 必须落到同一受控命令或工具契约；Agent 不直接修改 React 状态。
3. 图片、视频、Sprite 和蒙版二进制进入不可变资产或导出文件，不进入主文档 JSON 的内嵌 Base64。
4. 所有 ComfyUI 调用只经过版本化工作流注册表、节点/参数白名单与本机能力探测。
5. 长任务统一复用 `JobStore`、`JobScheduler`、SSE、取消、重试、恢复和输出版本，不为每个模式建立私有队列。
6. 本机桥接继续只监听回环地址；前端不持有第三方 API 密钥，也不直接访问 ComfyUI。
7. 模式间共享资产时传递稳定资产版本 ID 和必要元数据，不传递组件私有状态。

## 6. 质量证据

最低证据集合：

```text
npm run test:unit
npm run typecheck
npm run build
npm run validate:docs
npm run validate:quick
python C:/Users/niu-h/.codex/skills/wen-dang-zheng-li/scripts/validate_project_docs.py --project-root D:/代码玩具测试/pic
python C:/Users/niu-h/.codex/skills/xiang-mu-dui-jie/scripts/validate_project_handoff.py D:/代码玩具测试/pic
```

除命令结果外，QA 必须记录：

- 使用的提交与机器环境。
- 桌面和窄屏主路径。
- 使用的固定输入资产及输出位置或哈希。
- 取消、失败、刷新恢复和本机运行时休眠行为。
- 控制台 error/warning、页面级溢出、路径/密钥泄漏检查。
- 未执行的真实 GPU 检查及原因；未执行项不得写成通过。

## 7. 版本与 Git 规则

- `V0.2.x` 已由 `V0.2.0` 启动，并在 `V0.2.8` 经独立验收退出；后续版本轨道仍由主开发另行分配。
- 各工作组完成实现和范围内验证后返回 `[READY-FOR-VERSION]`；小版本由主开发按集成顺序发放。
- 一个小版本对应一个任务和一个提交。工作组不得预占编号、合并其他分支或直接推送 `main`。
- 长期工作树从 `V0.2.0` 基线建立本周期分支；旧 `V0.1` 分支保留为历史事实，不强制改写。
- QA 已在实现波次集成后以独立任务和 `V0.2.8` 记录证据；结论为通过，但不得外推为商业系统或 Stage B 完成。

## 8. 明确排除项与停止条件

本周期不包含：账号、支付、订阅、积分、云多租户、多人实时协作、任意 ComfyUI 节点市场、自动生成完整长剧、正式代码签名、公开商店发布和商业法务结论。

遇到以下任一情况必须停止对应能力并显示真实状态：

- 本机模型、Custom Node、权重许可或显存要求无法确认。
- 工作流需要前端提交任意图、文件系统路径或执行代码。
- 处理结果只能覆盖原资产，无法形成新版本或导出备份。
- 刷新或桥接重启后把未知状态错误显示为成功。
- 自动降级会实质改变用户结果但界面没有说明或确认。
