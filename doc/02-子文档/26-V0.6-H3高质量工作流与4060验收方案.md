# 光阴砚 AEONQUILL — V0.6 H3 高质量工作流与 RTX 4060 验收方案

> **文档梗概**：定义 V0.6 视频质量专项的事实基线、工作流矩阵、运行时门控、RTX 4060 Laptop 8GB 验收阶梯与商业封装边界。目标不是把低分辨率插值宣传成 720P，而是以 H3 真实生成信息量、Base 采样、时序修复和可复现证据共同提升成片。

## 1. 质量问题与目标

V0.5 的 `delivery720` 实际链路为 `608×352 H3 → Lanczos → 1280×720`。它能得到可播放、带音频、可 seek 的 720P 文件，但不会凭空恢复人物五官、材质、文字或运动边缘；当前“模糊”的主要原因是源片只有约 0.21MP，而不是 MP4 外壳尺寸不足。

V0.6 的目标分成四层：

1. 提高 H3 首次采样的真实像素与采样质量，不再把插值作为默认母版。
2. 保留 Turbo 低成本迭代，同时增加不挂 Turbo LoRA 的官方 Base 20 步路径。
3. H3 与时序修复分阶段运行；卸载 H3 后用 SeedVR2 3B INT8 处理完整短片，保留原音频、帧率和原生母片。
4. 前端展示真实分辨率、交付分辨率、预计耗时、能力缺口和降档原因；依赖不足时阻塞，不静默回到 Lanczos。

| 官方 | [LightX2V H3 设置](https://github.com/ModelTC/Minimax-H3-Turbo/blob/main/COMFYUI_SETUP_AND_INFERENCE.md) | 4/8 步 Turbo LoRA、合法帧数与三段式提示词结构 |

官方资料决定默认参数与产品表述；社区数据只用于本机测试阶梯与时间估计，不能替代本机复测。

## 3. 已裁定的质量矩阵

| 产品档位 | H3 源片 | 采样 | 后处理 | 允许时长 | 定位 |
| --- | --- | --- | --- | --- | --- |
| 快速动作预览 | 608×352 | Turbo 4 步 | 无 | 5/10/15 秒 | 构图、动作和提示词迭代 |
| 高清 Turbo | 1024×576 | Turbo 8 步 | 无 | 5/10 秒 | 质量迭代与短片直出 |
| 兼容 720P（插值） | 608×352 | Turbo 8 步 | Lanczos | 5/10/15 秒 | 旧项目兼容；UI 明示不新增真实细节 |
| 原生 768P Turbo | 1344×768 | Turbo 8 步 | 无 | 仅 5 秒 | 空间细节优先，禁止 8GB 长片 |
| Base 20 步精修 | 1024×576 | `res_multistep` + `simple`，20 步 | 无 | 5/10 秒 | 声画、运动与物理一致性优先 |
| 720P 时序精修母版 | 1024×576 | Base 20 步 | SeedVR2 3B INT8 → 1280×720 | 5/10 秒 | 默认高质量交付候选 |

竖屏与方形使用同档位等价画布。H3 原生片始终先原子保存；后处理失败不能覆盖或删除它。

## 4. 运行架构

```text
自然语言 / 首末帧
  → H3 Shot Planner v2：场景、镜头节拍、声音与连续性
  → 运行时能力门控：Comfy/Torch/节点/模型/显存/RAM
  → H3 Turbo 或 Base 固定白名单图
  → 原生 MP4（高质量档 CRF 12；Base/母版 CRF 8）
  → [母版档] 关闭执行跟踪器并调用 /free 卸载 H3
  → 上传受管源片
  → SeedVR2 3B INT8：21/384 → 13/256 → 9/192 → 5/128（时序帧/VAE tile）OOM 自适应档
  → 分块解码、交叠合并、wavelet 颜色对齐
  → 回填原音频、fps、bit depth
  → 原子保存 720P 母版 + 保留 H3 原生片
```

默认稳定精度仍是现有 D 盘 `FP8 scaled + Torch cu129`。`INT8 ConvRot + cu130` 只有在独立候选运行时通过版本、模型哈希、节点 API、固定镜头画质和稳定性检查后才自动路由；缺少任一条件时继续使用 FP8，不影响可用档位。

## 5. RTX 4060 验收阶梯

所有测试固定同一提示词、Seed、5 秒 124 帧与 16:9，记录 Comfy/Torch/CUDA、驱动、模型哈希、峰值显存、系统内存、总耗时、输出 SHA-256、ffprobe、首中末帧和失败节点。

1. 工作流契约：实时 `/object_info` 覆盖五个 H3 档位和 SeedVR2 图，不执行 GPU。
2. SeedVR2 独立烟测：用既有 608×352、5 秒母片生成 1280×720，验证完整 124 帧、音频、fps、可 seek 与分块峰值。
3. H3 目标尺寸 1 步预检：1024×576、124 帧，证明 TE、DiT、双 VAE、音频和封装都能走完。
4. Turbo 对照：1024×576/8 步与 1344×768/8 步，确认空间细节和耗时边界。
5. Base 母片：1024×576/20 步；与同 Seed Turbo 对比人物结构、纹理、运动拖影、物理和声画。
6. 完整母版：Base 20 步后接 SeedVR2；分别审查 H3 源片与 720P 修复片，避免把过度锐化或幻觉纹理误判为提升。
7. 候选运行时：FP8/cu129 与 INT8/cu130 使用完全相同工作流，比较质量、时延、RAM/VRAM、冷启动和二次运行。

验收不以“文件宽高等于 1280×720”作为单一通过条件。必须同时满足：真实生成或时序修复链路可追溯、124 帧完整、24fps、音频存在、可 seek、无 OOM、无静默降级、源片可恢复。

## 7. 商业与风险边界

- 默认主线优先采用官方 ComfyUI/Comfy-Org 与 Apache-2.0 SeedVR2；模型许可、MiniMax H3 社区许可、Custom Node 许可仍需写入最终 SBOM 和发行提示。
- H3 latent upscaler 只登记实验候选。部分节点为 GPL-3.0，权重与节点迭代快，尚不能直接纳入闭源商用默认包。
- 提示词 Agent 是本地确定性编排器，不宣称复刻官方未开源 Context-IR；用户文本与参考图只进入本地桥接/本机 ComfyUI，除非未来显式启用外部 API。
- 8GB 设备的质量提升主要用时间、RAM 和磁盘换取。不得以放宽显存比较、忽略 OOM、降低源分辨率或静默插值制造“已支持”的假象。

## 8. 回滚策略

V0.6 代码注册表不会替换 V0.5 的稳定文件。SeedVR2 不可用时可显式选择 `cinemaBase` 保留高质量源片；候选 cu130 运行时失败时自动回到 `fp8Scaled4060`，现有 D 盘 cu129 运行时和模型保持不变。任何后处理失败只清理未提交临时文件，已经登记的 H3 原生中间结果继续保留。
