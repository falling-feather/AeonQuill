# V0.6 开箱即用封包与签名方案

> **关联任务**：`REL-012`  
> **产品版本**：`0.6.0`  
> **实现版本**：`V0.6.3`—`V0.6.8`
> **状态**：封包链路已实现，最终包体与实机证据待干净提交后生成

## 1. 目标与非目标

本任务把已经在 RTX 4060 Laptop 8GB 上验证的 cu130/INT8 H3 候选，从“依赖当前机器绝对路径的 `.venv`”升级为可搬迁的 Windows x64 运行时闭包，并与 0.6.0 Tauri 应用组合为 `下载/光阴砚AEONQUILL-0.6.0-Windows-x64-开箱即用版/`。

开箱即用表示系统不需另装 Node.js、Python、ComfyUI 或模型；它不表示包内含 NVIDIA 显卡驱动，也不表示模型许可、Windows 信誉和公开商业再分发已经获批。

## 2. 包体结构

```text
下载/光阴砚AEONQUILL-0.6.0-Windows-x64-开箱即用版/
├─ AEONQUILL_0.6.0_x64-setup.exe
├─ Install-AEONQUILL-Full.cmd

├─ SHA256SUMS.txt
├─ SHA256SUMS-offline.txt
├─ 安装、限制与第三方说明
└─ runtime/aeonquill-comfyui-h3-cu130-win-x64-v3/
   ├─ ComfyUI/

   ├─ tools/
   ├─ models/rembg/
   ├─ licenses/

```

大型模型不进入 NSIS；安装入口默认原位使用包内运行时，因此不会重复复制数十 GiB 到 C 盘。包所在磁盘同时作为默认 `AEONQUILL/App`、`AEONQUILL/UserData` 和 `AEONQUILL/output` 所在磁盘。

## 3. Python 与 ComfyUI 闭包

候选 `.venv` 的 `pyvenv.cfg` 原先把 `home` 与 `executable` 指向当前机器的 cu129 Python，直接复制会在其他电脑失效。V0.6.3 的封包器不复制该 venv 启动器，而采用以下确定性组合：

1. 以既有便携 Python 3.12.10 为可搬迁基座，保留已经验证的 rembg、ONNX Runtime GPU、OpenCV、Numba、SAM 与 Impact Pack 依赖。
2. 按文件项清除并覆盖 cu130 候选 `site-packages`，获得 PyTorch `2.12.1+cu130`、torchvision `0.27.1+cu130`、torchaudio `2.11.0+cpu` 和 ComfyUI 0.31 所需包。
3. 不采用候选的 NumPy 2.5.2；该版本超过打包 rembg 所用 Numba 0.61.2 的上限。改为固定 PyPI wheel `numpy 2.2.6`，SHA-256 `c1f9540…84a40b2`，同时满足 SciPy 1.18.1 与 Numba。
4. 在 system-only PATH、`PYTHONNOUSERSITE=1` 下同时导入 Torch/CUDA、NumPy/SciPy、OpenCV、rembg、ONNX Runtime CUDA、SAM 与 aiohttp，证明不借用系统 Python 或用户 site-packages。
5. ComfyUI 只复制锁定提交、MiniMax 节点与 Impact Pack；删除 `.git`、`extra_model_paths.yaml`、input/output/temp/user、未知节点和未知权重。模型被复制到包内标准 `ComfyUI/models`，不再引用开发机共享路径。

## 4. 模型与工作流

`runtime-lock.json` 固定以下能力并记录大小、来源、许可证与 SHA-256：

- MiniMax H3 INT8 ConvRot：RTX 4060/cu130 首选 Base/Turbo 模型。
- MiniMax H3 FP8 scaled：运行时兼容回退。
- Qwen3-VL NVFP4/AWQ 文本编码器、视频 VAE、音频 VAE 与 Turbo LoRA。
- SeedVR2 3B INT8 与 SeedVR2 VAE：Base 母片的 720P 时序修复。
- SAM ViT-B、rembg/u2netp、FFmpeg 与 Real-ESRGAN：元素选择、去背景、媒体处理和超分。

应用携带 `DEV-017` 的六档 H3 注册表，支持 T2V、首帧/主体参考 I2V、INT8/FP8 Base/Turbo 与 SeedVR2 母版。模型或节点不满足时必须给出能力诊断，不能把高质量档静默变成 Lanczos 插值。

## 5. 签名与信任边界

构建期间临时创建不可导出的 CurrentUser Code Signing 证书，主体为 `CN=falling feather制作`。Sidecar 先签名，Tauri 再以同一 thumbprint 签署主程序和 NSIS。构建结束立即按精确 thumbprint 删除临时证书；PFX、证书私钥和签名缓存不进入 Git 或下载包。

自包含 sidecar 使用 `@yao-pkg/pkg` 经典模式。Node 22 SEA 模式虽然可以启动，但上游 Windows 路径在注入 blob 前没有移除原始 Node 签名安全目录，生成物会被 SignTool 以 `0x800700C1` 拒绝；本项目不在发行时修补第三方 PE 头，而采用已通过 system-only PATH 启动和 Authenticode 签名的经典输出。npm 封包入口固定调用系统 Windows PowerShell 5.1，避免嵌套 PowerShell Provider 状态差异。

三个由 Windows PowerShell 5.1 直接执行的入口使用 UTF-8 BOM；这是中文提示和签名主体在旧 PowerShell 中不被错误按 ANSI 解码的发行契约。外层 turnkey 脚本必须传播任何子构建的非零退出码，签名阶段失败时禁止继续复制大型运行时。

这是 Authenticode **自签名**：可核对文件完整性与制作者标识，但没有受信任根、OV/EV 证书信誉或 RFC 3161 时间戳。清单使用 `self-signed-test-package` / `self-signed-local-test`，不得写成“受 Windows 信任”或“正式商业签名”。

## 6. 用户数据与隐私边界

交付物显式排除：

- `UserData`、SQLite 项目库、WAL/SHM、项目与 client state；
- 用户图片、视频、ComfyUI 输入/输出、生成结果与默认 output；
- API Key、Token、日志、缓存、浏览器 profile 与启动器状态；
- 未登记 Custom Nodes、模型、下载缓存、开发源码和绝对本机路径；
- 证书私钥、PFX 与 NVIDIA 系统驱动。

边界验证器要求包根只能出现固定交付文件，递归拒绝 `.git`、`pyvenv.cfg`、`extra_model_paths.yaml` 和用户数据标记，并扫描配置/文本是否泄漏 `D:/AEONQUILL-Package`、工作区或开发者用户目录。

## 7. 构建、验证与清理顺序

```text
干净 Git HEAD
→ 构建 sidecar/前端
→ 临时证书签名 sidecar、主程序、NSIS
→ staging manifest 与组件签名检查
→ 组装独立 Python/ComfyUI/模型运行时
→ 关键哈希与全树哈希
→ 绑定完整包根清单
→ system-only PATH 冷启动 ComfyUI
→ packaged sidecar 与图片工具验证
→ 隐私/绝对路径/私钥扫描
→ 全树复核
→ 成功后精确删除旧 offline、staging、Electron 与 NSIS 发布目录
```

旧发布路径只能在新包全部通过之后清理。`D:/AEONQUILL/App`、`D:/AEONQUILL/UserData`、`D:/AEONQUILL/output`、稳定运行时源和当前共享模型源不属于清理目标。
