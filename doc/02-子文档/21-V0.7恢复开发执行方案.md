# V0.7 恢复开发执行方案

> 该文档隶属于[项目规划](../02-项目规划.md#05-2026-09-22-恢复开发)，用于定义本轮已授权范围、执行边界和验收步骤。任务状态与版本只维护在父文档。

**最后一次更新时间**：2026-09-26

**更新者**：主开发、项目统筹与产品规划组

## 1. 目标与约束

以现有三模式内部 Alpha 为基线，完成真实质量、声音、跨媒体督导、像素和性能任务，并把工作流调用、候选比较和成功配方复用连成可操作流程。用户于 2026-09-22 明确要求按之前安排恢复开发并尽快完成；已有目的与约束直接沿用，不重新建立平行产品路线。

- 主线 fda0d2b；产品 SemVer 0.7.1。已有功能轨 V0.7.62，最终发行身份由 REL-020 更新。
- React 18 / TypeScript / Node ESM / SQLite / Tauri / ComfyUI 保持同一业务内核。
- D 盘保存模型、样本、隔离运行时和输出；GPU 仅一个执行者。收费 API 只在用户已配置且明确授权对应消费时使用。
- 三模式正文使用现有严格命令、revision 和恢复点；新增字段必须显式迁移。模型结果以受管不可变资产入库。
- 用户原有未提交的 01 文档排版保留原位。项目对接 Skill 停用，旧工作树全部移除并保留其 Git 提交；当前开发者独立统筹，临时子任务固定 GPT-5.6-Luna / max。
- 实测必须区分机器结构质量、模型观感评估和真实人工盲审。缺模型或人工结论不得用合成夹具标记任务全部完成。

## 2. 并行边界与依赖

第一波：当前开发者实现 UX-001 并负责共享接口，设计完成后分别交给 Luna / max 实现 PIXEL-013 与 AUDIO-001。子任务在当前工作区使用不重叠文件范围与隔离测试目录，不操作 Git；模型任务统一串行占 GPU。

第二波：PIXEL-013 后实施 PERF-004；声音和镜头接口稳定后实施 AI-006；模型与配方身份稳定后实施 AI-007。共享 server/index.mjs 与 types.ts 由总控串行集成，实施者优先提供局部模块和明确接入点。

第三波：当前开发者负责 QA-007，对最终源码进行单元、默认、P7、浏览器和性能验收；需要独立复核时只派发范围明确的 Luna / max 只读子任务。REL-020 从干净提交构建并更新本机 App，验收失败回到原任务修正。

## 3. 工作流与配方交互

改动位置：src/components/WorkflowCenter、src/components/ImageLab.tsx、src/lib/workflowCenterApi.ts、server/workflow-center.mjs，以及新增专责配方模块和对应测试。

设计：工作流页面提供“任务/已保存配方/能力管理”用途明确的视图。内置能力沿用当前检测与执行路径；自定义工作流继续使用已批准输入输出映射。配方保存工作流 ID/哈希、支持的受控参数和显示名称，不携带凭据、任意路径、私有 prompt 副本或未经批准的模型字段。恢复配方时重新核对当前工作流身份和参数范围；输入素材由当前项目显式提供。图像比较使用受管候选 URL，保留原图和当前预览，接受结果才进入正式文档。

实施顺序：先写合法往返、工作流变更、参数越界和跨项目输入的失败测试，再实现单一配方校验器与持久服务，接 API 和 UI；用真实浏览器完成保存、刷新、恢复、运行、比较和接受。

## 4. 像素地图与性能

改动位置：src/lib/pixel/pixelCore.mjs/.d.mts、pixelGamePipeline.mjs/.d.mts、src/modes/pixel、tests/pixel-*.test.mjs、17—19 技术子文档。

PIXEL-013：在地图中新增有稳定 ID 的对象层与对象，保存有界位置、尺寸、标量属性及明确的帧/碰撞引用；Terrain 格仍采用 v7 的 Terrain ID。命令集中在 pixelCore，保证一次编辑一个可逆 revision；未知引用、重复 ID、非法数值及锁定写入拒绝。导出 TMJ 的 objectgroup 与内部 JSON 共用同一权威对象数据。缺邻接规则只报告 mask、位置与建议，不生成或覆盖用户帧。

PERF-004：在 PIXEL-013 集成后，把合成/地图预览/导出计算放入专用 Worker 请求协议。请求包含 ID、文档 revision 和操作；取消、切换项目或 revision 变化后旧响应不得入 UI。小文档保留同源同步函数；Worker 与同步参考输出必须一致，失败只回退同一确定性算法并显示可操作状态。

实施顺序：旧版迁移与合法/非法对象夹具 → 命令 undo/redo → 导出契约 → 地图对象 UI → 浏览器保存重开；随后加入 Worker/同步一致、取消/过期响应和大文档性能测试。

## 5. 声音与跨媒体督导

改动位置：src/lib/story/soundTimeline.mjs/.d.mts、server/sound-renderer.mjs、src/modes/video/SoundTimelinePanel.tsx、音频测试；督导改动在 src/lib/story/videoSupervisor.mjs、server/video-supervisor.mjs、ProductionStudio.tsx 及专责媒体执行模块。

AUDIO-001：保留已批准音频版本，新增与实际音频哈希绑定的对齐结果、句/词时间校验与用户修正；对齐执行通过探测后的本地工具适配器，缺依赖返回明确不可执行状态。交叉淡化、对白优先/音乐压低及局部重混使用 FFmpeg 受控滤镜；不接受用户任意滤镜代码或磁盘路径。改变文本/音频时旧对齐与试听结论失效。

AI-006：督导返回下一项可执行媒体提议，用户批准后调用已有 Job 接口；保存对应 Job ID 并等待真实终态，完成后停在候选/试听/成片复核。暂停、拒绝、失败重试和刷新恢复从权威正文与 Job 重建；未知输出不可自动接受，模型不直接发起本机命令。

实施顺序：音频身份/时间边界/局部无关片段保护测试 → 对齐与混音模块 → 编辑 UI 和真实 FFmpeg；媒体提议校验/幂等/暂停测试 → Job 接入 → 多节点浏览器恢复验收。

## 6. 模型质量与控制方案

AI-001/VIDEO-012 先记录真实模型、节点和样本清单，再选择固定输入运行。每条结果记录输入/输出 SHA、工作流与模型身份、全部受控参数、耗时、显存和错误阶段；Qwen、SAM/rembg 与已安装可运行候选按同一素材对比。人物样片覆盖近景、全身动作、双人交互，人工结论绑定具体视频候选。

AI-007 的 LoRA/参考控制只接入当前后端明确支持的模型家族和映射：底模、adapter 身份、强度和引用在服务端再次验证；H3 Turbo 加速 LoRA 与用户风格/角色 LoRA 分开建模。未完成硬件与实际输出验证的候选只进入实验列表。

实施顺序：依赖盘点 → 样本和评测清单 → 实测运行 → 固定参数对比 → 结果与回退建议；随后增加兼容模型/adapter 组合测试和真实运行验证。

### 6.1 固定 Qwen 加速候选

2026-09-26 的真实 40 步区域编辑在本机耗时约 19.5 分钟，选区外误差为 0。依据 Comfy-Org 固定提交 `98fd32ca756dd9d72077fbe3457146d11cbc88cb` 的 INT8 2511 模板，在 AI-007 的固定 LoRA 范围内增加 `lightning4` 实验档；标准 `base40` 保持原行为。已存在的 `params` 参数包增加可选 `preset` 枚举，旧请求不带该字段时继续使用原 40 步流程。

固定候选使用 LightX2V revision `d74eba145674fd7e31b949324e148e21e7118abd` 的 BF16 4-step LoRA，849,608,296 B，SHA-256 `22226e8d05d354bb356627d428809f5afd7819399b077238a2b70a82883a904f`。配置为 shift 3.1、Euler/simple、denoise 1、LoRA strength 1、4 steps/CFG 1；节点位于 CFGNorm 后。8-step 缺少同等明确的 Comfy 固定参数，暂不接入。

参数定义由前后端共享；权重/来源/SHA 单独提取到唯一 artifact 定义，服务端执行前复用既有完整文件验证。实验档缺依赖时拒绝执行，不能静默退回标准档；请求、Job 和派生资产记录实际 preset 与 LoRA 身份。图片实验室提供标准/快速实验选择，实际同输入对照与人工判断完成前不更改默认档或给出推荐质量结论。

## 7. 验收关注点

每个实施任务都必须覆盖与其相关的五类情况：旧项目迁移、输入/权重缺失、revision 过期、执行取消/重启、导出与预览一致。真实 UI 必须覆盖桌面和窄屏以及刷新恢复。先定向测试，集成后再运行默认/P7 和性能门，避免重复消耗 GPU。

文档元数据/链接和本轮新增历史字段必须通过检查。既有 60 条历史记录的旧字段格式缺口为恢复时发现的遗留问题，不将其伪装成新增实现故障，也不为本轮重写全部历史。
