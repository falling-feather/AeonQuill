# 光阴砚 AEONQUILL — V0.4 完整离线运行时封包方案

> **文档梗概**：定义 `REL-004` 对 V0.3 安装版工作流模板漏包的修复、V0.4 Windows x64 主安装器与 ComfyUI/Python/H3 拆分离线运行时的结构、完整性、安装、验证和许可退出边界。
>
> 该文档隶属于[光阴砚 AEONQUILL — 项目规划](../02-项目规划.md)。
>
> **具体规划法则**：
>
> 1. 发行验收只认可 packaged sidecar 与 staged runtime 的真实结果，不以源码目录或开发机外部 ComfyUI 通过替代。
> 2. 大型运行时不得直接塞进 NSIS；主安装器、运行时和一键脚本必须由根发布清单绑定。
> 3. 运行时只复制登记的代码、节点、模型与工具；个人素材、输出、缓存、密钥、未知节点和未知权重必须排除。
> 4. MiniMax H3 条款未明确接受、地域不适用或关键哈希失败时不得继续安装。
>
> **最后一次更新时间**：2026-08-20
>
> **更新者**：开发组、发布工程组、安全组、测试与质量保障组

## 1. 起因与阶段结论

V0.3 阶段安装包虽然通过壳层、图片任务、恢复、安全和卸载验收，但用户首次从 APP 提交 I2V 后得到：

```text
ENOENT: no such file or directory, open '[local-path]\server\workflows\minimax-h3-i2v.json'
```

根因是 `workflow-builder.mjs` 在运行时读取固定 JSON，而 `desktop/sidecar.pkg.json` 没有把 `server/workflows/*.json` 加入自包含 sidecar。开发目录存在文件，所以此前源码态测试没有暴露。V0.4 同时执行两层修复：

1. 两份工作流 JSON 进入 pkg assets，桥接监听前调用 `validateBundledWorkflowTemplates()`；任一模板缺失或结构错误会使应用明确启动失败。
2. ComfyUI、Python、节点、模型和本地图像工具按固定清单形成可重定位运行时，不再要求用户手工指出旧开发环境；V0.4.1 默认跟随完整包所在磁盘部署，V0.4.2 修复旧数据移动完成后的安装幂等边界，V0.4.3 把 WebView2 profile 一并放入便携 `UserData`。

packaged sidecar 已独立编译 T2V 15 节点与 I2V 16 节点，真实 I2V 不再复现 `ENOENT`。

## 2. 交付结构

完整交付根目录为：

```text
AEONQUILL_0.4.3_windows_x64_full/
├─ AEONQUILL_0.4.3_x64-setup.exe
├─ Install-AEONQUILL-Full.cmd
├─ Install-AEONQUILL-Full.ps1
├─ OFFLINE-FULL-INSTALL.zh-CN.md
├─ release-manifest.json
├─ offline-release-manifest.json
├─ SHA256SUMS.txt
├─ SHA256SUMS-offline.txt
└─ runtime/
   └─ aeonquill-comfyui-h3-cu129-win-x64-v1/
      ├─ ComfyUI/
      ├─ python/
      ├─ models/rembg/
      ├─ tools/ffmpeg/
      ├─ tools/realesrgan-ncnn-vulkan/
      ├─ licenses/
      ├─ runtime-manifest.json
      └─ runtime-SHA256SUMS.txt
```

采用拆分目录而非单一 EXE，是因为运行时超过 50 GiB，远超 NSIS/WiX 适合承载的单包体积。主 NSIS 保持可快速重建和升级；运行时以后可独立做内容寻址、断点下载或差分更新。

当前 staged 树包含 63,232 个文件、53,988,054,927 bytes，树 SHA-256 为 `4c4945aa239bd25e443e5864ad68640aa7d23df1265709df0b764e3524ec488b`。`runtime-manifest.json` 记录关键入口和模型字节数/SHA-256；`runtime-SHA256SUMS.txt` 覆盖全部文件。

## 4. 安装和运行数据边界

双击 `Install-AEONQUILL-Full.cmd` 后，一键脚本依次：

1. 读取 `offline-release-manifest.json`，验证产品 0.4.3、Windows x64、包 ID 和 `unsigned-local-stage-only` 状态。
2. 对清单绑定的主安装器、脚本、说明、应用 manifest 与运行时清单逐项验证字节数和 SHA-256，并验证聚合摘要。
3. 展示 MiniMax H3 许可与地域提示；只有输入 `ACCEPT` 或显式传入 `-AcceptMiniMaxH3License` 才继续。
4. 验证 ComfyUI、Python、FFmpeg/FFprobe、Real-ESRGAN、7 个模型及其关键文件哈希。
5. 双击入口默认在完整包所在磁盘建立 `AEONQUILL/App` 与 `AEONQUILL/UserData`，并通过 `-UsePayloadInPlace` 原位使用包内运行时；PowerShell 高级入口仍可选择复制到 `UserData/runtime/packages/<packageId>`。
6. 可用 `-MigrateLegacyData` 把旧 app-local-data 合并到新 `UserData`；只有显式加入 `-RemoveLegacyAfterMigration` 才移动旧文件并清理空根。若 `robocopy /MOVE` 已删除空源目录，V0.4.2 将其视为成功而不再二次删除；V0.4.3 的 WebView2 profile 直接写入同级 `UserData/EBWebView`。
7. 以临时文件 + 原子替换写入受控 `config/local.json`，按需卸载其他位置的同名旧应用，再将 NSIS 安装到 `App` 并写入严格 `aeonquill-layout.json`。

运行时包本身按只读载荷处理。Runtime Manager 启动包内 Python 时把可变目录重定向为：

```text
data/comfyui/input
data/comfyui/output
data/comfyui/user
cache/comfyui/temp
```

项目、Job、正式资产和客户端恢复仍位于 data；日志位于 logs。`App` 与 `UserData` 为同级目录，正常卸载只删除应用二进制、快捷方式与登记，不删除用户项目。原位运行时属于完整离线包，移动该包会使模型能力失效；`-RepairRuntime` 只允许删除经父目录与精确 package ID 双重验证的复制型同版本目标。

## 6. 许可与发布限制

- MiniMax H3 Community License 当前将欧盟、英国、韩国和美国列为排除地区，并要求下游接受、显著归属、NOTICE、可接受使用和合理安全措施；超过协议所列年度收入门槛时还需额外授权。
- ComfyUI 与 Impact Pack 的 GPL-3.0 文本及源码、Python/FFmpeg/Real-ESRGAN/rembg/SAM/Turbo 等顶层许可文本随运行时提供。
- 便携 Python 的全部传递包、PyTorch/CUDA/ONNX 组件仍需完整 SBOM 与法务复核；当前清单不是公开商业再分发批准。
- NVIDIA 驱动属于系统依赖；本包不静默安装驱动，也不把无兼容 GPU 的机器伪报为可用。
- 主安装器没有 Authenticode 签名、时间戳、自动更新或回滚，Windows 可能显示 SmartScreen 警告。

因此 V0.4 的退出口径是“Windows x64 完整离线本机阶段包可安装并可真实执行”，不是“全球公开商业发行就绪”。

## 7. 后续优化

1. 以小型下载器替代 50 GiB 目录复制，实现断点续传、并发限速、内容寻址复用和单组件修复。
2. 生成 CycloneDX/SPDX SBOM，补齐 Python wheel、CUDA DLL、字体和所有模型的传递许可/NOTICE。
3. 将 H3 许可接受、地域与版本写入持久审计记录，并接入内容安全策略。
4. 建立 Windows 10/11、NVIDIA 驱动代际、低磁盘、断电中断、升级/降级和跨版本模型复用矩阵。
5. 完成 Windows 代码签名、时间戳、原子更新和失败回滚后，才进入公开发行候选。
