## 1. 里程碑定义

`V0.3` 的目标是把已经通过 `V0.2.8` 独立验收的单机原型，推进为可交给个人用户试装的 Windows x64 阶段软件包。它必须真实完成安装、启动、依赖诊断、图像与视频能力接线、日志定位和安全卸载，而不只是从开发目录启动一个桌面窗口。

本周期完成时，一名未参与开发的验收者应当能够：

1. 在不安装系统 Node.js 的环境中安装并启动光阴砚 AEONQUILL。
2. 在首启或设置入口看到 WebView2、本机桥接、图像处理器、ComfyUI、模型与显存的真实状态和可执行恢复动作。
3. 使用包内前端与桥接完成至少一条确定性图像处理链，并获得不可变派生资产和可定位任务记录。
4. 在本机 ComfyUI/H3 依赖可用时提交受控视频任务；依赖缺失时保持阻塞并准确说明，不伪造“可用”。
5. 退出应用后确认桥接和由应用启动的 ComfyUI 按策略关闭，用户项目与资产不因退出或卸载被误删。
6. 通过发布清单核对安装包、应用版本、架构、文件大小、SHA-256、签名状态、依赖来源、许可证状态和验收报告。

本阶段称为“未签名阶段测试包”，不是正式商业发行版。没有代码签名证书时，Windows 信誉提示属于已知发行限制，文档和页面不得隐去。

## 2. 必须闭环的发行链路

### 2.1 构建与产物链

```text
锁定源码提交
→ 生产前端
→ 自包含 Node 22 桥接 sidecar
→ Tauri Windows x64 主程序
→ NSIS 当前用户安装包
→ 机器可读 release manifest
→ SHA-256 与验证报告
```

Tauri 是本周期唯一主发行壳；Electron 只保留为共享桥接契约的回退验证，不并行发布两个同等地位的安装包。构建脚本必须从仓库事实生成文件名和版本，不得继续硬编码旧 `MiaoHui_0.1.0` 路径。

### 2.2 安装与首启链

```text
安装包
→ 当前用户安装
→ AEONQUILL 快捷方式与卸载登记
→ 随机回环端口启动桥接
→ 等待健康检查
→ 显示产品主页
→ 首启诊断与依赖建议
```

渲染器继续保持无 Node、无 Shell、无直接文件系统权限。主程序只加载本次桥接的精确回环 Origin；未知导航和新窗口继续拒绝。

### 2.3 图像与视频能力链

```text
用户素材
→ 浏览器或本机确定性图像处理
→ Job / SSE / 取消 / 重试
→ 不可变派生资产
→ 画布回填

剧本或首帧
→ 固定 T2V/I2V 执行清单
→ 依赖与显存检查
→ 按需启动 ComfyUI
→ H3 队列与真实进度
→ MP4 资产
→ 队列空闲后安全关闭
```

安装包不内置任意 ComfyUI 工作流 JSON 执行入口。只有仓库登记的固定工作流和参数白名单可以进入执行面。

### 2.4 退出、卸载与恢复链

```text
关闭主窗口
→ 主窗口 CloseRequested 显式退出应用事件循环
→ 请求桥接优雅退出
→ 等待自有任务/进程收束
→ 必要时仅终止自有进程树
→ 端口关闭

运行卸载器
→ 删除应用二进制与快捷方式
→ 保留用户项目/资产/模型
→ 清理卸载登记
```

关闭测试必须作用于真实 Tauri 主窗口，而不是直接调用合成 `app.exit()`；窗口消失后 desktop、sidecar 或随机回环端口任一仍存活都属于发布阻断。卸载默认不得删除用户项目、资产、模型或外部 ComfyUI。需要清理用户数据时必须由独立、显式且可预览的操作完成，本周期不提供静默全删。

## 3. 包体与数据边界

### 3.1 应用本体

阶段安装包包含：

- Tauri 主程序、WebView2 bootstrapper 策略和产品图标。
- 生产前端静态资源。
- 自包含 Node.js 22 本机桥接及固定服务器代码。
- 应用自身所需的固定工作流、安装说明、限制与第三方声明资源。
- 设置页中的本机依赖诊断入口。

受控 release staging 与安装包并列保存 `release-manifest.json`、严格 JSON Schema、`SHA256SUMS.txt`、安装说明、限制与第三方声明；manifest 和校验和不重复塞入安装器内部，以免形成自引用哈希。验收者应从 staging 核对安装包。

阶段安装包默认不包含：

- ComfyUI 源码、Python 环境、Custom Nodes 和大模型权重。
- 用户本机 API 密钥、项目、输入输出或缓存。
- 未完成许可证核对的 FFmpeg、模型、字体或第三方素材。

### 3.2 用户数据

正式安装运行时必须把数据放入当前用户应用数据目录，不依赖安装目录可写，也不得回写开发仓库。至少隔离：

| 数据 | 目标边界 | 卸载默认行为 |
| --- | --- | --- |
| 配置 | 当前用户配置目录 | 保留 |
| 项目数据库 | 当前用户数据目录 | 保留 |
| 资产与导出 | 当前用户数据目录或用户选择位置 | 保留 |
| 运行时日志与报告 | 当前用户日志目录 | 保留，提供定位入口 |
| 临时任务文件 | 当前用户缓存目录 | 可安全回收 |
| 外部 ComfyUI/模型 | 用户配置的外部目录 | 永不由卸载器删除 |

配置迁移必须保留 schema 版本。旧 `MIAOHUI_*` 环境变量只作为兼容输入；新增源码和用户可见字段使用 `AEONQUILL_*`，兼容层的删除另建任务。

### 3.3 外部依赖

外部依赖采用“探测—解释—配置—复检”，不采用静默下载：

- WebView2：由 Tauri/NSIS 的受控安装策略处理。
- FFmpeg、rembg、Real-ESRGAN：探测可执行文件、模型和许可登记；缺失时保留浏览器能力或禁用正式处理器。
- ComfyUI：只允许回环地址；可从已配置路径或受控候选目录发现，用户确认后写入本机配置。
- H3 模型与节点：继续由固定工作流能力探测校验，不以目录存在替代节点契约。
- 云端 API：本周期不预置密钥，也不建立在线账号控制面。

## 4. 完成定义与验收矩阵

| 验收域 | 必须结果 | 自动证据 | 独立人工证据 |
| --- | --- | --- | --- |
| 品牌与身份 | 安装器、窗口、程序、快捷方式和卸载项统一为 AEONQUILL | 配置/二进制/注册表断言 | 开始菜单和应用列表目视 |
| 自包含启动 | 无系统 Node.js 时桥接启动，主页加载 | 隔离 PATH 生命周期测试 | 安装后首次启动 |
| 数据隔离 | 安装目录只读时仍运行；项目/资产写入用户目录 | 路径与脱敏断言 | 创建项目、重启恢复 |
| 首启诊断 | 图像工具、ComfyUI、模型、显存状态真实且可复检 | 能力 API 契约 | 断开/恢复依赖后复检 |
| 图像闭环 | 至少一种包内可用或明确声明外部执行器的确定性处理形成派生资产 | API/Job/SSE/资产测试 | 安装版提交、下载、回填 |
| 视频闭环 | 固定 H3 任务在依赖可用时完成；缺依赖时阻塞 | 工作流与运行时契约 | 本机真实任务或可审计既有产物复核 |
| 生命周期 | 退出后桥接端口关闭；自启 ComfyUI 按策略关闭 | 进程树与端口断言 | 任务后等待空闲关闭 |
| 安装卸载 | 当前用户静默安装/启动/卸载，二进制和登记清理 | 安装器自动验收 | 控制面板/开始菜单复核 |
| 发布物料 | manifest、SHA-256、版本、架构、签名/许可证状态完整 | manifest Schema 验证 | 产物与文档逐项核对 |
| 回归 | V0.2 三模式、移动布局、安全和任务恢复不倒退 | `npm run validate` | 关键链快速复核 |

最终完成判定同时要求：

1. `main` 上存在可追溯的候选提交与对应安装包。
2. 安装包在隔离目录真实完成安装、启动和卸载。
3. 公开 Job、日志、manifest 和报告不泄露开发机绝对路径、PID、句柄或会话凭据。
4. QA 组给出“通过”；“代码构建成功”不能替代独立安装验收。

## 5. 实施波次与责任边界

### 5.1 波次一：发行基线

- `PM-005` 锁定本方案、`V0.3.x` 轨道、任务和排除项。
- 发布工程组建立独立长期 worktree；主开发保留 `main` 集成权。
- 对齐 `package.json`、Tauri、安装器、sidecar 和报告中的产品版本/名称来源。

### 5.2 波次二：运行时与体验

- `DEV-012` 已于 `V0.3.1` 完成安装环境的数据目录、配置兼容、依赖发现/复检和页面诊断入口；日志按独立目录注入，受控“打开日志位置”桌面命令不在本任务范围。
- 不把机器绝对路径编译进前端；敏感配置只保存在本机桥接控制面。
- 完成证据：42 项完整门禁、111/111 单元契约、五种真实 FFmpeg 处理、隔离 API/SSE、旧 runtime 持久数据兼容回退、真实 D 盘 ComfyUI 脱敏发现、Edge 桌面/移动设置流程和两个随机 Origin 间客户端状态恢复均通过。

### 5.3 波次三：发布产物

- `REL-003` 已于 `V0.3.2` 完成 AEONQUILL Tauri x64 当前用户安装包、自包含 Node 22 sidecar、严格产物 manifest、SHA-256、许可证/限制声明和自动安装验收；产品包 SemVer 仍为 `0.3.0`。
- `QA-003` 首轮安装前审计发现该候选的新 H3 输出前缀仍为 `MiaoHui/` 并退回；`DEV-013` 已于 `V0.3.3` 把新 H3/Comfy 产物、公开诊断和桌面优先图片工具变量修正为 AEONQUILL，必要旧协议只作兼容读取。修复前候选哈希立即失效，必须从干净 V0.3.3 重建。
- `QA-003` 第二轮对 V0.3.3 重建候选发送真实主窗口 `WM_CLOSE` 后发现窗口消失，但 desktop、sidecar 与随机端口仍驻留超过 15 秒并再次退回；`DEV-014` 已于 `V0.3.4` 将 `CloseRequested` 接入应用退出，并把自动桌面验收改为真实 `window.close()`。第二轮候选哈希同样失效，必须从干净 V0.3.4 重建。
- Electron 只运行回退契约验证，不作为本阶段主交付物。
- 发布组自检已覆盖系统 Node 不在 PATH、隔离安装版启动、应用本地数据根下 runtime/data/cache/logs/config 五目录、旧 runtime 持久数据回退、正常/旧数据卸载保留、注册项/快捷方式清理和公开清单/安装报告无绝对路径或 PID；独立结论仍由 `QA-003` 给出。

### 5.4 波次四：独立验收

- `QA-003` 从干净候选基线验证安装、启动、数据、图像、视频依赖、生命周期和卸载。
- 范围内缺陷退回原任务；超出本阶段的签名、更新和模型分包保留在 `REL-002`。

## 6. 版本、产物与 Git 规则

- 当前周期使用 `V0.3.x`；`V0.3.0` 用于本方案和任务基线，`V0.3.1` 分配给 `DEV-012`，`V0.3.2` 分配给 `REL-003`，`V0.3.3` 分配给首轮 QA 退回后的 `DEV-013`，`V0.3.4` 分配给第二轮生命周期退回后的 `DEV-014`。这些是 Git 任务小版本；安装包的产品 SemVer 独立保持为 `0.3.0`。
- 后续小版本由主开发在任务达到 `[READY-FOR-VERSION]` 后唯一分配，不预占。
- 一个提交只对应一个任务编号；实现、文档和验证必须在同一任务提交闭环。
- 发布候选必须记录 Git 提交、安装包相对路径、字节数、SHA-256、签名状态和生成时间。
- `.runtime/` 与构建目录继续忽略；最终可交付物复制到受控 release staging 目录并由 manifest 引用，不提交大型二进制到 Git。
- 远端 Release、公开下载、代码签名和自动更新只有在用户提供渠道与凭据后执行。

## 7. 明确排除项与停止条件

本周期明确排除：

- Windows 代码签名证书采购、SmartScreen 信誉建立和商店上架。
- 自动更新、差分更新、在线回滚服务和灰度渠道。
- 将 ComfyUI、Python、全部 Custom Nodes 或大模型直接塞入主安装包。
- 云端账号、支付、订阅、积分、多租户、内容审核和在线密钥托管。
- macOS/Linux 包、ARM64 包和跨平台安装验收。
- 把 `REL-002` 的 Stage D 商业发行条件改写为已完成。

出现以下情况时暂停对应支线，但不阻塞仍可验证的封包工作：

- 需要用户提供代码签名证书、云端发布账号或付费 API 凭据。
- 第三方二进制或模型没有可接受的分发许可。
- 本机 H3 依赖发生变化，无法在固定工作流契约下运行；此时保留真实阻塞与既有审计证据。
- 安装或卸载将覆盖既有同名程序、用户项目或外部模型；验收脚本必须拒绝继续。
