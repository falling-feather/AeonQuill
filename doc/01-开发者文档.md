# 光阴砚 AEONQUILL — 开发者文档

> **文档梗概**：说明光阴砚 AEONQUILL 当前无限画布、本地图像/视频桥接、目录、状态、运行方式、验证路径和维护限制。
>
> **具体规划法则**：
>
> 1. `App.canvasDocument` 是画布状态的权威来源；正式图片和视频任务状态以本地 `JobStore` 为权威，由 `JobScheduler` 分配 CPU/GPU 资源，再经 SSE 合并到前端。
> 2. 屏幕坐标与世界坐标必须通过相机换算；框选预览的屏幕矩形必须显式映射到 CSS `left`/`top`/`width`/`height`，不得把几何 `x`/`y` 直接作为普通 HTML 定位样式；高频手势只更新内存预览，结束时经统一命令校验并形成一次文档修订与撤销快照。
> 3. 图片浏览器草稿与正式处理必须区分；正式去背景/超分由桥接调用本机 rembg/Real-ESRGAN，H3 视频由固定模板交给独立 ComfyUI。
> 4. 浏览器不得直接调用 ComfyUI，也不得提交任意工作流；视频参数必须经过服务端白名单和版本化模板。
> 5. `.runtime/projects/` 是正式单机项目存储（SQLite + 内容寻址资产）；`.runtime/inputs`、`.runtime/assets` 和 `jobs.json` 仍是执行期数据；`config/local.json` 是机器私有配置，不得提交。
> 6. 正式任务必须登记资源类别、优先级、幂等键和超时并经过统一调度器；RTX 4060 上 GPU 容量固定为 1，禁止绕过调度并发。
> 7. 本地桥接只允许回环绑定；除首个 HTML/健康握手外，`/api` 必须同时通过 Host、Origin/Fetch Metadata 与随机 HttpOnly 会话校验。
> 8. 正式画布写入必须通过 `CanvasCommand` 或已注册的画布工具；Agent 不得替换整份文档、修改锁定节点或写入媒体 URL/任务字段。
> 9. 画布显示受管图片时必须使用版本化缩略图/预览图；原始内容资产只供正式编辑、导出、哈希和版本追踪，不得为离屏节点直接解码。
> 10. 桌面壳只负责随机回环端口、桥接生命周期、窗口沙箱和发行；Electron/Tauri 不得分叉业务 API、项目格式或任务实现。
> 11. `.miaohui`、`MIAOHUI_*` 与旧本地存储键是兼容标识；在迁移工具、旧项目回归和回滚路径完成前不得做破坏性改名。
> 12. 自包含 sidecar 必须携带 `server/workflows/*.json` 并在监听前预检；不得以开发源码目录存在模板替代发行物资源闭包验证。
> 13. 离线运行时代码/模型目录视为只读；ComfyUI 的 input/output/user/temp 必须重定向到应用 data/cache，安装器只能在用户明确接受模型许可且发布/关键文件哈希通过后配置该运行时。
> 14. 用户自选输出目录只接收已完成的内部不可变资产副本；路径必须是现存、可写的本机绝对目录，公开诊断只显示脱敏标签，副本写入失败不得破坏 Job 与项目资产。未自选时必须自动使用桌面壳提供的软件 `output` 目录。
> 15. 视频 UI 必须区分 H3 真实生成分辨率与交付文件分辨率；Base、SeedVR2、INT8/cu130 等高质量能力必须经过运行时门控，依赖或实测未满足时不得静默改成低清插值。
> 16. 开箱即用运行时必须摆脱 venv 与共享模型的开发机绝对路径；签名清单必须区分自签名完整性与 Windows 公共信任，证书私钥/PFX、项目、UserData、个人媒体、输出、密钥、日志和缓存不得进入交付物。
> 17. 长视频多智能体编排必须经过严格、可序列化的生产项目状态机；依赖未批准时不得越级，人工修改上游后必须使下游产物失效，只有批准后的分镜才能桥接到 `StoryProject` 与 H3 执行清单。
> 18. V0.7 的 `WorkspaceStore` SQLite 是项目目录与模式正文的权威来源；目录只保存项目、模式文档、状态和稳定引用，正文仍分别通过 `CanvasDocument`、`PixelDocument`、`SmartVideoDocument` 严格校验。写入必须携带 base revision 并在冲突时失败关闭；浏览器和 `client-state` 只作恢复镜像。恢复点不可变，恢复旧正文必须写成新 revision，并先保留恢复前快照；旧单例迁移继续保留原键/原项目。
> 19. 资源库复用 `ProjectStore` 的 SHA-256 内容资产：全局加入项目只固定版本引用，不复制文件；项目编辑必须创建派生条目/版本并保留父链，全局原件不可原位覆盖。资源库二进制不得进入 Workspace 目录或模式正文 JSON。
> 20. 工作流中心只允许下载内置清单中固定来源、固定目标、固定字节数和 SHA-256 的文件；许可接受与磁盘确认必须显式记录，校验失败文件隔离而不启用。自定义 ComfyUI JSON 只接收 API prompt 格式，必须限制大小/节点数、拒绝网络/代码/未知或未批准节点及不安全路径，并在真实 ComfyUI 节点表复检、显式映射输入输出后才能启用；真执行必须再次校验不可变工作流/映射哈希、节点类型和模型枚举，只注入受控参数/项目可见资源，并仅从映射输出节点回填不可变资产。
> 21. 连续长片必须使用独立编排资源，不得用占住 GPU 槽位的父 Job 等待 GPU 子 Job；首镜 T2V 后的每镜必须从上一条受管 MP4 提取真实末帧再创建 I2V。成片只能引用已完成的受管视频 Job ID，禁止接受任意本机路径；重试应复用仍可读的 completed 子 Job 断点，最终剪辑不得覆盖源镜头。
> 22. 工作流中心的模型事实必须来自统一运行时注册表：主运行时目录和受支持的 ComfyUI `extra_model_paths.yaml` / `.yml` 共同参与发现，同一逻辑文件命中共享根后不得重复下载或覆盖。目录浏览阶段只读取文件事实，不计算大文件哈希；安装/启用阶段再按固定 SHA-256 校验。能力状态只允许“未安装、已安装未启用、已启用休眠、正在唤醒、可执行、异常”六态；绝对共享根只能经配置哈希门、原子备份和可回滚迁移改写，迁移前后必须保持全部模型解析结果，删除旧运行时前必须先通过共享根反向引用门。
> 23. 产品 SemVer、功能轨、Git 构建 SHA、运行时包 ID 和注册表版本必须来自同一构建身份，并在设置、诊断、任务回执、release manifest 与桌面 sidecar 环境中一致；发行脚本只能从 clean HEAD 固化 SHA，身份不一致必须失败关闭。
> 24. 自包含 sidecar 必须把 clean HEAD、产品版、功能轨、身份版本和注册表版本写入封包快照内的只读身份资源；不得只依赖 Tauri 父进程转发环境变量。封包运行时缺失、损坏或与环境不一致时必须拒绝启动，sidecar 生命周期门必须比较健康接口与内嵌资源。
> 25. `.aeonquill` 是三模式完整项目包：必须同时覆盖项目登记、三类正文、智能视频生产状态、恢复点、资源关系、不可变资产与 provenance，并在导入前预览覆盖/体积。包体、正文和资产分别校验 SHA-256，资产路径只能是规范的 `assets/<sha256>.<ext>`；低空间、篡改、同 ID 和中断必须失败关闭。`.miaohui` 仅为旧均衡画布兼容包，不得再标成完整项目。
> 26. 大文件清理必须先形成有时效、带指纹的只读扫描快照，再由用户逐项选择并确认精确候选数/字节数后提交统一 Job；执行前逐文件复核大小、修改时间、项目/资源/恢复点引用和活动任务。最终交付、模型与节点载荷只统计不自动删除；共享运行时只能经 `/api/runtime-removal-check` 独立移除。扫描与 Job 的公开响应不得包含绝对路径。
> 27. 生成式语义图像入口只能调用产品内固定版本模板：区域/定点编辑必须以受管灰度 Mask 在模型输出后再次与原图合成，选区外不得依赖提示词“尽量保持”；输入可使用受限 Data URL 或当前项目可见 SHA-256 资产，跨项目引用、尺寸不一致、未知字段、路径穿越和非固定输出节点必须在写入可见结果前失败关闭。原始 Data URL、私有路径和完整提示词不得写入 provenance，输出与点选蒙版必须形成不可变项目资产。
> 28. 新建蒙版配方必须使用 schema v2，并把膨胀/收缩、羽化和弱 Alpha 修剪作为有界、可重放参数；schema v1 只作读取兼容。语义模型定型必须经过锁定候选哈希、环境身份、授权数据、人工评分/返修和选区外漂移的严格画质门；合成夹具只能证明协议可执行，不得作为真实模型质量证据。
> 29. 声音执行必须从 WorkspaceStore 中的当前 `soundTimeline` 重新编译，不接受前端媒体路径或未批准音频。批量 TTS 只使用进程内 BYOK 配置并把成品写为项目不可变资源，自动绑定不等于人工批准；混音 Job 只消费精确条目/版本/SHA/MIME，公开状态剥离字幕私有路径。最终成片引用受管声音 Job ID，并再次核对项目、时间线 revision 与摘要，禁止把旧混音静默烧入新版本。
> 30. 像素动画标签是 `PixelDocument schema v2` 的正式事实；片段范围、方向、循环、批量帧时长和跨帧 Cel 复制必须通过严格可逆命令。播放预览不得增加 revision，Sprite metadata 与游戏 manifest 必须复用同一片段序列解析器；schema v0/v1 只能显式迁移到 v2，未知版本失败关闭。
> 31. `PixelDocument schema v3` 确立的图层组和图层 `groupId/blendMode` 必须继续进入严格文档与可逆命令，组级显隐/锁定必须约束编辑；`normal/multiply/screen/add` 只能由核心确定性 RGBA 合成器执行，并由画布预览、当前帧、Sprite 与游戏交付共同复用。旧 v0/v1/v2 只能经显式迁移进入当前协议，禁止用 CSS/浏览器混合伪装导出结果。
> 32. `PixelDocument schema v4` 确立的逐帧 `gameplay` 必须继续保存整数锚点、最多八个具名矩形碰撞区和可选 8 邻域 Terrain bitmask；编辑、帧复制/删除、撤销、项目/Sprite/game manifest、Tiled objectgroup/WangSet 与离线查看器必须复用同一事实。旧 v0/v1/v2/v3 必须经显式迁移进入当前协议，画布辅助线不得进入 Sprite 像素或另建导出事实。
> 33. 当前像素正文为 `PixelDocument schema v5`：调色板循环只能引用至少两个互不重复且不跨循环占用的现有颜色，动画事件只能绑定现有片段闭区间内的现有帧；增删改、颜色/帧/片段删除和迁移都必须经完整候选校验。循环预览只传递瞬态毫秒偏移，不写 revision；片段包必须以唯一基础帧 Atlas 加精确播放序列表达往返端点，并把事件/循环事实同步交付。
> 34. Terrain 九宫格必须从严格九项布尔占用图确定性推导：斜角位只有斜格与相邻两条正交边同时存在时生效；候选只取同 Terrain，先精确匹配，再按 Mask Hamming 距离、文档帧顺序和稳定 ID 降级。占用编辑和预览不得写 revision；只有中心规则应用可通过一次 `frames.patch` 形成可逆修订。PNG/JSON 预览包必须保存源 revision、逐格期望/命中 Mask、来源、距离和精确性，不得把降级结果标成精确。

## 0. 当前基线与硬规则

源码产品 SemVer、D 盘正式安装态和轻量包均为 `0.7.1`；正式桌面功能轨为 V0.7.30，V0.7.31 是不重编二进制的发行见证，当前功能源码已推进到 `PIXEL-008/V0.7.44`。正式桌面主程序/sidecar 与 clean `7f9bfbc…` manifest 同哈希，隐藏生命周期、四启动单实例、真实图片/像素/H3 纵切、自动停机和保护数据哈希均已通过。V0.7.32—V0.7.34 完成三模式完整项目包、受控自定义 ComfyUI 真执行和统一空间生命周期；V0.7.35—V0.7.36 完成四类语义编辑纵切、可逆蒙版 v2 与严格画质协议；V0.7.37—V0.7.39 建立连续性资产图、声音字幕时间线及批量配音/混音/字幕/成片消费；V0.7.40—V0.7.42 建立有界动画片段、跨帧编辑、非嵌套图层组、四种确定性混合和逐帧游戏元数据，V0.7.43 把像素正文升级到 schema v5，以受控调色板循环、片段内动画事件、无污染预览和唯一基础帧片段包统一创作与游戏交付；V0.7.44 再加入带角门的 3×3 Terrain 推断、精确/Hamming 稳定匹配、九宫格预览与 PNG/JSON 事实交付。V0.7.32—V0.7.44 尚未重新封装或替换正式桌面；V0.7.36 不代表真实 Qwen 画质已验收，V0.7.37 不把人工分数冒充机器阈值，V0.7.39 也不把固定时间窗裁切/补静音冒充强制对齐或口型同步。`AI-001` 仍需授权真实素材与本机数据，`AQ-VID-001` 仍需固定人物样片盲审，`AQ-VID-002` 的基础执行缺口已关闭但固定长片声画质量门仍须建立。轻量包只带应用、bridge 和 WebView2，ComfyUI/Python/模型由工作流中心按需引导；自签名仍不代表 Windows 公共信任或公开商业发行就绪。

`WF-002/V0.7.23` 建立 `aeonquill-runtime-registry-v1`：解析 ComfyUI 标准额外模型路径配置，登记主模型根、共享模型根、节点根、配置文件哈希和反向引用；工作流目录只展示脱敏根标签，安装/启用时才校验固定 SHA-256。当前 D 盘 cu130 运行时已能复用 cu129 的 H3 FP8、H3 INT8 和 SeedVR2 权重而不建议重复下载；SAM 权重虽存在，但当前 cu130 缺少 Impact Pack，因此仍诚实保持未安装。绝对共享根被明确标记为不可搬迁风险，旧运行时在引用修复前不得删除。

`REL-018/V0.7.24` 建立 `aeonquill-build-identity-v1` 与 `aeonquill-runtime-registry-migration-v1`：构建身份统一携带产品版、功能轨、源码提交、运行时包 ID、注册表版本及身份哈希，新建 Job 同步保存不可变执行身份；设置页和诊断页公开脱敏身份。迁移器只改写额外模型路径 YAML 中可证明等价的绝对 `base_path`，先预览、再以配置哈希门和原子备份应用，支持逐字节回滚；运行时、队列或安装任务非空闲时拒绝变更，且绝不移动、复制或删除模型。本检查点只完成源码与隔离 D 盘配置验证，正式配置和桌面尚未改变。

`REL-018/V0.7.25—V0.7.28` 修复 clean 桌面封包中的 WebView2 网络、PowerShell 宿主和 Tauri 内部签名不确定性。签名脚本优先从 Tauri 的 D 盘本地工具目录发现官方 x64 离线安装器，只接受大于 50 MiB、Windows SDK SignTool `/pa` 验证成功且 PE 嵌入证书主体为 Microsoft Corporation 的文件，以纯 .NET 流式 SHA-256 记录哈希并选择最高文件版本；显式指定的无效文件直接失败关闭。这里不再依赖易受 npm 父宿主 `PSModulePath` 影响的 `Get-AuthenticodeSignature` 或 `Get-FileHash` 自动加载；受审 Tauri CLI 自身也用同一类 .NET 哈希门。检测到可信离线输入时只使用从固定 2.11.4/2.9.4 源码离线重建的 `tauri-cli 2.11.4`，当前为 28,631,040 bytes、SHA-256 `3ED4C56D…2B60009`。签名封包分为四步：`build --no-bundle`、外部签署主程序与 sidecar、`bundle` 只组装已签署载荷、外部签署 NSIS；Tauri 分包阶段不再接收证书配置，避免其内部签名路径在生成 `installer.nsi` 前返回无上下文 EOF。为跨原生子进程稳定传递离线输入，脚本把原件逐字节复核到 D 盘纯 ASCII 临时名，补丁优先接受显式文件并以 `TEMP` 固定名兜底；显式输入不可读时立即报错，不再静默回落网络。构建结束恢复原环境，没有可信缓存时才使用官方网络流程，不把未知二进制加入安装器。

`REL-018/V0.7.29` 修复封包 sidecar 的构建 SHA 只依赖父进程环境、独立运行时退化为 `unversioned-development` 的缺口。`build-node-sidecar.mjs` 在调用 `pkg` 前拒绝 dirty worktree，解析 40 位 clean HEAD，并要求显式 `AEONQUILL_BUILD_COMMIT` 与 HEAD 完全相同；随后生成 Git 忽略的 `aeonquill-embedded-build-identity-v1` JSON，`sidecar.pkg.json` 明确把该文件收入快照。`resolveBuildIdentity()` 在 packaged 运行时必须读取并逐字段核对产品版、功能轨、身份版本、注册表版本及 SHA；缺失、损坏或环境提交不同均以 `BUILD_IDENTITY_EMBEDDED_INVALID` 失败关闭。开发态源码服务仍可用显式环境或 Git 探测。`validate-node-sidecar` 直接比较健康接口与内嵌资源，使 release manifest 正确但实际 sidecar 不自描述的候选无法再通过。

必须遵守：

1. 导入图片和派生图片可在提交前短暂使用 Data URL；SQLite 自动保存会将其外置为 SHA-256 内容寻址文件并改写成 `/api/project-assets/<hash>`，正式项目不得长期依赖内嵌二进制。
2. `pixel` 元件保存像素索引数组，禁止把每个像素创建为独立画布元件。
3. `connector` 通过 `fromId`、`toId` 引用端点；删除节点时必须同步清理连接线。
4. `processingStack` 是派生来源与显示开关元数据，不是完整图像 DAG；正式处理结果通过 `assetVersionId`、`jobId` 和 `sourceElementId` 追踪。
5. 视频二进制不进入画布 JSON；执行期可短暂引用 `/api/assets/...`，项目自动保存后必须规范化为 `/api/project-assets/<sha256>` 和不可变版本元数据。
6. ComfyUI 只监听 `127.0.0.1:8188`；浏览器只访问 `127.0.0.1:8787` 的 AEONQUILL 桥接服务。
7. 当前运行中取消调用 ComfyUI 全局 interrupt，只能用于受控单机，不能直接扩展到多租户。
8. rembg 只允许本地 `u2netp`/`u2net` 白名单并校验权重 MD5；禁止在首个用户任务中静默联网下载模型。
9. AEONQUILL 只关闭自己启动的 ComfyUI 进程；检测到外部 ComfyUI 时只提示显存风险，不得代用户终止。
10. 文本 Agent 的第三方密钥只保存在桥接进程内存中，刷新或重启后失效，不得进入浏览器状态、项目正文、日志或导出；Agent 只能产生严格变更卡，必须经用户接受后才通过正式命令修改生产图。远端端点必须为 HTTPS，仅允许回环地址使用 HTTP，并拒绝凭据 URL、重定向、私网字面地址及超限响应。
11. 图像、视频与 TTS BYOK 只允许登记的 capability/profile 和固定请求/响应映射；每次调用先检查用户单位费率、本次预算、适配器费用上限、超时、输出来源、媒体 MIME 魔数与字节上限。结果必须成为项目资源库不可变版本或统一 Job，密钥不得落盘；sidecar 重启后外部排队任务必须要求重新授权，不能为了恢复而持久化密钥。

## 1. 系统定位

AEONQUILL 当前验证一个高集成视觉创作产品的单机形态：用户在无限画布中组织图片、像素画、文本和视频，通过浏览器确定性处理器完成低成本编辑，通过本机 ComfyUI 完成 H3 视频生成。

| 术语 | 当前含义 |
| --- | --- |
| 视口 | `.canvas-viewport`，接收指针、滚轮和文件拖放 |
| 世界层 | `.canvas-world`，统一应用相机平移与缩放 |
| 相机 | `Camera { x, y, zoom }` |
| 元件 | `CanvasElement`；当前包含图片、像素、文本、视频和连接线等种类 |
| 浏览器图片草稿 | `ImageLab` 内的短任务，刷新后不恢复 |
| 正式图片/视频任务 | 本地桥接持久化 Job，刷新后通过 REST/SSE 恢复 |
| 执行器 | FFmpeg、rembg/u2netp、Real-ESRGAN NCNN 和回环地址上的 ComfyUI |
| 本地资产 | `.runtime/assets/*.{png,mp4}`，通过同源 API 提供；MP4 支持 Range |

本原型已负责单机视频推理和异步任务，但不负责用户登录、云端保存、多租户隔离、多人协作或商业计费。

画布和本地任务是两个不同的权威域：`App.canvasDocument` 负责空间、元件、schemaVersion 与修订历史，`JobStore` 负责持久化执行事实，`JobScheduler` 只负责资源分配与生命周期推进。SSE 到达后，视频 Job 更新占位节点；完成的图片 Job 创建新的图片节点与连接线，原图不覆盖。系统回填仍经过文档校验但不污染用户撤销栈；用户撤销画布操作不会取消执行任务，任务取消也不会回滚其他画布操作。

## 5. 启动与运行流程

### 5.1 前端初始化

1. `src/main.tsx` 挂载 `App`。
2. `loadProject()` 先构造 v8/v7 本地恢复候选；随后读取 `/api/projects/current`，采用 revision 不低于本地候选的 SQLite 项目，均不存在时回退到示例画布。
3. `App` 拉取 `/api/jobs` 和 `/api/runtime/status`，并订阅 `/api/jobs/events`。
4. 视频 Job 快照与本地图片 Job 合并到 `App.jobs`；项目 revision 变化后自动保存并接收规范化资产引用。
5. 画布中带 `jobId` 的图片/视频元件按 Job 状态恢复运行、失败或完成呈现。

### 5.2 视频任务

1. 用户在“视频”页选择文生或图生、场景模板、镜头运动、动作强度、连贯性、声音、音乐、约束、画幅、时长、流水线、音频和 Seed；前端使用共享编译器实时预览 H3 三段式提示词。
2. 图生模式从当前图片元件读取首帧，并可上传末帧；浏览器把两者 cover 裁切到目标宽高并导出 PNG Data URL。
3. `POST /api/jobs/video` 只接受白名单参数，并用 `Idempotency-Key` 绑定请求；服务端不信任前端预览，重新运行版本化提示词编译器，再原子写入持久化 Job、场景/精度 provenance 与 GPU 调度元数据。`POST /api/video/prompt/compile` 只提供不启动 GPU 的预览/校验。
4. `JobScheduler` 按优先级取得唯一 GPU 容量并设置两小时安全超时；Runtime Manager 再根据 `persistent | idle | manual` 策略准备 ComfyUI，只有 AEONQUILL 创建的子进程允许自动关闭。未显式配置外部路径时优先探测版本化离线运行时包。
5. `workflow-builder` 从 `video-workflow-registry` 解析模型档案、显存门槛和 4/6/8 步预设，再克隆相应模板并注入首/末帧和受控参数；关闭音频时移除无用分支。
6. 桥接先建立 ComfyUI WebSocket，再 `/prompt` 提交任务。
7. 节点执行与 `progress.value/max` 转为准备、条件、采样、解码、封装和保存状态。
8. 完成后桥接从 history 找到 `SaveVideo` 输出，通过 `/view` 下载到临时 MP4 并原子改名；720P 交付档保留原生 MP4，再由可取消 FFmpeg 子进程生成 Lanczos 交付文件并在 `intermediateOutputs` 登记原生结果。
9. 桥接计算最终文件 SHA-256 和确定性 `outputVersion` 后才把 Job 置为 `completed`；SSE 回填画布，项目保存将执行期 URL 外置为不可变项目资产。完成资产复制到用户自选目录；没有自选时复制到桌面壳提供的软件默认 `output`。调度器记录实际 GPU 毫秒，队列清空后 `idle` 策略进入关闭倒计时。

完整节点和 API 契约见[本地 H3 视频工作流](01-子文档/11-本地H3视频工作流.md)。

### 5.3 画布与图片任务

- 用户离散修改通过能力注册表编译为 `CanvasCommand`，再由纯函数执行器校验、递增 revision 并记录完整文档历史；旧复杂调用暂由内部 `elements.replace` 适配器渐进迁移，Agent 无此权限。
- 拖动和缩放用 `onElementsPreview()` 连续更新内存预览，不校验、不落盘、不增加 revision；指针释放后才通过 `commitCanvasPreview()` 校验并提交一次文档修订。
- 图片实验室应用调整时更新同一节点；浏览器裁剪/草稿和正式图片 Job 都创建派生图片与连接线；像素化草稿可创建可编辑像素节点。
- 正式操作先读取 `GET /api/image-tools`；`POST /api/jobs/image` 只接受操作与参数白名单，并要求前端为一次用户提交生成稳定 `Idempotency-Key`。`masked-adjust` 额外要求独立的 PNG/JPEG/WebP Mask Data URL，并把源图与蒙版分别写入受管输入目录；输入不会进入公开 Job，输出先写临时 PNG，完成后作为 `.runtime/assets` 正式执行资产。
- 语义图片操作先读取 `GET /api/semantic-workflows`。`semantic-image-v2` 固定登记并实现 `element-extract@impact-sam-v1`、`region-edit`、`point-edit` 和 `portrait-adjust` 四类能力，分别报告 `ready`、`runtime-stopped`、`missing-dependency` 或 `node-mismatch`。已安装但休眠可按任务启动；缺模型/节点时 UI 禁止提交，不伪装为可执行。
- 元素提取与定点修改都在图片上记录 0–1 归一化的正/负点击点：前者经 Impact Pack `/sam/prepare`、`/sam/detect` 输出透明元素和灰度蒙版；后者先生成同尺寸 SAM 蒙版，再把源图与蒙版送入固定 Qwen 模板。至少一个正向点、最多 32 个总点、阈值 0.5–0.99；点选蒙版也写入项目资源库。
- `region-edit` 只接受有明确 Alpha 来源链的派生图，服务端先验证源/Mask 尺寸一致，再抽取 Alpha 或灰度。`point-edit`、`region-edit` 最终都用 `ImageCompositeMasked` 把 Qwen 候选覆盖回原图，选区外直接保留源像素；`portrait-adjust` 不使用蒙版，但会把 0–1 身份强度编译为身份、年龄、肤色和五官约束。
- 三类 Qwen 工作流共用 `qwen-image-edit-2511-int8-v1`：`FluxKontextImageScale → Qwen Image Edit 2511 INT8 ConvRot / Qwen2.5-VL FP8 / Qwen VAE → ModelSamplingAuraFlow shift 3.1 → CFGNorm → 40-step KSampler (CFG 4, Euler/simple) → VAEDecode`。模板节点 ID/类型、受管输入引用、输出节点 `118` 和文件格式均在服务端锁定；模型三文件总计 30,137,560,750 bytes，只能经工作流中心固定 URL/大小/SHA-256 门下载到用户选择的 ComfyUI 模型根。
- `POST /api/jobs/semantic-image` 只接受严格字段和当前活动项目；来源/Mask 可为受限 PNG/JPEG/WebP Data URL 或当前项目可见的小写 SHA-256 资产 ID。公开 Job 不保存 Data URL/私有路径，provenance 记录内容哈希、工作流/提示词版本、指令哈希、seed、采样参数和来源；跨项目资产、内容哈希漂移、Mask 尺寸错误、路径穿越、非固定输出或超过 256 MiB 的结果失败关闭。
- 确定性 `masked-adjust` 仍与生成式编辑分开：它只接受由 `element-extract`、`semantic-element-extract`、`mask-refine`、`remove-background` 或 `alpha-cleanup` 明确产生的 Alpha 派生图，以 FFmpeg 执行 `selection-highlight`、`background-dim` 或 `background-blur`，强度 0.1–1、羽化 0–32px，不冒充 Qwen 重绘。
- 五种 FFmpeg 操作登记为 CPU 资源，模型去背景/超分和 H3 视频登记为 GPU 资源；CPU 容量由 `MIAOHUI_IMAGE_CONCURRENCY` 控制，GPU 容量固定为 1。各资源内部按优先级、排队时间和稳定序号选择任务，不再维护图片专用队列。
- GPU 图片任务发现妙绘托管且空闲的 ComfyUI 时会先停止其进程树；外部 ComfyUI 只记录警告，不会自动关闭。
- 完成 Job 经 SSE 到达 `App` 后，以 `job.id` 去重，生成包含 `processingStack`、`assetVersionId`、`sourceElementId` 的派生图片；输出哈希与版本 ID 已由桥接确定，用户删除后不会因其他 Job 更新而复活。
- 只有 `CanvasDocument.revision` 变化后才以 260ms 防抖写入恢复副本并提交 `ProjectStore`；ProjectStore 会外置 Data URL 与运行时 PNG/MP4、返回规范化引用，相机平移/缩放和手势中间帧不制造整树持久化。
- `CanvasWorkspace` 为可见非连接线节点建立旋转 AABB 均匀网格索引；相机只查询带 240 屏幕像素 overscan 的世界视口，选中节点和背景强制保留，连接线通过端点 Map 和包围盒裁剪。相机高频更新合并到动画帧，小地图用单 Canvas 绘制全部缩略几何。
- 受管图片在画布内按屏幕投影选择 `thumbnail-v1`（512px）或 `preview-v1`（1600px）WebP；编辑和导出仍读取原始 SHA-256 资产。派生缓存按源哈希并发去重、临时写入后原子提交，不进入资产版本链。

### 5.4 桌面壳与桥接生命周期

Electron 和 Tauri 均先取得随机回环端口，以受限环境启动同一桥接，再等待 `/api/health` 成功后创建窗口。渲染器只加载本次启动的精确 Origin，不拥有 Node、Shell 或文件系统桥；页面业务仍使用现有 HTTP/SSE/HttpOnly 会话，不维护桌面专用状态。

Electron 使用 `utilityProcess.fork(server/index.mjs)`；Tauri 使用 Rust Shell 插件启动自包含 Node 22 sidecar。Tauri 通过 `AEONQUILL_PARENT_CONTROL=stdio`（旧变量仅作兼容）发送 `shutdown\n`，Electron 通过 Utility Process 生命周期请求退出；两者都验证桥接退出、端口关闭和渲染器沙箱，超时才终止自有进程树。Tauri 的主窗口 `CloseRequested` 必须显式请求应用退出，`run_return` 返回后才执行 sidecar 关闭；QA 自动路径调用真实 `window.close()`，不得再以直接 `app.exit()` 绕过窗口关闭语义。当前发行候选和实测差异见[13-桌面封装与发行架构](01-子文档/13-桌面封装与发行架构.md)。

Tauri 的 `tauri-plugin-single-instance` 必须是 Builder 注册的第一个插件，在 `setup_desktop()` 启动 sidecar 和创建 WebView 前取得系统级应用锁。正常模式再次启动时，第二进程立即让位，由现有进程恢复、显示并聚焦 `main` 窗口；隐藏 QA 模式不执行聚焦，避免自动验证抢占用户前台。`scripts/validate-desktop-single-instance.mjs` 会在 D 盘隔离便携根同时发起一次主启动和三次重复启动，只有观测到一个 desktop、一个 bridge、三个次实例退出码为 0 且主实例完成标准关闭链才通过。

桥接优先读取 `AEONQUILL_RUNTIME_DIR`、`AEONQUILL_DATA_DIR`、`AEONQUILL_CACHE_DIR`、`AEONQUILL_LOG_DIR` 与 `AEONQUILL_CONFIG`，并只把旧 `MIAOHUI_*` 作为兼容输入。运行中临时文件位于 runtime，项目、Job、不可变资产和跨 Origin 客户端状态位于 data，预览位于 cache，ComfyUI 日志位于 logs；安装目录不作为写入目标。若升级时发现新 data 尚无持久数据、旧 runtime 却存在 jobs/projects/assets/client-state，桥接会继续使用旧位置并报告 `LEGACY_DATA_LAYOUT`，不自动搬移或删除；干净安装仍使用新分层。`REL-003` 已让 Tauri/Electron 在应用本地数据根下正式注入同级五目录，并验证干净 data 建库、旧 runtime 数据回退、卸载保留与安装目录无写入；桌面壳不会无条件注入 ComfyUI 策略/空闲秒数，因此用户保存在 `config/local.json` 的选择不会被环境变量永久覆盖。

当前源码的默认离线包位于 `<runtime>/packages/aeonquill-comfyui-h3-cu130-win-x64-v3/`。Runtime Manager 以包内 `python/python.exe` 启动 `ComfyUI/main.py`，同时注入 `--input-directory <data>/comfyui/input`、`--output-directory <data>/comfyui/output`、`--user-directory <data>/comfyui/user` 与 `--temp-directory <cache>/comfyui/temp`，避免模型载荷目录被运行数据污染。新包不包含 `pyvenv.cfg` 或 `extra_model_paths.yaml`，模型位于包内标准目录；显式用户配置仍优先于包内回退，诊断只公开运行时包 ID。

### 5.5 智能视频计划到本机队列

`productionPipeline.mjs` 在故事编译之前增加了长视频制片层。它不是外部模型调用器，而是一套本地、确定性、可导出和可恢复的编排契约：

```text
VideoProductionProject schema v4
  → 制片统筹 → 剧本 → 人物 → 场景 → 分镜
  → 素材 → H3 镜头 → 剪辑 → 声音字幕 → 成片质检
  → 每节点 ready / running / paused / review / approved / revision / failed
  → 极速 / 质量生成策略 + 快速 / 专业人物策略
  → 角色身份锁、正侧背三视图、基础与场景服饰状态
  → ContinuityGraph：角色 / 视图 / 服饰 / 地点 / 首尾帧 / 镜头 / 复核
  → 资源库版本绑定 → 人工批准 → 每镜接受 / 定向重生
  → SoundTimeline：声线 / 对白 / 旁白 / 音乐 / 环境声 / 音效 / 字幕 / 混音
  → 音频版本绑定 → 字幕与声音规格批准 → 声音导演门
  → 本地或 BYOK Agent 严格变更卡 → 用户接受 / 拒绝
  → 用户审批后的分镜源
  → StoryProject + GenerationPlan + 持久化生产会话
```

- 十个节点只允许引用排序在自己之前的依赖，未知字段、重复 ID、循环/逆序依赖、非法状态跃迁和过期 revision 均关闭失败。
- 全局暂停会把运行节点安全停在 `paused`；恢复后继续。用户编辑已批准节点会把该节点退回审批，并把所有下游节点重置为等待和过期；返工、审批、失败重置均写入有界事件历史。
- 十分钟武侠示例按 12 场、120 个五秒镜头、24 个生成批次估算；基于 RTX 4060 8GB 的 `master720` 顺序链显示约 40–80 小时，而不是把单镜头 20–40 分钟误写成整片耗时。
- `ProductionStudio` 支持用户显式选择极速/质量和快速/专业人物策略，系统建议只作解释性推荐，不能覆盖用户选择。专业人物模式生成身份锁、正/侧/背视图约束和场景服饰状态；当前这些是严格生产约束与素材占位，不伪造已经完成真实生图。
- 本地确定性 Agent 和 OpenAI-compatible 文本 BYOK Adapter 都只能返回严格变更卡。卡片含目标节点、理由、拟议指令和输出摘要，接受后才重新进入节点审批并使下游失效；拒绝、过期或已被人工编辑取代的卡片不得修改正式项目。第三方密钥只存在桥接内存，远端失败不会回显密钥或上游响应正文。
- `continuityGraph.mjs` 从 `StoryProject` 编译角色、所需视图、服饰状态、地点、质量模式首尾帧和镜头引用。槽位只保存资源库条目、不可变版本、SHA-256、MIME、范围和绑定时间，不保存 Data URL、临时 URL 或本机路径；故事同步保留仍与人物/地点语义一致的内容寻址资产。
- 绑定资产只进入 `ready`，必须由用户显式批准为连续性基准；替换、移除或换装会重新计算输入指纹并只撤销受影响镜头的活跃复核。素材节点要求全部必需槽位已批准，H3 导演节点要求全部镜头有当前输入对应的 `accept` 结论。
- 镜头复核记录身份、服饰、地点、清晰度和运动五维 0—5 人工分数、备注与 `accept/retry`；`retry` 仅从相对弱项生成定向返修建议，不存在伪造的绝对机器阈值。
- `soundTimeline.mjs` 从故事编译绝对时间码的对白、旁白、每场环境声、镜头音效提示、全片音乐床和关联字幕，并保存角色声线、字幕安全区/样式及 48kHz 双声道响度目标。MP3/WAV 只以资源库条目、不可变版本、SHA-256、范围和绑定时间引用，不保存路径或密钥；对白/旁白音频、字幕、样式和混音都须显式批准，缺一项时 `sound-director` 失败关闭。
- production v1/v2/v3 读取时依次迁移到 v4；节点、审批、事件和连续性资源保留，旧松散图片或音频无法证明条目、版本和内容哈希时只回到待绑定，不伪造批准。故事、声线、文本、时间码、字幕样式或混音变化只撤销相应结论。
- `sound-renderer.mjs` 只从 WorkspaceStore 当前生产正文编译声音计划。`prepare-speech` 要求声线已批准、TTS Adapter 与声线服务标签一致且总预计成本不超用户预算；每条结果经媒体魔数复检后写入项目资源库，并由前端以 `orchestrator` 命令自动绑定，仍保持 `ready` 等待人工试听批准。时间线在排队期间变化会以 revision 冲突失败关闭。
- `render-mix` 只解析已批准条目/版本/SHA/MIME 对应的项目可见音频，先用 FFprobe 验证真实音轨，再按绝对时间窗执行裁切/补静音、增益、淡入淡出和对白期间音乐/环境声闪避，最后输出 48kHz 双声道 PCM WAV，并生成 SRT、VTT 与受管 ASS。公共 Job/SSE 剥离全部字幕本机路径；固定时间窗处理不等于词级强制对齐。

`StoryProject` 与 `GenerationPlan` 仍然只描述故事、场景、镜头和上游参考/帧任务，不直接执行模型。`storyExecution.mjs` 在计划之上建立第二层严格契约：

```text
StoryProject + GenerationPlan
  → 严格镜头选择（T2V / I2V、固定档位、受管帧引用）
  → 运行时 / 模型 / 节点 / 显存 / 首末帧依赖判定
  → ready / blocked 执行清单
  → 用户确认指纹
  → 固定 MiniMax H3 VideoJobRequest
  → 现有 /api/jobs/video + JobScheduler + SSE
```

确认后的多镜头清单还可进入受控连续长片路径：

```text
confirmed Story submissions
  → /api/jobs/video-chain（orchestration，GPU 并发不占用）
  → 第 1 镜 /api/jobs/video（T2V）
  → FFmpeg 提取上一镜末帧到受管 input
  → 第 2..N 镜 /api/jobs/video（I2V，GPU=1 串行）
  → /api/jobs/final-cut（CPU）
  → 1280×720 / H.264 High / AAC 48kHz stereo
```

- `video-chain` 只接受同一受管项目的 2–24 个 5 秒镜头参数，不接受工作流 JSON、URL 或文件路径。父 Job 使用独立 `orchestration` 资源，避免父任务持有 GPU 时等待子任务造成死锁；取消父任务会把信号传给当前子 Job，已完成镜头继续保留。
- 每个镜头完成后从其受管 MP4 距结尾约 0.12 秒处提取一帧，按目标 H3 画幅以 Lanczos cover 方式规范化为 PNG，再作为下一镜唯一 I2V 首帧。子 Job ID、逐段模型档、采样参数、输出版本和父子关系均留在 `JobStore`；父任务重试会复用仍存在且 completed 的顺序断点，从第一个不可复用镜头继续。
- `final-cut v2` 只接受 completed 的 `video`/`provider-video` Job ID；没有声音 Job 时沿用逐镜补静音、`acrossfade`、-14 LUFS/-1.5 dBTP 的兼容路径。附带 `soundRenderJobId` 时必须同时提供项目 ID，服务端复核声音 Job 已完成、项目一致、时间线 revision 与摘要仍是当前事实，再以该 WAV 替换镜头原音频并烧录同 Job 的受管 ASS；旧混音不会静默进入新成片。两条路径都统一缩放裁切、`xfade`、H.264 slow/CRF 17，并在完成前重新探测尺寸、时长与音轨。
- V0.7.20 在 RTX 4060 8GB/cu130 上以《雪夜问剑》实跑六镜：首镜 T2V、后五镜末帧接力 I2V，全部使用 `balanced` 1024×576、INT8 ConvRot、8 步和原生音频，最终为 30.416667 秒 1280×720/24fps H.264 High/AAC。机械媒体门通过，但六点抽帧仍可见后半段面部身份漂移；末帧接力改善构图连续性，不等价于专业角色参考图或身份模型。

- 执行选择、清单、确认和受管帧资产均为 schema v1 严格对象，未知字段直接拒绝；LLM 候选必须先经过 `server/intelligent-video/execution-planner.mjs`，不能携带 workflow ID、ComfyUI 节点 JSON 或本机路径。
- 只允许 `aeonquill.video.minimax-h3-t2v.v1` 与 `aeonquill.video.minimax-h3-i2v.v1` 两个产品级 ID；它们映射到桥接内固定的 H3 文生/图生模板，再由 `aeonquill-h3-registry-v2` 注入受控 Turbo/Base、精度和后处理参数，产品级 ID 本身不作为任意后端模板入口。
- 清单只保存稳定 `bindingId` 与 `assetVersionId`，不保存 Data URL。ready 帧的版本 ID 必须采用 `sha256:<64 位小写十六进制>` 内容寻址；浏览器导入的帧先按目标画幅执行 `normalizeVideoFirstFrame()`、转为 PNG 并计算 SHA-256。确认清单编译为提交参数时会再次受限解码 Data URL、对实际字节计算 SHA-256 并与版本 ID 比较，ID、MIME 或字节任一不符都不会进入现有视频 API。
- `fast`、`balanced`、`delivery720`、`nativeHigh`、`cinemaBase` 与 `master720` 的标称显存门均为 8GB，但每档时长和运行时能力另行限制：1344×768 只允许 5 秒，Base/SeedVR2 只允许 5/10 秒，`master720` 还必须具备完整 SeedVR2 模型和节点。显存比较使用原始字节值而不是 UI 的一位小数；仅允许最多 64 MiB 的驱动报告偏差，使标称 8GB、报告略低的设备不被误拒，短缺超过容差仍返回 `VRAM_INSUFFICIENT`。桥接不可用、手动策略下运行时停止、已探测模型/节点缺失、显存未知或不足、I2V 首帧缺失以及明确选择首末帧但末帧缺失，均形成可读阻塞码，不伪造依赖。
- 清单与确认使用规范 JSON 的 SHA-256 指纹防止 UI 中的过期确认或意外字段替换；它是本地工作流完整性检查，不替代服务端会话、来源校验和参数白名单。
- `SmartVideoWorkbench` 直接复用 `videoApi`、`JobStore`、`JobScheduler` 与 `/api/jobs/events`，展示排队、阶段、进度、错误、取消和快速重试；没有智能视频私有队列。批量执行只是同一已确认严格清单上最多 24 个镜头的幂等迭代，不会自动提交整部长剧。

像素图像导入的浏览器边界位于 `src/modes/pixel/pixelBrowser.ts`：这里只解码 PNG/WebP、把 RGBA 编码为 PNG 并触发下载，不把源文件字节或 Base64 写入 `PixelDocument`。`src/lib/pixel/pixelConversion.mjs` 是可独立测试的纯函数层，负责 nearest-neighbour 的 `contain` / `cover` / `stretch` 缩放、确定性 median-cut 调色板、固定调色板复用、`none` / `bayer4` / `floyd-steinberg` 抖动和透明阈值。相同 RGBA 与相同参数必须产生相同序列化文档；固定样本哈希由 `tests/pixel-conversion.test.mjs` 锁定。

像素项目下载使用 `application/vnd.aeonquill.pixel+json` 与 `.aeonpixel.json`，导入必须显式声明 `schemaVersion`；当前 schema v5 严格校验，schema v4 补空调色板循环/动画事件，schema v3 为每帧补安全默认游戏元数据，schema v2 再补空组并把旧图层规范为不分组/normal，schema v1 补空动画标签，schema v0 进入既有单层迁移器，缺失或未知版本直接拒绝。成套导出由一次 `createPixelExportBundle()` 形成项目 JSON、当前帧 RGBA、Sprite Sheet RGBA 与 metadata；Sprite PNG 和 metadata 共享同一个布局及核心 RGBA 合成事实，帧 ID、顺序、时长、动画标签、图层组、混合模式、逐帧游戏元数据、调色板循环、动画事件、坐标和源 revision 可追溯。产品入口原有 `aeonquill:pixel-document:v1` 自动草稿键名仍走 `serializePixelDocument()` / `deserializePixelDocument()`，该键名只是兼容标识，与当前正文 schema 及手动项目往返互不替换。

调色板循环与动画事件由 `src/lib/pixel/pixelCore.mjs` 中的独立可逆命令维护：循环最多 16 组，每组 2—32 个现有且跨循环互不占用的颜色、20—60000ms 步长和 `forward/reverse/ping-pong` 方向；事件最多 256 条，类型只允许 `marker/sfx/hit/custom`，并同时引用现有动画片段和其闭区间内的现有帧。删除被引用颜色、帧或片段会失败关闭。`resolvePixelPaletteCycleMap()` 只根据文档和瞬态毫秒偏移生成颜色 ID 映射，`renderPixelFrameRgba()` 在确定性图层混合前应用该映射，因此播放不写 revision/undo。`createPixelAnimationClipExportBundle()` 生成 PNG 加 JSON 两文件：Atlas 只含活动片段的唯一基础帧，播放序列仍保留正放/倒放/乒乓的逐项时长和端点语义，事件、循环、游戏元数据、图层与组事实同源。详细契约见[逐帧游戏元数据、调色板循环与动画事件](01-子文档/19-逐帧游戏元数据与Tileset规则.md)。

像素动画边界位于 `src/lib/pixel/pixelCore.mjs`。`animationTags` 用起止帧 ID、`forward/reverse/ping-pong` 和循环标记描述有界片段；`resolvePixelAnimationFrames()` 同时供工作台预览、Sprite metadata 与游戏 manifest 使用。`frames.duration.set` 原子修改多个帧时长，`cels.copy` 以覆盖或非透明合并把指定图层复制到多个目标帧，二者都先全量校验并返回完整逆命令。删除边界帧、倒置标签范围、锁定层、重复目标和超过 1,048,576 单元格的批量命令均在写入前失败关闭。详细契约见[像素动画片段与跨帧编辑](01-子文档/17-像素动画片段与跨帧编辑.md)。

像素图层组织和合成边界同样位于 `pixelCore.mjs`。`layerGroups` 保存最多 32 个非嵌套组，图层以 `groupId` 引用并只允许 `normal/multiply/screen/add`；组删除只解除归属，不删除 Cel，组恢复会原子恢复原位置和成员。隐藏组不参与预览/导出且拒绝新的像素写入，锁定组拒绝像素、区域、清理和跨帧写入。核心以固定 Alpha/混合公式生成 RGBA，工作台 Canvas、当前帧、Sprite 和游戏 Atlas 不另建浏览器混合路径。详细契约见[像素图层组与确定性混合](01-子文档/18-像素图层组与确定性混合.md)。

专业像素工具的纯函数边界位于 `src/lib/pixel/pixelTools.mjs`。Bresenham 线段、矩形、连续区域填充、方形笔刷扩张、水平/垂直镜像和选区变换均只接收有界整数坐标，不读取 React 状态。自由笔划会先补齐相邻指针点之间的线段，再按笔刷与镜像去重，整个手势只提交一次 revision。移动、复制、翻转和清除会生成同时携带颜色 ID 与 `null` 的 `pixels.patch`；该公共命令仍受锁定图层、已知调色板、唯一坐标和 65,536 像素上限校验，并返回系统专用 `pixels.restore` 逆命令。选区只是本地草稿，方向键移动、Alt+方向键复制、Delete 清除，只有区域像素实际变化时才进入历史。概念基准见 [pixel-editor-v0614-concept.png](image/pixel-editor-v0614-concept.png)。

游戏资产交付边界位于 `src/lib/pixel/pixelGamePipeline.mjs`。schema v5 manifest 只从经严格校验的同一 `PixelDocument` 和单次规范化选项创建，固定保存源文档/revision、Atlas 单元格、帧时长、全部动画片段、选定主动画、图层组/混合模式、逐帧锚点/碰撞区/Terrain 规则、调色板循环、动画事件、八方向映射、调色板与 Tilemap；Tiled TSJ 为每个 tile 写入碰撞 `objectgroup`，并按 Terrain ID 生成 `type: mixed`、`colors` 和八项 `wangid`，TMJ 引用该 TSJ，离线 HTML 查看器复用 manifest 并叠加同一元数据，不自行推导另一套 GID、碰撞或帧顺序。没有标签的旧项目仍得到兼容的 `default` 动画。查看器只读取同目录 Sprite PNG，禁止外部 URL。工作台对游戏元数据的修改复用 `frames.patch` 完整候选校验和逆命令；详细契约见[逐帧游戏元数据与 Tileset 规则](01-子文档/19-逐帧游戏元数据与Tileset规则.md)。`createSmartPixelCleanupPatch()` 只执行八邻域孤点删除与四邻域同色针孔填充，未知选项、尺寸不符、未知帧和图块尺寸不匹配全部失败关闭；应用仍通过一次 `pixels.patch` 提交，因此图层/组锁、补丁上限与撤销语义不分叉。

同一模块的 `createPixelTerrainPreviewLayout()` 把固定九项布尔占用图转换为 3×3 Terrain 布局：正交邻边直接置位，斜角仅在斜向格和相邻两条正交边同时占用时置位。候选限定为同 Terrain，先精确匹配，再按期望/候选 Mask 的 Hamming 距离、文档帧顺序和稳定 ID 选择降级帧；每格保留期望/命中 Mask、来源、距离和精确性。`renderPixelTerrainPreviewRgba()` 复用核心 RGBA 合成器并缓存重复来源，`createPixelTerrainPreviewExportBundle()` 交付 3×3 PNG 与 `aeonquill.pixel-terrain-preview` JSON。工作台只以 `useMemo` 从正文和瞬态占用图派生预览，函数式更新单格状态；预览不写正文，只有中心 Mask 应用进入一次 `frames.patch`。完整算法、交付字段和限制见[逐帧游戏元数据、调色板循环、动画事件与 Terrain 九宫格](01-子文档/19-逐帧游戏元数据与Tileset规则.md)。

图片实验室同时提供浏览器草稿和本机正式处理。草稿仍可能在主线程运行且只供预览；正式去背景是 `u2netp` 通用主体分割，正式超分是 Real-ESRGAN，并不等于生产级细发丝 Matting 或任意素材的最佳质量。当前适配器仍在桥接进程调度子进程，正式分发前应拆出隔离 Worker，并建立素材基准与许可证清单。

运行时注册表只读取配置与目录事实。默认检查 `<ComfyUI>/extra_model_paths.yaml`、`extra_model_paths.yml`，并识别启动参数中的 `--extra-model-paths-config`；单个配置上限 256 KiB，分组、类别和路径数量有界，YAML 解析失败只隔离该配置并形成可操作告警。相对路径、环境变量、`~`、多行类别路径和 `base_path` 均按 ComfyUI 语义解析；前端只得到安全根标签，绝对本机路径仍由公共响应脱敏层移除。目录刷新不扫描整盘、不读取模型内容；已有文件在用户发起“校验并启用”时按目标路径专属指纹计算 SHA-256，匹配后登记，失败时不覆盖共享文件。新增下载仍只写主运行时固定相对目录，原子提交后登记同一指纹。

运行时迁移服务只处理注册表已识别且能够保持解析根不变的 YAML `base_path`。预览不写文件；应用要求当前配置 SHA-256 与预览一致、ComfyUI/Job/安装队列均空闲，先在 D 盘配置同目录形成原子备份和状态，再写入相对路径并重新解析验证。回滚同样校验当前哈希后逐字节恢复原配置；公开响应只返回脱敏标签、哈希和数量。删除旧运行时前必须调用 `/api/runtime-removal-check`，任何仍命中的配置、模型或节点反向引用都会返回拒绝结论；本服务本身不执行删除。

自定义 ComfyUI 真执行由 `prepareCustomExecution()` 与 `CustomWorkflowExecutor` 分层完成。前者从持久化的不可变 API prompt 克隆执行副本，要求工作流已启用且当前规范化映射哈希一致，再以产品节点批准表和实时 `/object_info` 复检节点、输入类型及模型枚举。prompt/negative 只能进入字符串输入，seed/width/height/frames/steps 等数值角色只能进入相应受限数值输入；模型、文件、设备、格式和凭据类输入列入动态注入拒绝表，同一 node/input 不能被两个角色覆盖。LoadImage 节点必须映射为 `sourceImage` 或 `lastFrame`，浏览器只能提交当前项目可见的资源版本 ID，服务端上传后注入受管文件名，绝不接收任意本机路径。

执行器复用现有 `RuntimeManager`、`ComfyClient`、GPU `JobScheduler`、`JobStore`、SSE 和输出交付服务。每次执行生成独立安全前缀，仅从显式 output 映射节点的 history 结果中选择 ComfyUI output/temp 边界内、扩展与 MIME 受支持且不超过 256 MiB 的文件；其他节点产物、目录穿越和任意绝对路径均忽略或拒绝。结果通过 `ProjectStore.createLibraryAsset()` 形成当前项目不可变版本，provenance 固定记录执行版本、workflow/mapping hash、execution ID、输入资源版本与输出节点。取消向 ComfyUI 发送 interrupt，并在所有终态执行空闲停止钩子；相关 Job 尚在 queued/running 时，工作流停用和删除返回 `CUSTOM_WORKFLOW_IN_USE`，避免执行图在途漂移。

空间生命周期服务把“统计”和“删除”分成两条边界。`scan()` 有界遍历已知数据根且不跟随符号链接，模型/节点/最终交付仅统计；项目资产通过 ProjectStore 引用计数与 WorkspaceStore 当前正文/恢复点二次取证，任务输入、中间/派生输出和预览缓存再叠加活动 Job 与最终结果保护。ComfyUI 只把相对路径中含 `AEONQUILL`/`aeonquill` 受管命名前缀的 input/output/temp 文件纳入候选，外部用户或节点产生的文件保持未知、不触碰。自选输出目录只识别应用已知交付文件名，不扫描或删除其他内容。

候选快照只在内存保存私有绝对路径，公开 ID、类别、脱敏标签、字节、年龄、保护原因和快照指纹；默认 15 分钟过期且成功清理后一次性失效。`cleanup()` 要求候选 ID 全部来自同一快照，并精确确认候选数与预计字节；每个文件在删除前重新核对大小/mtime、活动 Job、项目/资源/恢复点引用，变化项跳过而不是强删。项目孤儿复用 ProjectStore 带最终保护回调的 GC；任务中间字段只在文件处理成功后清除。完成、取消或部分失败都由统一 Job/SSE 展示，成功终态包含复扫快照和一致性结果；模型根移除仍必须走运行时反向引用门，生命周期服务不提供模型删除端点。

### 7.2 核心数据

V0.7 项目中心以 `ProjectCatalog` schema v1 管理“项目壳”和模式文档引用，以 `WorkspaceStore` SQLite 保存权威目录和正文。目录只接收精确字段，项目和文档 ID 全局唯一；创建项目只建立一种初始模式文档，项目操作菜单再通过 `addProjectDocument()` 显式加入或打开其他模式。归档不删除内容，回收站记录 `trashedAt` 并由 `purgeExpiredProjects()` 按 15 天确定性清理。目录和正文写入分别携带 base revision，过期 writer、同 revision 内容冲突、跨项目文档移动、模式/正文 ID 不匹配均失败关闭。像素与智能视频正文通过带 `documentId` 的串行队列写入；智能视频外层 schema v2 保存完整 `StoryProject + GenerationPlan + VideoProductionProject`，其中生产项目为 schema v4 并包含连续性图和声音字幕时间线。旧外层 schema v1 与内层 production v1/v2/v3 在读取时确定性迁移，节点审批和事件保留，无法验证资源身份的旧松散图片或音频不会被伪造为已批准。浏览器键和旧 client-state 继续作为恢复镜像与非破坏迁移输入；旧像素/视频单例和 revision>0 的旧均衡 ProjectStore 文档会被包装为项目引用，原数据不删除。

恢复点同时保存项目快照及可选模式正文。普通正文写入按 30 秒节流自动留档，项目菜单允许手工创建与浏览；每一项目/文档作用域最多保留最近 20 份。恢复不会覆盖或删除原恢复点：系统先记录 `before-recovery-restore`，再把快照写为当前目录与正文的新 revision。均衡正文仍使用既有 `ProjectStore` 外置媒体和内容寻址资产，恢复后同步写回该存储，避免出现两套画布资产事实。

双层资源库继续使用同一 `ProjectStore` 数据库和 `assets/<sha256>.<ext>` 内容目录。`library_items` 表示全局或项目条目，`library_versions` 固定内容哈希及父版本，`library_project_refs` 把全局条目的明确版本钉到项目；标签、集合与集合成员关系独立索引。相同内容跨范围、项目和派生只保留一份字节；全局原件不可追加内容版本，项目派生可追加新版本且必须保留来源。资源库版本加入 GC 保护集合，任何库版本仍引用时都不能回收底层内容。

完整项目迁移由 `.aeonquill` 承担，而不是继续扩张旧 `.miaohui`。导出器从 WorkspaceStore 和 ProjectStore 取同一项目的目录、全部已落盘模式正文、恢复快照、均衡资产版本、项目集合/条目、钉住的全局版本及递归来源，再只收集实际被引用的内容哈希。归档是 gzip JSON envelope，顶层 payload、每份正文和每个二进制都有 SHA-256；二进制只能写成规范 `assets/<sha256>.<ext>` 并在恢复前完成 MIME、扩展、字节数、canonical Base64 和内容哈希复核。导入先检查空间并暂存文件，再写 ProjectStore/WorkspaceStore 事务；任一步失败会回滚元数据、移除本次文件并补偿已提交侧。已登记但文件遗失的同哈希资产可由包内可信字节修复，已有字节损坏则拒绝覆盖。`copy` 会重映射项目、正文、恢复点、资源条目/集合/版本引用及正文内部 ID；全局资源仍作为明确版本引用恢复，不把来源链静默丢失。

通用生成 Adapter 不建立第二套媒体库。同步图像/TTS 与异步视频完成后都调用 `ProjectStore.createLibraryAsset()`，写入 provider/model/profile/usage/remoteRequestId provenance 和同一 SHA-256 内容层；参考图只接受已存在的 64 位内容哈希并由服务端读取，不允许浏览器提交本机路径。外部视频 Job 仅保存非秘密请求和项目引用；密钥仍在 `GenerationAdapterService` 内存中，桥接重启会把尚未执行的外部任务标为会话失效。

```ts
type ProjectCatalog = {
  schemaVersion: 1
  revision: number
  projects: WorkspaceProject[]
}

type WorkspaceProject = {
  id: string
  title: string
  initialModeId: 'balanced' | 'pixel' | 'smart-video'
  status: 'active' | 'archived' | 'trashed'
  documents: ProjectModeDocument[]
  createdAt: number
  updatedAt: number
  lastOpenedAt: number
  trashedAt: number | null
}
```

正式画布使用 `CanvasDocument` schema v1。`localStorage` 键已从 `miaohui-canvas:v7` 升级为 `miaohui-canvas:v8`；启动时依次读取 SQLite、v8 与 v7，并把旧 `{ elements, camera }` 或旧 `version: 2` 导出迁移为当前文档。面向用户的导入/导出改用带文档、版本、provenance 和全部二进制的 `.miaohui` 包；JSON 只再用于内部调试。

```ts
type CanvasDocument = {
  schemaVersion: 1
  id: string
  title: string
  revision: number
  createdAt: number
  updatedAt: number
  elements: CanvasElement[]
  camera: Camera
}

type CanvasCommand = {
  schemaVersion: 1
  id: string
  actor: 'user' | 'tool' | 'agent' | 'system'
  type: 'elements.add' | 'elements.patch' | 'elements.remove' |
    'elements.replace' | 'camera.set' | 'document.reset'
  baseRevision: number
  payload: Record<string, unknown>
}
```

事务在同一 `baseRevision` 上原子执行，成功只增加一次 revision；过期命令/草稿、未知字段、重复 ID、悬空连接线、非法尺寸与超限数组会整体拒绝。Agent 当前只可调用 add/patch/remove，且通用 patch 只能修改视觉与几何白名单，不能写入 `src`、`jobId`、资产或处理来源字段。

`ProjectStore` 将画布逻辑资产 ID 与内容哈希分开：`CanvasElement.assetId` 表示逻辑资产，`assetVersion` 是单调版本号，`assetVersionId` 指向 SQLite `asset_versions`；实际二进制以 SHA-256 为文件名。派生节点可通过 `sourceElementId` 建立跨逻辑资产父版本，来源同时记录 Job、处理操作和原始引用。项目更新先校验 revision/引用/版本冲突，再以临时文件 + SQLite `BEGIN IMMEDIATE` 提交；失败不会留下正式项目记录或孤立暂存文件。

当前实现使用 Node.js 22 内置 `node:sqlite` 并启用 WAL、`synchronous=FULL` 与外键约束。它适合当前单机基线，但仍属于需要固定运行时验证的接口：桌面封装必须捆绑并锁定已回归的 Node 版本，升级前执行项目重开、100 轮保存、导入导出和故障注入测试；云端多租户阶段再评估独立数据库驱动或服务。

`CanvasElement` 继续承载通用几何和内容字段；视频新增：

```ts
type CanvasElement = {
  // 通用 id / kind / name / transform / appearance ...
  videoSrc?: string
  posterSrc?: string
  jobId?: string
  jobStatus?: ProcessingJobStatus
  jobPhase?: VideoJobPhase
  jobProgress?: number
  jobDetail?: string
  jobError?: ProcessingJobError
}
```

`ProcessingJob` 同时容纳本地图片 Job 与视频 Job。图片 `output` 保存 `width`、`height`、`mimeType`、`bytes`、`provider`；视频 `output` 保存 Comfy 文件位置摘要，两者用 `isImageJobOutput()` 区分。`scheduling` 固定记录资源类别、优先级、幂等键、尝试/上限、超时和排队/开始/结束时间；`costEvents` 当前记录金额为 0、不可计费的 CPU/GPU 估算与实际毫秒，为未来云 API 费用事件保留同一结构。`outputVersion` 记录最终 SHA-256、逻辑资产、版本 ID 和 provenance；`executionIdentity` 在任务创建时固化产品版、功能轨、构建 SHA、运行时包 ID、注册表版本和身份哈希，后续重试不得被当前进程身份覆盖。公开 API 会移除 `inputPath`、`outputPath`、`temporaryOutputPath`、`lastFramePath` 和运行中的进程控制对象。

`subscribeVideoJobs()` 是图片与视频共用的受管 SSE 客户端。桥接断线时它关闭浏览器原生连接，清除旧会话缓存，通过 `/api/health` 获取重启后轮换的 HttpOnly 会话，再按 250 ms、500 ms、1 s、2 s、4 s 上限退避重建；新连接首先接收 `jobs.snapshot`，因此即使短任务在断线窗口内完成，画布与任务面板也会追平，而不依赖整页刷新。组件卸载会同时取消定时器和连接；均衡工作台在初次桥接暂不可用时也保留该重连循环。

## 8. 页面与响应式

当前使用无需服务端重写的轻量 Hash 导航：`/` 是项目中心，`#/balanced?project=<workspace-id>`、`#/pixel?project=<workspace-id>`、`#/smart-video?project=<workspace-id>` 从同一项目进入三种工作台；项目内部再解析对应的稳定 `documentId` 作为模式正文存储键。项目行的操作菜单显示“打开/新建均衡、像素、智能视频”和“恢复点”，缺少目标模式文档时先严格建档再导航。恢复点对话框可刷新、手工留档和确认恢复；目录写入完成后才允许创建快照。旧 `?project=<legacy-document-id>` 深链仍保留兼容门；旧单例通过保留原数据的包装项目进入新目录。浏览器前进/后退、刷新与各模式返回按钮保持一致；未知或畸形 Hash 会安全规范化回项目中心。像素/智能视频路由在 SQLite 正文读取完成前保持加载门，禁止先挂载旧内存状态再重新挂载。

### 10.4 旗舰广告预览、渲染与质检

广告工程位于 `videos/aeonquill-flagship-ad/`，独立于产品应用、ComfyUI 和 H3 生成任务。预览、检查和渲染必须在该目录执行，并把 npm 缓存与临时文件留在 D 盘工程目录。

```powershell
cd videos/aeonquill-flagship-ad
$env:npm_config_cache = "$PWD/.runtime/npm-cache"
$env:TEMP = "$PWD/.runtime/temp"
$env:TMP = "$PWD/.runtime/temp"
npx --yes hyperframes@0.8.16 check --at-transitions --samples 15
npx --yes hyperframes@0.8.16 preview --background --no-open --port 3017
```

正常结果是 `check` 报告 0 error，Studio 在 `http://127.0.0.1:3017/#project/aeonquill-flagship-ad` 返回 HTTP 200。`--no-open` 必须保留，避免自动抢占用户正在使用的浏览器；审片结束后用 `npx --yes hyperframes@0.8.16 preview --stop --port 3017` 关闭后台预览。

独立质检器可以在不渲染正式广告的情况下复测：

```powershell
npm run test:delivery-validator
./scripts/validate-final-video.ps1 -InputPath <待验收 MP4> -ReportPath <QA JSON>
```

烟测会在工程 `.runtime/validator-smoke/` 生成一个 21 秒、1280×720、30fps、H.264/AAC 的运动样本。第一条路径必须写出 `ok: true` 的报告；第二条故意把最低时长提升到 22 秒，必须抛错且禁止留下报告。质检器对真实交付固定检查单一 H.264 视频流、单一 AAC 48 kHz 双声道音轨、20—27 秒、1280×720、30fps、中段 seek 解码、最长黑帧段不超过 0.5 秒、最长静帧段不超过 3 秒、综合响度 -18 至 -11 LUFS、真峰值不高于 -1 dBTP 和 SHA-256。

最终渲染只允许在用户明确批准后执行：

```powershell
./scripts/render-final-720p.ps1 -Approved
```

脚本先重跑高密度 `check`，再以 HyperFrames high/CRF 12 渲染 1920×1080、30fps、SDR 母版；交付转码使用 Lanczos、x264 slow/CRF 16、AAC 192 kbps，并对音频执行目标 -14 LUFS、-1.5 dBTP 的 EBU R128 双遍规范化，再复用上述独立质检器写入 `renders/qa/`。Windows PowerShell 必须显式调用 `npx.cmd`，QA JSON 必须以显式 UTF-8 读取，避免严格模式 shim 异常或中文路径损坏。不带 `-Approved` 会在任何渲染、目录创建和媒体写入前失败关闭；`renders/` 与临时缓存是本机产物，不进入 Git。

2026-08-27 最终实例：母版 `AEONQUILL-flagship-ad-20260827-151916-master-1080p.mp4` 为 21,384,571 bytes、SHA-256 `0f2ba3704e3c935255d611ece9986b16b407379e6a7166ad187dca9138956f91`；交付片 `AEONQUILL-flagship-ad-20260827-151916-720p.mp4` 为 5,310,124 bytes、26.1 秒、SHA-256 `ee073da7e089a151005eb06cfe75da61b511b173a4f0da4889fedaaf8b5fbc0f`。机器报告和五点抽帧联系表位于同项目 `renders/qa/`，验证 1280×720、30fps、H.264/AAC 48 kHz 双声道、-14.37 LUFS、-1.40 dBTP、无阻断黑帧/静帧且目检通过。

## 11. 扩展指南

### 11.1 新增画布元件

1. 在 `ElementKind`、`CanvasElement`、`canvasCore.mjs` 的元素/字段白名单登记类型与字段。
2. 在 `CanvasElementView` 增加渲染，在 `Inspector.kindIcons` 登记图标。
3. 如可创建，接入 `ToolId`、`ToolRail` 和 `App.createAt()`。
4. 如需 Agent 操作，单独审查其可创建类型或可修改字段；不要默认开放媒体、资产与任务字段。
5. 验证选择、移动、缩放、复制、删除、撤销、本地迁移和非法命令拒绝。

### 11.2 新增视频参数或工作流版本

1. 先在 `validateVideoRequest()` 建立类型、范围和白名单。
2. 场景、精度档、显存或质量预设只登记到 `video-workflow-registry.mjs`；提示词字段变化必须升级 prompt schema/agent 版本。
3. 在 `workflow-builder.mjs` 映射到固定节点；不要接受前端节点 ID、模型路径或任意图。
4. 模板变化时保持节点阶段映射一致，或同步修改 `stageForNode()`。
5. 更新运行时必需节点/模型检查；升级 cu129/cu130 或量化格式必须单独完成画质、显存和发行回归。
6. 运行 `npm run validate:workflows`、提示词/注册表契约，再做一条真实 T2V 和一条真实 I2V。
7. 同步[本地 H3 视频工作流](01-子文档/11-本地H3视频工作流.md)。

### 11.3 接入第三方 API 或 Agent

只能新增服务端 Adapter 和受控工具，不得从 React 组件直接调用带密钥的模型。实施前必须在规划中定义资产版本、费用、内容审核、超时、幂等和重试语义。Agent 只能生成经 `compileCanvasToolInvocation()` 校验的工具调用，并先用 `createCanvasDraft()` 形成预览；只有当前 revision 未变化时才能 `commitCanvasDraft()`。Agent 不能调用 `elements.replace`/`camera.set`、写任意画布 JSON 或提交任意 Comfy 工作流。

### 11.4 新增本地图像处理器

1. 在 `src/types.ts` 的 `ImageOperationId`、`server/image-processor.mjs` 的能力清单和 `imageOperationLabels` 同时登记稳定操作 ID。
2. 在 `validateImageRequest()` 只接受明确参数键、枚举和值域；按输入 20MB/40MP、输出 64MP 的现有边界拒绝超限任务。
3. 处理器必须把输出写到调用方指定的 `.runtime/assets` 路径，监听 `AbortSignal` 并终止完整子进程树；错误消息不得暴露本机绝对路径。
4. 使用 GPU 的操作加入 `gpuImageOperations`；所有正式处理器必须由 `JobScheduler` 分配资源并使用其 `AbortSignal`，不得从路由直接启动执行函数。CPU/FFmpeg 操作受 CPU 容量限制，GPU 与 H3 共用容量 1。
5. 在 `ImageLab` 登记参数、能力解释和可用/降级行为；如果没有真实处理器，正式按钮必须禁用，不得返回假结果。
6. 扩展 `server/validate-image-tools.mjs` 或增加最小真实烟测；验证能力探测、成功、非法参数、取消、失败建议、资产下载和画布派生回填。
7. 发布前分别登记代码许可证、模型权重许可证、来源、校验值和再分发条件；运行期下载不得发生在首个用户任务中。

### 11.5 新增 ComfyUI 语义图片工作流

1. 先在 `server/semantic-workflow-registry.mjs` 分配稳定 ID 与独立语义版本，登记扩展、模型、节点、输入、输出、显存和超时；`implemented: false` 的能力只能展示 `template-pending`，不能进入执行路由。
2. 前端只能提交产品参数，不能提交 ComfyUI 节点图、节点 ID 或本机路径；请求必须用精确键白名单、数量和值域校验后再持久化。
3. ComfyUI 节点图型工作流必须通过既有节点白名单；扩展 HTTP API 适配器必须固定端点、模型名、受管上传引用和响应类型，并支持 `AbortSignal`。
4. 正式结果必须保留原图，输出新的不可变图片版本；蒙版、深度或控制图如后续会参与编辑，也必须使用独立受管资产而不是只留在临时内存。
5. GPU 工作流进入 `JobScheduler` 的共享 GPU 容量 1；启动、进度、错误、取消、重试和空闲关闭继续复用统一 Job 语义。
6. 至少增加离线注册表/非法参数契约和一条真实本机最小烟测；模型许可与固定素材质量门禁完成前只能标为 preview/experimental，不得宣传为生产级编辑质量。

| 最近项目为空、深链无法恢复或指向错误模式 | 检查 Hash 的 `mode`/`project`、主页状态提示、`/api/projects/current`、像素草稿键与当前标签页视频摘要 | 先使用页面“重试”；确认项目确实存在后从最近项目重新进入。未知/畸形 Hash 会回主页，缺失项目必须显式新建，不得手改模式私有状态或伪造最近项目 |
| 画布图片破图或回退原图 | 检查图片响应的 `x-miaohui-asset-tier`、`?variant=` 和 FFmpeg 可用性 | 运行 `npm run validate:api`；派生缓存可删除后重建，但不得删除 `.runtime/projects/assets` 原始内容资产 |
| 桌面窗口未出现 | 查看对应 `.runtime/qa/desktop-*-final.json` 的 bridge/renderer timeline | 先运行 sidecar 或壳专项验证；桥接健康前窗口不会显示，禁止绕过健康检查直接加载页面 |
| 一次启动出现多个 AEONQUILL 窗口 | 检查产品版本是否低于 0.7.1，并查看 `.runtime/qa/desktop-single-instance-*-final.json` | 使用 0.7.1 及以上版本；运行 `npm run validate:desktop:single-instance:release`，不得以延迟显示或隐藏重复窗口替代系统级单实例锁 |
| Tauri 构建找不到 Rust/MSVC/NSIS | 检查 `.runtime/toolchains/rust`、VS 2022 C++ 工具和 Tauri 本地缓存 | 使用 `scripts/tauri-toolchain.ps1 check`，不要临时改全局 PATH 或跳过下载哈希 |
| 卸载后项目是否保留不明确 | `REL-003` 自动验收已证明正常 data 与旧 runtime 回退数据均在卸载后保留 | 本阶段卸载只删除程序、注册项和快捷方式；清缓存/模型/项目必须另做显式可预览操作，进入 `REL-002` 前不得改变此原则 |

统一启动器管理的 Comfy 日志在 `.runtime/comfyui.log`；Comfy 自己也可能写入其 `user/comfyui.log`。排错时优先查看任务错误的节点 ID、类型和 Prompt ID，再关联日志时间。
