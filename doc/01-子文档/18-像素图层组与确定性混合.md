# 光阴砚 AEONQUILL — 像素图层组与确定性合成

> 该文档隶属于[01-开发者文档](../01-开发者文档.md)，用于说明像素图层组、混合、合成与迁移规则。
> 本文回答：图层组、显隐、锁定、透明度和混合模式如何工作，为什么编辑预览与所有导出必须复用同一 RGBA 合成器。

**最后一次更新时间**：2026-09-04

**更新者**：像素模式组、渲染责任域、文档专项组

---

## 1. 当前能力

| 对象 | 可编辑项 |
| --- | --- |
| 图层组 | 新建、删除、重命名、显示/隐藏、锁定/解锁 |
| 图层 | 新建、删除、重命名、显示/隐藏、锁定、透明度、所属组、混合模式、排序 |
| Cel | 每帧每图层独立像素数组 |
| 渲染 | normal、multiply、screen、add |
| 预览 | 调色板循环、洋葱皮、游戏辅助线 |
| 导出 | 当前帧、Sprite、动画片段、游戏包共同复用合成器 |

上限：32 个图层组、64 个图层。

---

## 2. 数据结构

```ts
type PixelLayerGroup = {
  id: string
  name: string
  visible: boolean
  locked: boolean
}

type PixelLayer = {
  id: string
  name: string
  visible: boolean
  locked: boolean
  opacity: number
  groupId: string | null
  blendMode: 'normal' | 'multiply' | 'screen' | 'add'
}
```

每帧的像素不存放在 Layer 中，而在：

```text
frame.cels[layer.id] = Array<colorId | null>
```

图层顺序就是 `document.layers` 数组顺序；合成从前到后遍历该数组。

---

## 3. 有效显隐与锁定

有效可见：

```text
layer.visible
AND (layer.groupId is null OR group.visible)
AND layer.opacity > 0
```

有效可写：

```text
NOT layer.locked
AND (layer.groupId is null OR NOT group.locked)
AND (layer.groupId is null OR group.visible)
```

`assertWritableLayer()` 在执行像素命令时统一检查。隐藏组中的图层不能被编辑，避免用户在不可见内容上误画。

删除图层组不会静默删除所属图层；命令必须显式处理成员关系并可逆恢复。不存在的 groupId 会在完整文档校验时拒绝。

## 4. 合成顺序

`renderPixelFrameRgba()` 位于 `src/lib/pixel/pixelCore.mjs`：

```text
校验 PixelDocument
→ 解析调色板循环映射
→ 建立 colorId → RGBA
→ 创建透明输出缓冲
→ 按 layers 顺序遍历
→ 跳过无效不可见或 opacity=0 图层
→ 逐像素执行 blendPixel
→ 返回 Uint8ClampedArray
```

可选参数：

- `includeHiddenLayers`：仅用于受控调试/导出场景。
- `paletteCycleElapsedMs`：预览某个循环时间点。

组件不得自行用 CSS `mix-blend-mode` 作为正式结果；浏览器实现和导出会因此出现不同 Alpha 行为。

---

## 5. 混合模式

每个颜色通道先计算 blend channel：

| 模式 | 通道计算 |
| --- | --- |
| normal | `source` |
| multiply | `source × destination / 255` |
| screen | `source + destination - source × destination / 255` |
| add | `min(255, source + destination)` |

随后使用源 Alpha、图层 opacity 和目标 Alpha 做预乘 Alpha 组合：

```text
sourceAlpha = source.a / 255 × layer.opacity
outputAlpha = sourceAlpha + destinationAlpha × (1 - sourceAlpha)
```

RGB 结果同时考虑源覆盖透明区域、源/目标重叠区和仅目标区，再除以 outputAlpha。最终每通道四舍五入到 0—255。

---

## 6. 调色板循环与图层合成

Cel 永远保存基础 colorId。渲染某一时刻时：

```text
elapsedMs
→ resolvePixelPaletteCycleMap
→ 基础 colorId 映射到当前 colorId
→ 解析当前 RGBA
→ 进入图层合成
```

因此：

- 循环预览不会污染文档。
- 所有使用同一 elapsedMs 的输出确定一致。
- 颜色替换必须复核循环引用。
- 同一颜色不能同时属于两个循环。

---

## 7. 洋葱皮与辅助线

洋葱皮不是 PixelDocument 图层：

1. 先对相邻帧调用正式 RGBA 合成。
2. 在 UI 预览层以距离衰减透明度着色。
3. 当前帧仍使用正常合成。
4. 导出 Sprite 时不包含洋葱皮。

锚点、碰撞区、选区边框、网格和 Terrain 提示也都是 UI overlay，不能写入 RGBA 成品。

## 8. 图层命令

| 命令 | 作用 |
| --- | --- |
| `groups.add/remove/restore/patch` | 图层组生命周期 |
| `layers.add/remove/restore/patch` | 图层生命周期和属性 |
| `layers.reorder` | 改变合成顺序 |
| `layers.select` | 改变 activeLayerId |
| `cels.copy/restore` | 跨帧复制某图层内容 |
| `pixels.*` | 修改指定 frame/layer 的 Cel |

每个命令包含 baseRevision。执行后完整验证所有 frame 的 cels 都与当前 layers 一一对应，数组长度均为 width×height。

---

## 9. 删除与迁移规则

删除图层时必须同步所有帧的对应 Cel，并在 inverse 中保留图层位置与每帧像素，以便一次撤销完整恢复。

schema v2 → v3 引入 groupId 与 blendMode；旧图层迁移为：

```text
groupId = null
blendMode = normal
```

当前读取链继续支持 v0—v6 显式迁移到 v7。未知未来 schema 失败关闭，不能默认当作 normal 读取。

## 10. 新增混合模式

1. 将 ID 加入 `PIXEL_BLEND_MODES`。
2. 在 `blendChannel()` 实现 0—255 确定性公式。
3. 更新严格验证器与 `.d.mts` 联合类型。
4. 更新右侧 UI 标签。
5. 增加透明源、透明目标、半透明、边界值和多层顺序测试。
6. 复核帧 PNG、Sprite、动画片段、游戏包和离线预览。
7. 记录与参考实现的舍入规则；不得依赖 GPU/浏览器厂商差异。

---

## 11. 新增图层属性

新增持久字段必须：

1. 提升 PixelDocument schema。
2. 增加旧版默认迁移。
3. 修改精确字段集合与类型声明。
4. 更新 `layers.patch` 白名单及 inverse。
5. 修改合成器或明确字段只影响 UI。
6. 更新项目序列化、metadata 与所有导出。
7. 加入非法值、保存重开和撤销测试。

若属性只用于选中/悬停，保持组件瞬态 state，不进入正文。

## 13. 当前限制

- 组不支持嵌套。
- 混合模式只有四种。
- 没有调整图层、蒙版图层或滤镜栈。
- 组本身没有 opacity/blend；只有显隐和锁定。
- 合成由 CPU 确定性执行，超大多帧文档批量导出仍受内存限制。
