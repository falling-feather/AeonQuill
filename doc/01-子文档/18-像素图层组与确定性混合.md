## 1. 能力边界

本检查点继续坚持一个像素工程只有一份权威 `PixelDocument`。图层组不是 DOM 折叠状态，混合模式也不是只在浏览器预览中生效的 CSS；二者均写入严格文档、经过统一命令修改，并由同一个 RGBA 合成器供画布预览、当前帧 PNG、Sprite Sheet 和游戏包使用。

当前提供：

- 最多 32 个非嵌套图层组；
- 图层归组或回到“不分组”；
- 组级命名、显隐、锁定和删除；
- `normal`、`multiply`、`screen`、`add` 四种确定性图层混合；
- 组/图层变更的单步撤销与重做；
- schema v0/v1/v2 到 v3 的显式迁移；
- Sprite metadata 与游戏 manifest 中完整保留图层组和混合事实。

本检查点不提供嵌套组、组级不透明度、剪贴蒙版、调整图层、逐像素混合空间选择或 PSD 往返。Tileset 规则、锚点/碰撞区可视编辑在后续 V0.7.42 完成；调色板循环、Worker 化和三引擎导入器继续作为独立任务。

## 2. PixelDocument schema v3

文档新增 `layerGroups`，每个图层新增 `groupId` 与 `blendMode`：

```ts
type PixelLayerGroup = {
  id: string
  name: string
  visible: boolean
  locked: boolean
}

type PixelLayer = {
  id: string
  name: string
  visible: boolean
  locked: boolean
  opacity: number
  groupId: string | null
  blendMode: 'normal' | 'multiply' | 'screen' | 'add'
}
```

约束如下：

1. `layerGroups` 必须是 0—32 项的唯一 ID 列表；
2. `groupId` 只能为 `null` 或引用现存组；
3. `blendMode` 必须来自固定枚举，不能把浏览器任意 `globalCompositeOperation` 写入项目；
4. 组隐藏时，其图层不参与正常预览/导出，也拒绝新的像素或跨帧写入；
5. 组锁定时，其图层拒绝像素、区域、清理和跨帧 Cel 写入；
6. 图层自身的显隐、锁定与不透明度继续有效。

图层组暂不嵌套，避免循环引用、祖先状态传播和不确定的隔离合成语义。组删除只移除组织对象并把关联图层原子改为不分组，不删除任何 Cel；撤销会恢复原组位置和全部归属。

## 3. 可逆命令

命令信封仍为 schema v1，新增四种类型：

| 命令 | 输入 | 逆命令 |
| --- | --- | --- |
| `groups.add` | 严格组对象与可选索引 | `groups.remove` |
| `groups.remove` | `groupId` | 内部 `groups.restore`，含原索引和成员图层 ID |
| `groups.restore` | 组、索引、成员图层 ID | `groups.remove` |
| `groups.patch` | 名称/显隐/锁定的非空补丁 | 同类型旧值补丁 |

`layers.patch` 同步扩展 `groupId` 与 `blendMode`，仍先把完整候选图层放回当前文档上下文校验，再产生逆补丁。未知组、未知混合模式、重复组 ID、超过组上限和用户直接调用内部恢复命令均失败关闭。

## 4. 确定性 RGBA 合成

`renderPixelFrameRgba()` 是唯一合成真值。它按文档图层顺序从底到顶执行，每层先应用调色板 Alpha 与图层不透明度，再使用固定非预乘 Alpha 公式合成。混合函数分别为：

```text
normal(C_s, C_b)   = C_s
multiply(C_s, C_b) = C_s × C_b
screen(C_s, C_b)   = C_s + C_b - C_s × C_b
add(C_s, C_b)      = min(1, C_s + C_b)
```

实际通道在 0—255 空间计算后只在最终输出处四舍五入。透明底色、半透明调色板色和图层不透明度都走同一 Alpha 路径，不依赖不同浏览器对 Canvas 混合模式的实现差异。

工作台先调用该函数得到 RGBA，再绘制到编辑 Canvas；Sprite Sheet 对每帧调用同一函数。因此预览、PNG 和游戏 Atlas 不会出现“界面滤色、导出却是正常覆盖”的双重事实。

## 5. 迁移与兼容

迁移路径固定为：

- schema v3：严格校验后复制；
- schema v2：先按旧文档字段边界拒绝额外字段，再补入空 `layerGroups`，所有旧图层补 `groupId: null` 与 `blendMode: normal`；
- schema v1：在 v2 迁移内容之外补入空动画标签；
- schema v0：继续使用单层调色板索引迁移器，由 `createPixelDocument()` 生成完整 v3 图层；
- 缺失版本、未知版本、未知组引用或非法混合值：拒绝导入。

历史浏览器草稿键 `aeonquill:pixel-document:v1` 只是存储兼容名称，不等于正文 schema；读取后同样进入迁移器。迁移不覆盖用户原文件。

## 6. UI 与导出

右侧图层检查器新增“图层组”区：

- 新建组后可原位改名；
- 每组显示成员数量，可切换显隐、锁定或删除；
- 当前图层可从选择框切换组，并选择四种混合模式；
- 新建图层默认继承当前所选图层的组，但混合模式从 `normal` 开始；
- 组锁定或隐藏时，画布手势、选区变换和本地智能清理给出明确阻断信息。

`createSpriteSheetMetadata()` 与 `createPixelGameManifest()` 升级为 schema v3，新增 `layerGroups` 和 `layers` 快照；Sprite 像素仍来自同一合成器。项目 JSON、metadata、manifest、Tiled 文件和离线预览页不包含本机路径、Data URL 或外部网络引用。

## 7. 验证口径

自动契约覆盖：

- schema v0/v1/v2→v3 迁移与 v3 无损往返；
- 组新增、删除、恢复、归组、显隐、锁定和完整逆命令；
- 未知组与未批准混合模式失败关闭；
- 固定 1×1 RGBA 向量对 normal/multiply/screen/add 的精确输出；
- 隐藏组不渲染，隐藏或锁定组拒绝图层写入；
- Sprite metadata 与游戏 manifest 保留组、图层和混合模式。

P7 在隔离像素项目中补齐八方向后建立“角色光影”组，把当前图层归组并设为滤色，执行组锁定/解锁、动画片段、跨帧复制和六文件下载；随后核对项目与 manifest schema v3、组 ID、混合模式、动画序列和逐帧时长。页面刷新后再次验证组名、混合选择与 SQLite 正文恢复，并在 1440×900 与 390×844 检查可达性和页面级横向溢出。

本检查点不启动 ComfyUI/H3，不下载模型，不改写正式桌面、正式项目或用户 `output`。
