## 2. 启动流程

Tauri 不在配置中静态创建业务窗口。Rust 启动顺序为：

```text
进程启动
→ single-instance 插件注册
→ 解析便携布局和 UserData
→ 预留随机回环端口
→ 构造安全环境变量
→ 隐藏启动 aeonquill-bridge sidecar
→ 轮询 /api/health
→ 健康且构建身份一致
→ 创建主窗口并导航到随机回环地址
```

关键文件：

| 职责 | 文件 |
| --- | --- |
| Tauri 生命周期 | `desktop/tauri/src-tauri/src/lib.rs` |
| Tauri 配置 | `desktop/tauri/src-tauri/tauri.conf.json` |
| 便携布局协议 | `desktop/shared/portable-layout.mjs` |
| 桥接契约 | `desktop/shared/bridge-contract.mjs` |
| 产品身份 | `desktop/release/product-identity.mjs` |
| 发行元数据 | `desktop/release/release-meta.mjs` |
| sidecar 构建 | `scripts/build-node-sidecar.mjs` |
| sidecar 验证 | `scripts/validate-node-sidecar.mjs` |

## 3. 为什么不会出现终端窗口

正式 Tauri 由 sidecar API 启动桥接，不调用可见的 `cmd.exe`、PowerShell 或 Windows Terminal。Windows 子进程创建必须使用隐藏窗口语义；运行时进一步启动 Python/ComfyUI 时同样使用隐藏窗口选项。

必须避免：

- 用 `.bat` 或 `.ps1` 作为桌面快捷方式目标。
- `Start-Process` 未指定隐藏窗口。
- 每次前端请求都重新启动一个桥接。
- Tauri 主进程与启动器各自启动一份 sidecar。
- 把开发命令 `npm run app` 当作发行启动器。

单实例插件在第二次启动时聚焦已有窗口并退出新实例，因此连续点击快捷方式不应产生多份窗口或终端。

## 4. 随机端口与本地安全

Tauri 先绑定 `127.0.0.1:0` 获取空闲端口，再把端口传给 sidecar。桥接只监听回环地址。

sidecar 环境遵循最小传递：

- 清理父进程中无关环境。
- 只传允许的 PATH、数据目录、输出目录、端口、构建身份等。
- 不把用户密钥写入命令行。
- `/api/health` 完成初始握手后使用随机 HttpOnly 会话。
- 前端后续 API 仍校验 Host、Origin/Fetch Metadata。

固定 8787 只用于源码开发态；桌面态不能假设该端口。

## 5. 便携目录

存在 `App/aeonquill-layout.json` 且内容合法时启用 sibling-user-data：

```text
安装根/
  App/
    aeonquill-desktop.exe
    aeonquill-bridge.exe
    aeonquill-layout.json
    其他应用资源
  UserData/
    data/
    runtime/
    cache/
    logs/
    config/local.json
    EBWebView/
  output/
```

边界：

- 更新或卸载 `App/` 不得删除 `UserData/` 和 `output/`。
- 默认输出是安装根的 `output/`。
- 用户自选输出目录优先，且必须是现存、可写的绝对目录。
- 项目正式资产仍保存在 UserData；output 是交付副本。
- 发行包不得包含开发机项目、数据库、个人素材、生成结果、日志、缓存或密钥。

普通当前用户安装在平台数据目录建立 UserData；其默认 output 位于应用数据区，可在设置中修改。

## 6. 退出与进程所有权

主窗口退出时：

1. 请求 sidecar 优雅关闭。
2. 等待子进程退出。
3. 超时后只强制终止当前 Tauri 持有句柄的 sidecar。
4. 等待随机端口关闭。
5. sidecar 再按所有权停止自己启动的 ComfyUI。
6. 外部独立启动的 ComfyUI 不被终止。

Tauri QA 报告记录 bridge PID、端口、启动时间线、renderer probe 与 shutdown 结果；报告只能写在隔离运行目录。

## 7. 构建身份

统一身份来自 `desktop/release/product-identity.mjs`：

```text
productSemver
functionalTrack
sourceCommit
buildIdentityVersion
runtimeRegistryVersion
runtimePackageId
identitySha256
```

sidecar 封包前要求 clean HEAD，并把只读身份资源打入可执行快照。桌面传入的环境身份、sidecar 内嵌身份和 `/api/health` 必须一致；缺失、损坏或提交不一致时拒绝启动。

这样可以防止“安装器 manifest 看似最新，但实际 sidecar 来自旧提交”。

## 8. 构建命令

开发调试：

```powershell
npm run build:desktop:sidecar
npm run build:desktop:tauri:debug
```

主要验证：

```powershell
npm run validate:desktop:sidecar
npm run validate:desktop:tauri
npm run validate:desktop:single-instance
npm run validate:desktop:tauri:installer
npm run validate:desktop:release-manifest
npm run validate:desktop:release
```

Electron 后备：

```powershell
npm run desktop:electron
npm run validate:desktop:electron
```

完整发行脚本还负责 WebView2 离线输入、PE 签名顺序、manifest 哈希和 NSIS 组装。不要手工复制构建目录冒充发行包。

## 9. 应用框架包与能力包

两层分发：

| 层 | 内容 | 更新方式 |
| --- | --- | --- |
| 应用框架 | UI、sidecar、固定工作流模板、工作流中心 | 安装器/应用更新 |
| 能力包 | ComfyUI、节点、模型、图像处理器 | 用户在工作流中心按需安装 |

能力包必须声明：

- 固定来源。
- 目标相对目录。
- 字节数与 SHA-256。
- 许可文本和磁盘需求。
- 最低显存、系统内存和运行时版本。
- 安装、启用、禁用与失败隔离状态。

自定义 ComfyUI JSON 不是能力包下载；它只导入受控 API prompt，并受大小、节点数、节点类型、路径和输出映射校验。

## 10. 应用图标与品牌

Tauri 图标资源位于 `desktop/tauri/src-tauri/icons/`，窗口/安装器显示名由 Tauri 配置与 `release-meta.mjs` 共同决定。

更换图标时：

1. 从同一正方形母图生成 Windows 要求的 ICO/PNG 尺寸。
2. 更新 Tauri 资源，不修改用户数据目录。
3. 清理构建缓存后重新构建。
4. 验证 EXE、窗口、任务栏、安装器和快捷方式图标。
5. 不通过手工改快捷方式图标掩盖旧二进制。

## 11. 常见问题

| 现象 | 检查点 |
| --- | --- |
| 启动出现多个窗口 | 单实例插件、快捷方式目标、是否还在运行旧启动器 |
| 弹出终端 | 是否经过正式 Tauri sidecar API；子进程是否隐藏 |
| 页面空白 | sidecar 健康、随机端口、WebView2、构建身份 |
| 找不到工作流 | UserData 的 local.json、运行时根和 extra model paths |
| 输出仍在旧目录 | 设置值是否可写；默认 output 是否来自便携布局 |
| 退出后 8188 仍在 | ComfyUI 是否外部进程；应用只停止 owned 进程 |
| 更新后项目消失 | 是否错误覆盖/迁移 UserData；App 与数据必须分离 |
| 发行包巨大 | 是否误把模型、运行时缓存或用户数据放入 App |

## 12. 发布前最低验证

1. clean HEAD 构建。
2. 主程序和 sidecar 身份一致。
3. 首次冷启动只产生一个主窗口、无终端。
4. 连续四次启动只保留一个 desktop 与一个 bridge。
5. 退出后 bridge 端口关闭，owned ComfyUI 被回收。
6. 现有 `UserData/config/local.json`、项目 SQLite 和 output 摘要不变。
7. 安装包不包含 `.runtime`、UserData、output、模型、PFX 或 API Key。
8. 无模型机器仍能打开项目中心、均衡画布和像素模式，并诚实显示视频依赖缺失。
9. 默认输出与用户自选输出均通过真实写入测试。
10. `npm run validate:desktop:release` 通过。

## 13. 当前限制

- 公开商业发行前仍需完成完整第三方许可/SBOM 审核；该项当前不作为开发任务门，但风险事实保留。
- WebView2、Windows 版本和 NVIDIA 驱动的干净机矩阵仍需持续扩大。
- Electron 只作后备，不保证与 Tauri 相同的安装体验。
- 主安装器是工作框架，不是把所有模型和 Python 一次封入的巨型离线包。
- 签名字段和文件完整性不能替代公共 CA 信任；当前文档不把二者混称。
