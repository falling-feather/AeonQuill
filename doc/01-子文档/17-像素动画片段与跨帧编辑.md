## 1. 用户入口与布局

从项目中心创建或打开“像素模式”。工作台入口为 `src/modes/pixel/PixelModeWorkbench.tsx`。

主要区域：

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 项目名、revision、Agent、撤销/重做、打开项目、导出 |
| 工具栏 | 绘图工具、洋葱皮、动画播放、状态 |
| 左侧 | PNG/WebP 转像素、调色板与循环 |
| 中央 | 像素画布、选区和游戏辅助线 |
| 时间线 | 帧、动画片段、动画事件 |
| 右侧 | 图层组、图层、逐帧游戏数据、Terrain |

核心编辑和导出不依赖 ComfyUI，可离线使用。

## 2. 绘图工具与快捷键

| 工具 | 快捷键 | 行为 |
| --- | --- | --- |
| 铅笔 | `B` | 使用当前颜色绘制 |
| 橡皮 | `E` | 将像素设为空 |
| 填充 | `G` | 对连续同值区域 flood fill |
| 吸管 | `I` | 读取像素颜色 |
| 直线 | `L` | Bresenham 风格整数栅格线 |
| 矩形 | `R` | 栅格矩形 |
| 选区 | `M` | 建立整数矩形选区 |
| 取消选区 | `Esc` | 清除选区和拖动草稿 |
| 清空选区 | `Delete` / `Backspace` | 将选区像素设为空 |
| 撤销 | `Ctrl/Meta + Z` | 应用逆命令 |
| 重做 | `Ctrl/Meta + Shift + Z` | 重新应用命令 |

画笔尺寸 1—4。水平/垂直镜像在生成笔触像素集合时展开，并在提交前去重、裁剪到文档边界。

底层算法位于 `src/lib/pixel/pixelTools.mjs`：

- `normalizePixelRect`
- `rasterPixelLine`
- `rasterPixelRectangle`
- `expandPixelBrush`
- `floodFillPixels`

## 3. 选区与剪贴板

| 操作 | 输入 | 结果 |
| --- | --- | --- |
| 移动 | 方向键 | 原位置清空，目标位置写入 |
| 复制移动 | Alt + 方向键 | 保留原位置并写入目标 |
| 复制 | Ctrl/Meta + C | 写会话剪贴板 |
| 剪切 | Ctrl/Meta + X | 写剪贴板并清空原区域 |
| 粘贴 | Ctrl/Meta + V | 写入目标选区 |
| 水平/垂直翻转 | 选区按钮 | 生成可逆像素 patch |
| clear | 选区按钮/删除键 | 写 null |

剪贴板协议：

```text
kind: aeonquill.pixel-selection-clipboard
schemaVersion: 1
width / height / pixels / source
```

粘贴支持替换全部或只覆盖非透明像素。跨帧粘贴仍由目标 frameId/layerId 命令写入，不直接修改数组。

## 4. 图像转像素

导入支持 PNG 与 WebP。源 RGBA 只保存在当前会话内存，转换后写入 PixelDocument。

| 参数 | 范围 |
| --- | --- |
| 目标宽/高 | 1—512 |
| 色数 | 1—256 |
| Alpha 阈值 | 0—255 |
| 缩放 | contain / cover / stretch |
| 抖动 | none / bayer4 / floyd-steinberg |
| 调色板 | 自动提取 / 使用当前调色板 |

实现：`src/lib/pixel/pixelConversion.mjs`。

流程：

```text
解码 RGBA
→ 确定性缩放
→ 透明阈值
→ 自动提取或复用调色板
→ 最近颜色量化/抖动
→ 创建严格 PixelDocument
```

导入项目文件扩展名为 `.aeonpixel.json`，MIME 为 `application/vnd.aeonquill.pixel+json`。反序列化支持 schema 0—7 的显式迁移，未知版本拒绝。

## 5. PixelDocument v7

实现：`src/lib/pixel/pixelCore.mjs`，类型：`pixelCore.d.mts`。

```ts
{
  kind,
  schemaVersion: 7,
  id, name, width, height, revision,
  palette,
  paletteCycles,
  layerGroups,
  layers,
  frames,
  animationTags,
  animationEvents,
  terrainMaps,
  activeLayerId,
  activeFrameId,
  onionSkin
}
```

每个 frame 的 `cels` 按 layerId 保存固定长度数组：

```text
cels[layerId].length === width × height
cell = palette color ID | null
```

因此一个像素不是画布元件或 DOM 节点。最大总文档单元数 16777216；单普通像素命令最多 65536 个点。

## 6. 命令与撤销

持久修改必须使用 `PixelCommand schema v1`。核心命令族：

| 领域 | 命令 |
| --- | --- |
| 像素 | paint、erase、patch、restore |
| 调色板 | replace |
| 调色板循环 | add、remove、restore、patch |
| 图层组 | add、remove、restore、patch |
| 图层 | add、remove、restore、patch、reorder、select |
| 帧 | add、remove、restore、patch、duration、reorder、select |
| Cel | copy、restore |
| 动画 | add、remove、restore、patch |
| 动画事件 | add、remove、restore、patch |
| Terrain Map | add、remove、restore、patch、resize、cells.patch |
| 洋葱皮 | set |

执行顺序：

```text
构造 command(baseRevision)
→ 精确字段与引用校验
→ 克隆并应用候选
→ 完整 assertPixelDocument
→ revision + 1
→ 返回 next document + inverse command
```

预览播放、拖动草稿、调色板循环的 elapsedMs 不写正文 revision。

## 7. 帧与洋葱皮

帧支持：

- 新建。
- 复制当前帧。
- 删除。
- 重排。
- 重命名。
- 单帧 durationMs。
- 选择和播放。

洋葱皮保存 enabled、previousFrames、nextFrames、opacity。渲染时按距离降低透明度；动画播放期间不把预览帧写成 activeFrameId。

复制帧同时复制所有图层 Cel 和逐帧 gameplay 数据；删除帧会触发动画片段、事件和引用一致性校验。

---

## 8. 动画片段

AnimationTag 字段：

```ts
{
  id,
  name,
  fromFrameId,
  toFrameId,
  direction: 'forward' | 'reverse' | 'ping-pong',
  loop
}
```

序列规则：

- forward：从起始帧到结束帧。
- reverse：反向。
- ping-pong：首尾只出现一次，中间帧反向返回。

例如 `[A,B,C,D]` 的 ping-pong 为 `[A,B,C,D,C,B]`。

UI 支持：

- 新增/删除/命名片段。
- 修改闭区间。
- 方向与循环。
- 为片段批量设置帧时长。
- 将当前图层 Cel 复制到片段其他帧。
- 只导出当前片段。

唯一序列解析器 `resolvePixelAnimationSequences()` 同时供播放、metadata 和游戏导出使用。

---

## 9. 动画事件

事件类型：

```text
marker / sfx / hit / custom
```

每条事件绑定：

- animationTagId。
- 片段范围内的 frameId。
- 名称和 value。

删除片段或帧时不能留下悬空事件。片段导出会保留事件，而编辑器本身不会执行游戏逻辑或自动播放音效。

---

## 10. 调色板循环

每个循环：

- 至少两个现有颜色。
- 最多 32 色。
- 不与另一循环重复占用颜色。
- stepDurationMs。
- forward / reverse / ping-pong。
- enabled。

`resolvePixelPaletteCycleMap(document, elapsedMs)` 只返回瞬态颜色映射，不改变 Cel 中保存的基础 color ID。预览、帧渲染和导出使用同一映射规则。

---

## 11. 导出

| 导出 | 内容 |
| --- | --- |
| 项目 | 完整 `.aeonpixel.json` |
| 成套导出 | 项目 JSON、当前帧 PNG、Sprite Sheet、metadata |
| 动画片段 | 片段专属 Atlas、精确播放序列、事件、调色板循环 |
| 游戏资产 | 共享 Atlas、manifest、离线预览 |
| Terrain | PNG、JSON、TMJ |
| 引擎桥 | Godot、Unity、RPG Maker 文件 |

正式 PNG 渲染不读取 DOM 画布截图，而是从当前校验后的 PixelDocument 调用确定性 RGBA 合成器。

## 12. 修改/新增工具

1. 在 `pixelTools.mjs` 实现纯函数，输入和输出使用整数坐标。
2. 在 `PixelModeWorkbench.tsx` 增加 UI 与预览草稿。
3. 把结果压缩成现有 `pixels.patch`；确需新语义时再增加命令类型。
4. 为新命令定义精确字段、权限、最大点数和 inverse。
5. 验证锁定图层/组、边界裁剪、透明像素、撤销/重做和跨帧。
6. 若影响渲染，复核当前帧、Sprite、片段、游戏包和 Terrain 输出。

## 14. 当前限制

- 没有 Aseprite 原生文件读写。
- 剪贴板是应用会话协议，不是系统级像素格式。
- 画布最大 512×512、最多 256 帧和 64 图层。
- 本地“智能清理”和八方向补齐是确定性辅助，不是生成式补画模型。
- 多人实时协作尚未接入。
