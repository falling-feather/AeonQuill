## 1. 能力边界

本检查点把“帧列表”升级为可命名、可限定范围、可决定播放方向的动画片段，但不建立第二套动画文档。帧像素、图层、调色板、动画标签和当前编辑位置仍共同属于唯一 `PixelDocument`；人工操作与后续 Agent 工具都必须经过同一 `PixelCommand` 校验和逆命令。

本次提供：

- 有界动画标签：名称、起始帧、结束帧、正向/反向/往返、是否循环；
- 不污染 document revision 的片段预览；
- 一个命令批量设置片段基础帧时长；
- 把当前帧的当前图层覆盖复制或按非透明像素合并到片段其他帧；
- 在 Sprite metadata 与游戏 manifest 中交付确定播放序列；
- schema v0/v1 到 v2 的显式迁移。

图层组、混合模式、调色板循环、Tileset 规则编辑、碰撞框和 Godot/Unity/RPG Maker 往返不属于本检查点。

## 2. PixelDocument schema v2

`src/lib/pixel/pixelCore.mjs` 是权威校验与命令执行边界。文档新增 `animationTags`：

```ts
type PixelAnimationTag = {
  id: string
  name: string
  fromFrameId: string
  toFrameId: string
  direction: 'forward' | 'reverse' | 'ping-pong'
  loop: boolean
}
```

约束如下：

1. 标签 ID 在文档内唯一，标签最多 64 个。
2. 两个边界都必须引用现存帧，且起始帧在当前帧序中不得晚于结束帧。
3. 删除标签边界帧会以 `FRAME_IN_ANIMATION_TAG` 失败；重排帧若会倒置任何标签范围也会失败。
4. 标签可覆盖单帧；往返播放不会在序列内部重复首尾端点。
5. 文档未知字段、未知方向、重复标签和越界引用一律失败关闭。

命令 schema 仍为 v1，因为新增命令类型不改变命令信封结构；文档、Sprite metadata 和游戏 manifest 升级为 schema v2。

## 3. 播放序列

`resolvePixelAnimationFrames(document, tagId)` 是 UI、Sprite metadata 和游戏 manifest 共用的唯一序列解析器：

- `forward`：`A, B, C, D`
- `reverse`：`D, C, B, A`
- `ping-pong`：`A, B, C, D, C, B`

循环由播放器在序列末尾回到开头实现。非循环片段到达末帧后停止。工作台用序列游标而不是只保存 frame ID，因此往返序列中重复出现的中间帧不会被错误折叠；预览只更新 React 本地状态，不提交 `frames.select`，也不增加文档 revision。

## 4. 原子批量命令

### 4.1 帧时长

`frames.duration.set` 接收唯一帧 ID 和 20—60000ms 整数时长。列表必须非空且不超过文档帧数；整个列表一次验证、一次 revision、一个逆命令，任何一项非法时不会部分写入。

### 4.2 跨帧图层复制

`cels.copy` 固定包含：

- `sourceFrameId`
- 唯一且不含源帧的 `targetFrameIds`
- 唯一 `layerIds`
- `replace` 或 `non-transparent` 模式

`replace` 用源 Cel 完整替换目标 Cel；`non-transparent` 只写入源 Cel 非空颜色，目标透明区以外的原像素保留。目标图层被锁定、帧或图层未知、重复目标、源帧混入目标或预计处理超过 1,048,576 个单元格时，命令在写入前失败。逆命令 `cels.restore` 保存受影响目标 Cel 的完整旧值，因此一次跨帧操作可以一次撤销和重做。

### 4.3 动画标签

`animations.add/remove/patch` 都生成严格逆命令；`animations.restore` 仅供系统撤销栈使用。删除标签不删除帧或像素。修改名称、范围、方向或循环会创建正常文档 revision，并随 SQLite 正文、恢复点和完整项目包保存。

## 5. UI 与持久化

`PixelModeWorkbench` 的帧时间线下方提供片段标签条和编辑区。用户可以新建/删除标签、修改名称、范围、方向和循环，按片段批量设定时长，并把当前活动图层复制到范围内其他帧。时间线以底边标识当前标签覆盖范围，播放按钮只预览选中标签；没有标签时兼容播放全部帧。

活动标签选择属于会话 UI 状态，不写入项目；标签定义本身属于 PixelDocument。像素正文仍由 `WorkspaceStore.mode_documents` 权威保存，刷新后重建标签和帧数据；浏览器镜像只作恢复回退。

## 6. Sprite 与游戏交付

`createSpriteSheetMetadata()` 输出 schema v2，并在既有 Atlas 单元格之外加入所有动画标签及解析后的 `frameIds`。

`createPixelGameManifest()` 同样输出 schema v2：

- `animations` 保存所有标签的名称、方向、循环和逐项 `{ id, durationMs }`；
- `animation` 保存本次导出在 UI 中选择的主动画；
- 没有标签的旧项目仍生成 `default` 正向循环动画，保持离线查看器兼容。

Tiled TSJ/TMJ、八方向、锚点和 Atlas 继续复用同一 manifest 与 Sprite 布局，不重新推导另一套帧索引。

## 7. 迁移与兼容

- schema v2：严格校验后复制，不做隐式修复；
- schema v1：严格拒绝未知旧字段，然后补入空 `animationTags` 并升级到 v2；
- schema v0：继续经过既有单层/调色板索引迁移器，最终形成 v2；
- 缺失 `schemaVersion` 或未知版本：拒绝导入。

旧 localStorage 键名中的 `v1` 是兼容标识，不等于当前正文 schema；在迁移回归和恢复路径移除前不得破坏性改名。

## 9. 维护要求

新增动画能力时，优先扩展 PixelDocument 和严格命令，不在组件内部维护另一份不可导出的动画事实。任何批量算法必须先估算单元格预算、全量校验再写入，并返回可应用的逆命令。需要高密度实时预览或大规模逐帧运算时，应依据性能门引入 Worker/PixiJS 子场景，而不是把每个像素或 Cel 变成 DOM 元件。
