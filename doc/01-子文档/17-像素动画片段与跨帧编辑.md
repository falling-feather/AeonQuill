## 2. 绘图工具与快捷键

| 工具 | 快捷键 | 行为 |
| --- | --- | --- |
| 铅笔 | `B` | 使用当前颜色绘制 |
| 橡皮 | `E` | 将像素设为空 |
| 填充 | `G` | 对连续同值区域 flood fill |
| 吸管 | `I` | 读取像素颜色 |
| 直线 | `L` | Bresenham 风格整数栅格线 |
| 矩形 | `R` | 栅格矩形 |
| 选区 | `M` | 建立整数矩形选区 |
| 取消选区 | `Esc` | 清除选区和拖动草稿 |
| 清空选区 | `Delete` / `Backspace` | 将选区像素设为空 |
| 撤销 | `Ctrl/Meta + Z` | 应用逆命令 |
| 重做 | `Ctrl/Meta + Shift + Z` | 重新应用命令 |

画笔尺寸 1—4。水平/垂直镜像在生成笔触像素集合时展开，并在提交前去重、裁剪到文档边界。

一像素铅笔默认启用“像素完美笔触”。先处理按时间排列的栅格路径，再展开镜像：删除孤立的冗余正交角点，保留有歧义的连续折线、起终点和重复访问。粗笔及橡皮不应用此规则。绘制期间只更新画布草稿；抬笔提交一个命令，取消或失去指针捕获则恢复原画布，不推进 revision。笔刷与选区控制条位于画布外，避免遮挡边缘像素。

底层算法位于 `src/lib/pixel/pixelTools.mjs`：

- `normalizePixelRect`
- `rasterPixelLine`
- `rasterPixelRectangle`
- `pixelPerfectStroke`
- `expandPixelBrush`
- `floodFillPixels`

## 3. 选区与剪贴板

| 操作 | 输入 | 结果 |
| --- | --- | --- |
| 移动 | 方向键 | 原位置清空，目标位置写入 |
| 复制移动 | Alt + 方向键 | 保留原位置并写入目标 |
| 复制 | Ctrl/Meta + C | 写会话剪贴板 |
| 剪切 | Ctrl/Meta + X | 写剪贴板并清空原区域 |
| 粘贴 | Ctrl/Meta + V | 写入目标选区 |
| 水平/垂直翻转 | 选区按钮 | 生成可逆像素 patch |
| clear | 选区按钮/删除键 | 写 null |
| 旋转/缩放 | 选区变换面板 | 预览、裁剪统计，应用一个像素命令 |
| 系统复制/粘贴 | Ctrl/Meta + Shift + C/V 或按钮 | PNG 与精确颜色文本，跨项目取用 |

剪贴板协议：

```text
kind: aeonquill.pixel-selection-clipboard
schemaVersion: 1
width / height / pixels / source
```

粘贴支持替换全部或只覆盖非透明像素。跨帧粘贴仍由目标 frameId/layerId 命令写入，不直接修改数组。原 Ctrl/Meta+C/X/V 使用会话剪贴板；系统按钮与 Shift 快捷键使用操作系统剪贴板，两者均可独立操作。

选区变换由 `pixelTransform.mjs` 唯一计算：nearest 缩放、非正方形 90 度精确旋转、任意角逆映射、中心/左上锚点、移动/复制和透明裁剪。预览不改 revision，应用前复检文档 revision、选区和锁定，最终一个 pixels.patch 支持完整撤销。

系统协议由 `pixelSystemClipboard.mjs` 定义，kind 为 aeonquill.pixel-system-clipboard、schema1，只有尺寸、canonical RGBA 色表与像素索引，不传源项目 ID。写入 PNG 与 text/plain，优先读取精确文本；外部 PNG-only 也可粘贴。按 RGBA 复用/追加目标调色板，最多 256 色和 65536 像素，PNG 8MiB、单边 512；超色数或越界拒绝并保留正文，不自动量化。无选区落在 (0,0)，有选区以其左上角为目标；调色板和 linked Cel 联动由唯一内核校验，像素和增色一起作为一次完整快照撤销。

浏览器读写在 `pixelSystemClipboardBrowser.ts`，PNG 解码前检查签名、尺寸和预算；异步读取期间文档变化会拒绝应用。权限或 API 不可用显示具体原因，内存剪贴板仍可使用。当前平台验证为系统 Edge；不同桌面 WebView 的权限能力单独实装验证。

## 4. 图像转像素

导入支持 PNG 与 WebP。源 RGBA 只保存在当前会话内存；“生成转换预览”不修改正文，检查原图和候选后点击“应用转换结果”才写入 PixelDocument。

| 参数 | 范围 |
| --- | --- |
| 目标宽/高 | 1—512 |
| 色数 | 1—256 |
| Alpha 阈值 | 0—255 |
| 缩放 | contain / cover / stretch |
| 抖动 | none / bayer4 / floyd-steinberg |
| 调色板 | 自动提取 / 使用当前调色板 |
| 采样 | nearest / area |
| 颜色匹配 | rgb / oklab |
| 透明模式 | threshold / preserve |

实现和预设的唯一来源为 `src/lib/pixel/pixelConversion.mjs`。默认 nearest/rgb/threshold 保持原转换行为；“像素素材”保持硬边，“插画缩小”使用面积采样和 Oklab，“柔和透明边缘”进一步保留半透明。预设只改变采样、匹配、透明和抖动，不改目标尺寸或用户调色板。

面积采样按源像素覆盖面积在线性 RGB 中预乘 Alpha、加权平均后反预乘，避免透明背景产生暗边；Oklab 用于感知颜色距离，确定性调色板提取继续使用原 median cut。preserve 在现有 RGBA 调色板条目中保存半透明，完全透明仍为空像素。固定调色板不扩展或修改，因此保留透明度的范围受其现有 Alpha 值约束；RGB 改色保留该条目的 Alpha。

加权中位数落在排序末端的高占比颜色桶时，将末桶独立切出，避免背景色与前景混色。默认参数及既有默认素材字节基准保持兼容；旧算法在该边界的错误结果不再保留。

流程：

```text
解码 RGBA
→ 确定性缩放
→ 透明阈值或保留 Alpha
→ 自动提取或复用调色板
→ 最近颜色量化/抖动
→ 创建严格 PixelDocument
→ 预览候选
→ 用户显式应用
```

转换复用现有计算 Worker，绑定源图、参数、文档 ID 和 revision。任一变化主动取消旧计算并使候选失效；取消、过期响应和 Worker 不可用均不改变正文。应用保持当前文档 ID，推进一次 revision，完整恢复前文档的撤销/重做由会话历史管理。源 RGBA、候选和历史快照不存入 SQLite 或项目文件。

固定素材的 12 组转换输出与机器统计见[像素算法对照](../../benchmarks/pixel-quality/README.md)；可重复输出和测试通过不等于人工观感验收。

导入项目文件扩展名为 `.aeonpixel.json`，MIME 为 `application/vnd.aeonquill.pixel+json`。反序列化支持 schema 0—8 的显式迁移，未知版本拒绝。

## 5. PixelDocument v9

实现：`src/lib/pixel/pixelCore.mjs`，类型：`pixelCore.d.mts`。

```ts
{
  kind,
  schemaVersion: 9,
  id, name, width, height, revision,
  palette,
  paletteCycles,
  layerGroups,
  layers,
  frames,
  celLinks,
  animationTags,
  animationEvents,
  terrainMaps,
  activeLayerId,
  activeFrameId,
  onionSkin
}
```

每个 frame 的 `cels` 按 layerId 保存固定长度数组：

```text
cels[layerId].length === width × height
cell = palette color ID | null
```

因此一个像素不是画布元件或 DOM 节点。最大总文档单元数 16777216；单普通像素命令最多 65536 个点。

## 6. 命令与撤销

普通持久修改使用 `PixelCommand schema v1`。核心命令族：

| 领域 | 命令 |
| --- | --- |
| 像素 | paint、erase、patch、restore |
| 调色板 | replace |
| 调色板循环 | add、remove、restore、patch |
| 图层组 | add、remove、restore、patch |
| 图层 | add、remove、restore、patch、reorder、select |
| 帧 | add、remove、restore、patch、duration、reorder、select |
| Cel | copy、restore、link、unlink、restore-links |
| 动画 | add、remove、restore、patch |
| 动画事件 | add、remove、restore、patch |
| Terrain Map | add、remove、restore、patch、resize、cells.patch |
| 洋葱皮 | set |

执行顺序：

```text
构造 command(baseRevision)
→ 精确字段与引用校验
→ 克隆并应用候选
→ 完整 assertPixelDocument
→ revision + 1
→ 返回 next document + inverse command
```

预览播放、拖动草稿、调色板循环的 elapsedMs 不写正文 revision。

整图转换会更换尺寸、调色板及帧结构，使用 `pixelHistory.mjs` 的会话内 document-snapshot 撤销条目；普通命令仍由同一 `applyPixelCommand` 执行。快照严格迁移并复制完整 v9 文档，恢复时保持文档 ID 并推进当前 revision，避免倒退保存基准。历史条目不改变持久化 schema。

## 7. 帧与洋葱皮

帧支持：

- 新建。
- 复制当前帧。
- 删除。
- 重排。
- 重命名。
- 单帧 durationMs。
- 选择和播放。

洋葱皮保存 enabled、previousFrames、nextFrames、opacity。渲染时按距离降低透明度；动画播放期间不把预览帧写成 activeFrameId。

复制帧同时复制所有图层 Cel 和逐帧 gameplay 数据；删除帧会触发动画片段、事件和引用一致性校验。

## 8. 动画片段

AnimationTag 字段：

```ts
{
  id,
  name,
  fromFrameId,
  toFrameId,
  direction: 'forward' | 'reverse' | 'ping-pong',
  loop
}
```

序列规则：

- forward：从起始帧到结束帧。
- reverse：反向。
- ping-pong：首尾只出现一次，中间帧反向返回。

例如 `[A,B,C,D]` 的 ping-pong 为 `[A,B,C,D,C,B]`。

UI 支持：

- 新增/删除/命名片段。
- 修改闭区间。
- 方向与循环。
- 为片段批量设置帧时长。
- 将当前图层 Cel 复制到片段其他帧。
- 只导出当前片段。

唯一序列解析器 `resolvePixelAnimationSequences()` 同时供播放、metadata 和游戏导出使用。

---

## 9. 动画事件

事件类型：

```text
marker / sfx / hit / custom
```

每条事件绑定：

- animationTagId。
- 片段范围内的 frameId。
- 名称和 value。

删除片段或帧时不能留下悬空事件。片段导出会保留事件，而编辑器本身不会执行游戏逻辑或自动播放音效。

---

## 10. 调色板循环

每个循环：

- 至少两个现有颜色。
- 最多 32 色。
- 不与另一循环重复占用颜色。
- stepDurationMs。
- forward / reverse / ping-pong。
- enabled。

`resolvePixelPaletteCycleMap(document, elapsedMs)` 只返回瞬态颜色映射，不改变 Cel 中保存的基础 color ID。预览、帧渲染和导出使用同一映射规则。

### 13.1 大文档 Worker

大文档的帧合成、Sprite sheet、Terrain 推断/覆盖检查和交付计算进入 `pixelComputation.worker.ts`；小文档保留同源同步计算。协议与预算的唯一实现为 `pixelComputation.mjs`，生命周期由 `pixelComputationClient.mjs` 管理。请求绑定 ID、revision 和操作；取消、卸载及过期响应不会覆盖当前预览。普通渲染和导出在 Worker 不可用时使用同源同步回退；image-convert 必须有 Worker，否则显示可重试错误，避免同步转换阻塞取消。算法错误不被吞掉。

`createPixelComputationSnapshot` 为帧预览仅保留必需帧与合成元数据，覆盖检查保留地形/对象引用并用共享空 Cel 替代像素，转换仅携带文档身份及源图。这些快照是短期只读计算输入，不得保存、导出或修改。正式保存与导出继续使用完整权威文档。

Terrain 地图/九宫格预览使用同一投影机制：依赖帧由 `createPixelTerrainMapLayout` / `createPixelTerrainPreviewLayout` 的最终 `cells[].frameId` 唯一决定，其余帧保留全部 gameplay 和引用元数据，但不传真实 Cel。对象层、碰撞、片段与颜色循环引用完整保留。Terrain 导出包含完整图集和 manifest，继续使用原文档。定向等价、真实预检查、失败恢复及 30 分钟原控制/资源门通过；完整数据见[性能记录](../../benchmarks/product-performance/pixel-20261004.json)。

64MiB 是每次计算的输出/中间产物预算，不是整个页面的 JS 堆上限。纯预览预算不会序列化整份文档；导出预算在大缓冲和重复项目 JSON 创建前检查。静止编辑仅计算当前帧及洋葱皮，播放时缓存当前片段的去重帧，超过预算会停止播放并显示错误；调色板预览限制更新频率并合并下一次计算。地形和覆盖检查在相关区域进入视口后才请求，减少屏幕外计算和整份文档的跨线程复制。并行计算统一跟踪待完成请求，只有全部结束后才退出运行状态。

验证入口：`tests/pixel-computation.test.mjs` 与 `scripts/validate-pixel-objects-worker-ui.mjs`。浏览器验收核对 Worker 与同步字节哈希、取消/过期、导出图集一致性和大文档预算。导入与正文校验仍可能产生明显主线程开销；每次实际输入延迟和堆观察值以 QA 报告为准，不用 Worker 存在推断整体性能通过。

通过严格校验的 v9 文档在迁移、克隆和命令执行时，由 `pixelCore.mjs` 按 Cel 复制像素数组，其余元数据继续深拷贝。输入与输出没有共享可变内容，序列化字节及键顺序保持不变；避免为了复制而往返解析数千万字符的 JSON。持久化仍使用原有字符串正文和 revision 协议。HTTP 大请求先编码为 UTF-8 字节，再封装成 Blob；避免直接 BufferSource 在浏览器 `fetch()` 中发生大规模同步复制。1Mi 字符的分界与小请求字符串路径保持，服务端 JSON 字节、写入顺序、重试和冲突协议相同。失败保存/恢复及字节回归已通过，没有新增并行存储权威。

长测先确认绘制、撤销和重做分别推进 revision，再计入有效操作；控制动作沿用 3 秒总预算，不等待保存或 Worker 完成。超时报告保留当轮按钮状态、修订号、Worker 和请求摘要。该仪器修正不能反推旧失败的具体原因，也不改变性能阈值。

诊断入口 `--preflight-only --profile-summary` 只运行既有预检查，不能代替长测。CPU profile 聚合为 Top20，不保存原始 trace 或正文；它包含诊断包装内的原生工作，仅供定位，生产指标取未启用包装的长测。诊断 hook 或采集缺失时显式失败；大字符串大小用字符数，二进制用 byteLength，统计不额外编码字符串。页面可见性、revision 与 click 起止分别记录，避免把自动化等待等同于算法耗时。

大像素正文保存准备通过现有计算Worker的document-json操作执行，完整文档按原serializePixelDocument编码；同一文档的新准备会取消旧Worker，小文档保留同源同步路径。ProductApp先登记dirty内存草稿，再等待序列化；迟到或被替代的准备不能覆盖较新正文、恢复结果或当前另一文档。HTTP写队列在确定base revision后，将大请求的JSON转义和UTF-8/Blob编码交给短期Worker，小请求保持原字符串路径。Worker异常回退同一编码实现，算法错误与超时保留草稿并可重试；没有平行存储权威。

异步编码开始前就预约工作区写入：saveWorkspaceModeDocument接收正文字符串或其准备Promise，但只向服务端发送已解析字符串。写入dirty和代数先建立，准备期间晚到的clean读取不能移动base revision。HTTP序列、幂等重试与冲突检查仍走唯一队列；准备失败不写入、不清空草稿。

### 13.2 草稿持久化与释放

`ProductApp.tsx` 只在工作区实际保存成功后标记正文已持久化。离开像素模式时释放已保存的文档缓存；保存尚未完成或失败的草稿按文档 ID 留在当前页面会话中，切换项目再返回仍可恢复。保存回调只处理对应文档对象，较早请求不会清空较新的修改。

存在未保存草稿时，重开直接使用内存内容，并保留原写入基准 revision。不会先读取新的 SQLite revision 再覆盖并发修改；重试仍经过服务端冲突检查。用户明确恢复历史正文时才丢弃该文档的待保存副本。大文档可能超过 localStorage 配额，内存恢复不等于刷新页面后可恢复；保存失败仍需保持页面并导出或重试。

专项浏览器回归入口为 `scripts/validate-pixel-draft-release-ui.mjs`，覆盖保存后的释放、配额不足且服务端失败、跨项目返回、恢复写入和并发冲突。首轮笔触/转换完整用户链路由 `scripts/validate-pixel-first-round-ui.mjs` 验证，纳入默认门。

选区变换面板及算法只在打开时载入，模式首载预算保持150KB。加载期间可取消；载入失败保持工作台与正文可用，提示先保存/导出再重新载入。面板直接回传当前预览的严格结果，根仍核对revision、图层/关联锁定并通过同一像素命令提交，避免重复变换计算。

### 13.3 持续输入延迟验证

validate-pixel-objects-worker-ui.mjs在原30分钟控制/资源门上，增加每轮一次真实按住鼠标的11点笔触：按住期间必须出现画布像素变化且正文revision不变，释放仅推进一次revision，再验证撤销。记录预览和释放各自P50/P95/最大值，预览P95预算50ms、释放250ms；原点击、撤销/重做、取消和资源阈值保持，不以新分项替换原控制门。

完整60轮的统计、1360个短期Worker释放与页面堆观测见[持续延迟记录](../../benchmarks/product-performance/pixel-latency-20261018.json)。这是当前机器前端链路的实测，安装态快验与跨硬件/人工观感结论分开；自动保存仍遵循上节唯一队列及失败保护。

## 14. 当前限制

- Aseprite tilemap、复杂嵌套、额外混合模式与自定义扩展不全支持；导入明确拒绝或警告，导出保留原项目。
- 系统剪贴板支持 PNG 与应用像素文本；大于预算或超过可用 256 色需要先做图像转换，不能静默损失颜色。
- 画布最大 512×512、最多 256 帧和 64 图层。
- 本地“智能清理”和八方向补齐是确定性辅助，不是生成式补画模型。
- 多人实时协作尚未接入。

## 15. 关联 Cel 与互通

关联 Cel 已进入 v9 正文。时间线显示当前图层的关联帧，选择目标帧后用“关联”将当前 Cel 复制到目标并建立联动；“解除”只解除当前帧关系，保留像素。旧 v0—v8 文档显式迁移为空 celLinks，未来版本拒绝。

关联Cel采用正文显式分组：同一图层内的两个或更多帧共用关联身份，现有frame.cels像素数组继续作为渲染/导出输入。v9新增celLinks列表。组内数组值必须完全一致；像素命令对组内成员联动，所有受影响成员/图层锁定均校验，解除关联保持像素。删除帧/图层会修正或移除不足两成员的组，逆操作完整恢复关系；不以仅内存引用相等判断持久关联。

Aseprite 互通已接入；编解码继续复用当前 create/migrate/assert，不另建正文。保留范围与限制见[原生互通](#16-aseprite-互通)。

关联操作使用 cels.link / cels.unlink，逆操作完整恢复像素与关系。Worker 帧快照裁去无效分组；Terrain 预览对关联成员闭包后再裁剪真实 Cel，避免快照违反同组等值约束。覆盖检查使用全空只读 Cel，正式保存始终保留完整正文。

方案及状态以[长任务规划](../02-项目规划.md#07-持续开发长任务)为准。

## 16. Aseprite 互通

顶栏“打开项目”可选择 .ase/.aseprite，先显示尺寸、帧、层、色数与warnings，再明确应用；替换像素内容但保持当前项目身份，完整快照一次撤销。“Aseprite”准备导出并提示专属字段损失，确认后下载。完整保存仍使用 .aeonpixel.json。

唯一编解码实现 `src/lib/pixel/pixelAseprite.mjs` 按[官方规范](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md)处理32位RGBA、16位灰度、8位索引、raw/zlib、单层组、normal/multiply/screen/add、透明、时长与支持的动画标签；32MiB文件、512单边、256帧、64层、256色及解压输出预算在分配前检查。

缺少 Cel 的帧保持透明，只有显式type1复用；动态索引调色板按帧冻结并将实际RGBA并入文档色表，超256色拒绝且不自动量化。显式linked链在最终全画布像素等价时迁入celLinks；offset/opacity/动态palette导致不同像素则保留画面并警告关联未保留，不根据像素相同自动建关联。导出以组内最早帧为原始Cel，其余type1引用，关联拓扑可往返。

Terrain、逐帧游戏数据、palette cycles、动画事件和Aseprite user data等未共同表达的内容明确提示；tilemap、不支持的混合/嵌套或色彩配置按解析规则拒绝/警告，不声称所有文件无损。帧与图层ID由当前正文重新生成，不维持外部编辑器私有标识。

11项独立二进制夹具与攻击边界、RGBA/时长/标签/关联往返和真实Edge导入预览、拒绝不变、导出解码、保存重开均通过。Aseprite/LibreSprite本机未安装，原生编辑器直接打开和视觉对比尚未验证；机器往返不替代该结论。
