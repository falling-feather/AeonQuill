## 3. 坐标系统

画布同时存在三套坐标：

| 坐标 | 原点 | 用途 |
| --- | --- | --- |
| client | 浏览器窗口左上角 | PointerEvent 提供 |
| screen | 画布视口左上角 | 选框 CSS、手势 |
| world | 无限画布世界原点 | 元件 x/y/width/height |

相机定义：

```ts
type Camera = {
  x: number
  y: number
  zoom: number // 0.05—8
}
```

换算公式：

```text
screenX = worldX × zoom + camera.x
screenY = worldY × zoom + camera.y

worldX = (screenX - camera.x) / zoom
worldY = (screenY - camera.y) / zoom
```

client 转 screen 时还必须减去画布容器的 `getBoundingClientRect().left/top`。

## 4. 框选的正确实现

框选同时维护两个事实：

1. 屏幕矩形：直接用于 HTML 预览层。
2. 世界包围盒：用于空间查询和旋转元件相交测试。

```text
pointerdown
→ 记录 startScreen
→ 冻结 interactionCamera
→ pointermove: screenMarqueeRect(startScreen, currentScreen)
→ CSS 使用 left/top/width/height
→ pointerup: screenMarqueeWorldBounds(start, end, interactionCamera)
→ 空间索引初筛
→ 精确相交测试
→ 更新选区
```

实现位于：

- `screenMarqueeRect()`：`src/lib/canvasSpatialIndex.mjs`
- `screenMarqueeWorldBounds()`：同上
- 手势状态和预览：`src/components/CanvasWorkspace.tsx`

关键约束：

- 预览必须写 `style.left` 与 `style.top`，不能只传几何对象的 `x/y`。
- 提交必须使用 pointerdown 时冻结的 camera，不能在 pointerup 读取可能已变化的新 camera。
- 从右下向左上拖动时需用 `min()` 归一化。
- 屏幕预览和世界提交必须来自同一组起终点。
- 旋转元件不能只用未旋转 width/height 直接判断。

此前“预览永远从左上角开始”即是预览层未正确映射 left/top；“预览范围与实际选择不一致”通常是屏幕矩形与世界换算使用了不同相机。

## 5. 文档与命令

`CanvasDocument schema v1` 包含：

```ts
{
  schemaVersion,
  id,
  title,
  revision,
  createdAt,
  updatedAt,
  elements,
  camera
}
```

硬限制：

| 项目 | 限制 |
| --- | --- |
| 元件总数 | 5000 |
| 单事务命令数 | 1000 |
| 文字长度 | 200000 |
| 坐标/尺寸绝对值 | 10000000 |
| 图像处理步骤 | 64 |
| 蒙版笔画 | 512 |
| 蒙版点数 | 20000 |
| zoom | 0.05—8 |

正式命令：

- `elements.add`
- `elements.patch`
- `elements.remove`
- `elements.replace`
- `camera.set`
- `document.reset`

每个命令先校验精确键、actor 权限和候选文档，再增加 revision。拖动、缩放、框选等高频手势只更新内存预览；结束时合并为一次提交，避免撤销栈产生数百项。

## 6. 元件与能力边界

当前 kind：

```text

shape / frame / image / video / connector
```

元件共同拥有 ID、位置、尺寸、旋转、层级、锁定等字段；媒体元件额外保存稳定资源引用与处理栈。

Agent 工具只暴露允许的命令和字段：

- 不允许创建任意媒体 URL。
- 不允许替换整份文档。
- 不允许改变 camera。
- 不允许修改锁定元件或系统任务字段。
- 计划先在副本预演，经用户批准后由服务端重读权威正文提交。

## 7. 空间索引与视口裁剪

空间索引位于 `canvasSpatialIndex.mjs`。

渲染范围：

```text
left   = -camera.x / zoom
top    = -camera.y / zoom
width  = viewportWidth / zoom
height = viewportHeight / zoom
overscan = 240 screen pixels / zoom
```

视口查询只渲染相交元件并增加 240 屏幕像素 overscan，避免快速平移时闪白。

保护限制：

| 限制 | 数值 | 目的 |
| --- | --- | --- |
| 单元件最大索引网格数 | 1024 | 超大元素走大对象集合 |
| 单次查询最大网格数 | 16384 | 超大视口避免遍历无限网格 |

空间索引只做候选初筛。框选、命中和旋转对象仍需精确几何判断。

## 8. 图片资源分级

受管图片具有原图、预览图和缩略图。画布选取规则：

- 元件未选中且屏幕尺寸较小时使用 thumbnail。
- 元件被选中或屏幕最大边超过 640 px 时使用较高分辨率版本。
- 离屏元件不创建图片解码节点。
- 原图只用于正式编辑、导出、SHA 和版本追踪。

这能避免在拥有大量高分辨率素材的画布上同时解码所有原图。

## 9. 渲染与事件性能

`CanvasWorkspace` 的高频相机更新通过 `requestAnimationFrame` 合并。渲染层使用统一 world transform：

```css
transform: translate(camera.x, camera.y) scale(camera.zoom)
```

选框是 screen 层，不进入上述 world transform。选择边框和手柄尺寸按 `1 / zoom` 反向缩放，以保持屏幕可点击尺寸稳定。

避免以下实现：

- 每次 pointermove 写 WorkspaceStore。
- 为每个像素创建 DOM。
- 在 React render 中重复解码原图。
- 把整个 `elements` 数组作为每个子组件的新对象。
- 用 CSS 混合结果代替正式导出合成。
- 让屏幕 UI 层和 world 内容层共享一个 transform。

## 10. 新增元件步骤

1. 在 `canvasCore.mjs` 增加 kind 与精确字段校验。
2. 若数据结构变化，增加显式迁移；未知未来 schema 继续失败关闭。
3. 在 `CanvasElementView.tsx` 增加渲染、命中和媒体资源选择。
4. 在创建工具和 Inspector 增加入口。
5. 通过现有命令写入；需要专用动作时定义可逆命令。
6. 决定该元件是否进入空间索引、框选和迷你地图。
7. 增加保存/恢复、移动/缩放、旋转、锁定、复制、撤销测试。
8. 使用大画布夹具检查离屏裁剪和资源解码数量。

## 12. 当前限制

- 当前为项目自研 DOM/Canvas 混合画布，不是 tldraw SDK。
- 元件上限为 5000；超大型节点图仍需继续做分区和增量状态。
- 多人/复杂自动布线尚未接入；普通有向连接和旋转端点已开放。
- 多人 CRDT 协作尚未接入。
- 画布文档为 schema v1，扩展字段必须严格校验并显式兼容旧正文，不得在组件内临时附加不可序列化对象。

## 13. 连接与批量对齐

选择元件，在浮动工具栏或属性位置面板点“创建连接”，选择起终点后创建。曲线可点击或键盘选择，在“连接关系”中改向、锁定、解锁或删除；删除端点沿用正文级联。锁定对象仍可作为连接端点，不修改它。自连、同向重复、失效端点与ID冲突拒绝，反向关系可独立存在。

所有连接（包括生成的来源关系）使用 `canvasSelection.mjs` 的 canvasConnectorPorts，从右侧/左侧中点按各自旋转求真实端点；几何不再复制在渲染组件。连接本身仍是既有CanvasElement，不新增正文schema或并行存储。

单普通元件对齐既有1200×800画板；多普通元件对齐当前选择的旋转AABB外边界，支持左/中/右/顶/垂直中/底。连接器不参加几何，任何被选普通元件锁定则整次拒绝；无变化不提交。唯一canvas.elements.patch一次更新全部位置并一次撤销，原位置保留精度。

纯几何/核心22项及真实Edge创建、多选、旋转、锁定、单revision/undo/redo、连接改向/删除、端口跟随、保存重开、包体往返和1440/390响应式通过，验收入口 `scripts/validate-canvas-selection-ui.mjs`。图像“全部工具”打开已有实验室，原浮动栏无行为“更多”已移除。

## 14. 均衡画布保存与草稿恢复

CanvasDocument仍以SQLite为持久化权威。canvasDraft.mjs只保存当前页面会话的未确认对象，编辑后同步登记，260ms防抖仅控制落盘。项目切换、桥接失败或localStorage配额不足时草稿不会因编辑器卸载而丢失；返回该项目优先读取保留草稿。关闭整个应用前仍应确认“已保存”，双失败时内存草稿不是磁盘备份。

projectApi.ts的保存和兼容包导入共用项目队列；同对象重复保存复用Promise，旧对象完成只释放仍为同对象的草稿，失败不污染后续队列。读取在请求前与响应后检查新草稿，过期GET不能覆盖它。导入期间若有新编辑，保留新正文并推进到导入修订之后，用户重新明确导入才替换。

顶栏区分正在保存、已保存、仅浏览器草稿和保存失败；后两种提供“重试保存”。目录touch只在SQLite成功后执行。服务端归一化资产返回只在当前仍是同一对象时应用，浏览器配额失败不掩盖SQLite成功。

验证为tests/canvas-draft.test.mjs、tests/canvas-project-client.test.mjs及scripts/validate-canvas-draft-ui.mjs，真实Edge覆盖205ms离开、跨项目、配额/HTTP双失败、仅浏览器、重试、刷新和导入并发。
