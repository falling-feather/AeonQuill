# 光阴砚 AEONQUILL — 本地 H3 视频工作流

> 该文档隶属于[01-开发者文档](../01-开发者文档.md)，用于说明本地 H3 视频工作流。
> 本文回答：用户怎样生成 H3 视频、哪些预设是真实高画质、T2V/I2V 如何接线、运行时怎样按需启动，以及开发者如何新增预设。

**最后一次更新时间**：2026-09-04

**更新者**：智能视频组、工作流与运行时责任域、文档专项组

---

## 1. 用户从哪里开始

1. 在项目中心创建或打开“智能视频”项目。
2. 打开“工作流”，安装并启用一个 H3 能力包。
3. 回到智能视频的“执行”页，选择镜头。
4. 选择 T2V、首帧 I2V 或首尾帧 I2V。
5. 选择画质预设、时长、比例与模型配置。
6. 检查执行清单；确认后提交。
7. 在任务卡查看排队、唤醒、上传、采样、后处理和交付状态。
8. 完成后把候选绑定到镜头并人工批准。

“规划、分镜和审批”不需要 H3；真正生成视频需要 ComfyUI、模型、节点与固定工作流全部就绪。

## 2. 能力状态与开箱条件

工作流中心使用六种状态：

| 状态 | 含义 | 是否可提交 |
| --- | --- | --- |
| 未安装 | 至少一个模型或节点缺失 | 否 |
| 已安装未启用 | 文件齐全，但未写入启用状态 | 否 |
| 已启用休眠 | 能力可用，ComfyUI 未启动 | 是，提交会唤醒 |
| 正在唤醒 | 已启动受管 ComfyUI，等待健康检查 | 等待 |
| 可执行 | 节点表、模型与版本复检通过 | 是 |
| 异常 | 启动、校验或连接失败 | 否 |

检测不只看主 `ComfyUI/models`，还解析受支持的 `extra_model_paths.yaml` / `.yml`。目录浏览阶段不计算大模型哈希；安装或启用时再校验固定 SHA-256。

相关实现：

- `server/workflow-center.mjs`
- `server/runtime-registry.mjs`
- `server/runtime-settings.mjs`
- `src/components/WorkflowCenter/`
- `src/lib/workflowCenterApi.ts`

## 3. 模型配置

统一注册表位于 `server/video-workflow-registry.mjs`，版本为 `aeonquill-h3-registry-v2`。

| profile | 状态 | 精度组合 | 运行时门 | 最低显存/内存 |
| --- | --- | --- | --- | --- |
| `fp8Scaled4060` | production | H3 DiT FP8 scaled + Qwen3-VL NVFP4/AWQ + VAE FP16/FP32 | ComfyUI 0.30+；当前稳定基线 0.30.2 / torch 2.8 cu129 | 8 GB / 32 GB |
| `int8ConvrotCu130` | candidate | H3 DiT INT8 ConvRot + 同上文本/VAE | ComfyUI 0.31+、PyTorch cu130+ | 8 GB / 32 GB |
| `w4a8MixedExperimental` | research-only | W4A8/INT4 混合 | 固定来源、哈希和画质对照未完成 | 不参与自动路由 |

`auto` 会按预设偏好和当前运行时能力选择 profile。用户显式选择不满足运行时门的 profile 时必须阻止提交，不得静默切换。

显存比较使用 0.0625 GB 容差，因此检测值 8.0 GB 满足 8 GB 要求。

## 4. 画质预设

| ID | H3 原生尺寸（16:9） | 采样 | 时长 | 4060 估时 | 交付含义 |
| --- | --- | --- | --- | --- | --- |
| `fast` | 608×352 | Turbo / 4 步 | 5/10/15 秒 | 3–5 / 7–11 / 12–18 分钟 | 动作与构图预览 |
| `balanced` | 1024×576 | Turbo / 8 步 | 5/10 秒 | 11–16 / 20–28 分钟 | 高清迭代母片 |
| `delivery720` | 608×352 | Turbo / 8 步 | 5/10/15 秒 | 5–7 / 11–16 / 17–24 分钟 | Lanczos 到 720P，仅文件尺寸 |
| `nativeHigh` | 1344×768 | Turbo / 8 步 | 5 秒 | 17–24 分钟 | H3 原生 768P |
| `cinemaBase` | 1024×576 | Base / 20 步 | 5/10 秒 | 15–30 / 30–55 分钟 | 质量优先，不挂 Turbo LoRA |
| `master720` | 1024×576 | Base / 20 步 | 5/10 秒 | 20–40 / 38–75 分钟 | SeedVR2 时序修复后交付 720P |

比例对应尺寸：

| 档位 | 16:9 | 9:16 | 1:1 |
| --- | --- | --- | --- |
| preview | 608×352 | 352×608 | 448×448 |
| quality | 1024×576 | 576×1024 | 768×768 |
| native768 | 1344×768 | 768×1344 | 992×992 |
| delivery720 | 1280×720 | 720×1280 | 720×720 |

关键语义：

- `delivery720` 是插值兼容档，不增加真实细节。
- `master720` 必须先释放 H3，再运行 SeedVR2 3B INT8；依赖缺失时禁止回退成 Lanczos。
- 预设表同时驱动 UI、服务端构建、运行时门和交付报告，不能在组件内复制一份常量。
- 估时是硬件经验区间，不是 SLA；任务记录必须保存实际耗时与执行身份。

## 5. T2V、I2V 与参考帧

| 模式 | 必需输入 | 可选输入 | 工作流模板 |
| --- | --- | --- | --- |
| T2V | 正向提示词 | 负向提示词、seed、比例、时长 | `server/workflows/minimax-h3-t2v.json` |
| 首帧 I2V | 正向提示词、首帧资产 | 负向提示词、seed | `server/workflows/minimax-h3-i2v.json` |
| 首尾帧 I2V | 正向提示词、首帧、末帧资产 | 负向提示词、seed | 同一 I2V 模板，启用末帧映射 |
| 连续镜头 | 第一镜输入 + 上一镜完成视频 | 下一镜的约束 | 服务端从受管 MP4 提取真实末帧 |

参考帧必须是当前项目可见的不可变资产版本。前端传入的磁盘路径、任意 URL 或跨项目哈希均被拒绝。

## 6. 提示词编译

前端提供创作参数，服务端将其规范化为 H3 提示：

```text
主体与身份
+ 动作时间顺序
+ 相机与镜头语言
+ 场景、光线、材质
+ 连续性约束
+ 质量限制
```

编译入口与请求模型：

- 前端：`src/lib/videoApi.ts`
- API：`server/index.mjs` 中的视频 prompt compile 路由
- 工作流参数：`server/workflow-builder.mjs`
- 固定节点白名单：同一 builder 中的节点 ID/type 映射

提示词只决定语义，不负责保护选区、模型身份或输出路径；这些由资产绑定和服务端映射保证。

## 7. 服务端执行路径

```text
提交参数
→ 校验项目、资产、preset/profile、时长和比例
→ 生成 workflow digest 与运行时快照
→ JobStore 写 queued
→ Scheduler 取得 GPU:1
→ RuntimeManager 按需启动/连接 ComfyUI
→ WorkflowBuilder 克隆固定模板并注入白名单参数
→ ComfyClient 上传受管输入并提交 prompt
→ 轮询/事件映射进度
→ 下载固定输出节点结果
→ 媒体探针与可选后处理
→ ProjectStore 写不可变版本
→ 复制交付副本并通过 SSE 完成任务
```

主要文件：

| 职责 | 文件 |
| --- | --- |
| 注册表与预设 | `server/video-workflow-registry.mjs` |
| 模板填充与节点白名单 | `server/workflow-builder.mjs` |
| ComfyUI 通信 | `server/comfy-client.mjs` |
| 运行时启动/停止 | `server/runtime-manager.mjs` |
| 后处理 | `server/video-postprocess-workflow.mjs` |
| 交付质量 | `server/video-delivery-quality.mjs` |
| 最终资产 | `server/project-store.mjs` |
| 输出副本 | `server/output-delivery.mjs` |

## 8. 按需运行时

策略由 `RuntimeManager` 实现：

| policy | 行为 |
| --- | --- |
| `idle` | 需要时启动；队列空闲达到设定时长后关闭自有进程 |
| `persistent` | 应用期间保持运行 |
| `manual` | 只接受用户显式启动/停止 |

空闲时长限制为 30—3600 秒。自动关闭前再次检查活动队列；外部已启动的 ComfyUI 只连接、不杀进程。切换策略不会绕过任务调度器。

## 9. 任务状态与错误显示

用户可见阶段至少区分：

- 等待 GPU。
- 检测/唤醒 ComfyUI。
- 上传输入。
- 加载模型。
- 采样。
- 卸载 H3。
- SeedVR2 修复。
- 媒体封装与质量检查。
- 写入项目资产。
- 复制到输出目录。

错误卡必须包含稳定错误码、失败阶段、可执行建议和有限日志。`COMFY_EXECUTION_ERROR` 是外层类别；例如模板缺失、模型缺失、节点不兼容、输出节点无文件应有更具体原因。

取消只终止本任务及其受管执行；重试复用规范化参数，并记录父任务 ID。

## 10. 新增预设的步骤

1. 在 `VIDEO_PRESETS` 登记唯一 ID、原生尺寸档、步数、采样器、时长、profile 偏好、最低资源与估时。
2. 若引入新后处理，在 `VIDEO_POSTPROCESSORS` 登记节点和模型依赖。
3. 更新 builder 的允许值和模板参数映射。
4. 更新工作流中心能力包及固定文件哈希。
5. 在 UI 明确区分原生尺寸和交付尺寸。
6. 增加 registry/builder/request/quality 单测。
7. 在目标硬件记录峰值显存、系统内存、总时长、文件探针和人工画质结论。

禁止只在前端增加一个选项；否则服务端会拒绝或出现 UI 与实际工作流漂移。

## 11. 验证与排障

最低验证：

```powershell
node --test tests/video-workflow-registry.test.mjs
node --test tests/workflow-builder.test.mjs
node --test tests/video-request.test.mjs
npm run validate:api
npm run validate:p7
```

排障顺序：

1. 工作流中心是否显示能力包已启用。
2. runtime status 是否指向正确 ComfyUI/Python。
3. object info 是否包含所需节点。
4. 模型是否能由主根或 extra model paths 唯一解析。
5. preset/profile/runtime gate 是否匹配。
6. Job 失败阶段与有限日志。
7. ComfyUI 输出是否来自映射的输出节点。
8. ProjectStore 是否已生成资产版本；外部 output 只是副本。

## 12. 当前限制

- INT8 cu130 和 SeedVR2 在注册表中仍是候选能力，必须满足运行时门后才启用。
- 8 GB 设备的 `master720` 依赖内存卸载，系统内存低于 32 GB 不应推荐。
- 10/15 秒不是所有预设都允许；`nativeHigh` 在 8 GB 上固定为 5 秒。
- 主体参考的强身份保持仍需真实样片盲审；目前不把机械哈希或提示词一致视为人物观感通过。
- 固定模板是安全与可复现边界，不等于完整暴露 ComfyUI 的任意节点编辑。
