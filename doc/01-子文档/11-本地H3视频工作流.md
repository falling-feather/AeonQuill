# 光阴砚 AEONQUILL — 本地 H3 视频工作流

> **文档梗概**：记录光阴砚 AEONQUILL 本地视频软件原型的当前实现，包括 MiniMax H3 文生/图生工作流、本地桥接 API、任务状态、前端回填、统一启动、验证结果和故障排查。
>
> 该文档隶属于[光阴砚 AEONQUILL — 开发者文档](../01-开发者文档.md)。
>
> **具体规划法则**：
>
> 1. 浏览器只能访问 AEONQUILL 本地桥接服务，不直接访问 ComfyUI `8188`。
> 2. 服务端只能从版本化模板构造工作流；前端不得提交任意 ComfyUI 图。
> 3. 图生视频首帧必须先规范化为目标宽高，再上传到 H3，避免节点的直接拉伸路径。
> 4. ComfyUI、Custom Node 和模型权重的许可证分别登记；当前默认只使用已核验来源的 Larry Turbo LoRA，不把 T8 LoRA 设为商用默认。
> 5. 发行 sidecar 必须内嵌两份固定 JSON 并在监听前预检；发行验收必须从包内资源编译 T2V/I2V，不能借用仓库文件。
>
> **最后一次更新时间**：2026-08-20
>
> **更新者**：开发组、后端组

## 1. 当前边界

本模块已经是可运行的本地闭环，不再只是界面占位：

```text
React 无限画布
  └─ /api（同源或 Vite 代理）
      └─ Node 本地桥接 127.0.0.1:8787
          ├─ 固定工作流模板与参数白名单
          ├─ JobScheduler：GPU 优先级、幂等、超时、取消与恢复
          ├─ JobStore、SSE、日志、错误、重试与不可变输出版本
          ├─ Runtime Manager：按需启动与队列空闲关闭
          ├─ .runtime 输入、任务与 MP4 资产
          └─ ComfyUI HTTP + WebSocket 127.0.0.1:8188
              └─ MiniMax H3 + Larry Turbo LoRA
```

当前只面向单机单用户。V0.4 完整离线阶段包提供受控 ComfyUI/Python/H3 运行时，但没有账号、权限、多租户隔离、云端对象存储、支付、配额、内容审核、安装包签名或自动更新。ComfyUI 端口仍只监听回环地址，NVIDIA 驱动仍由系统提供。

## 3. 工作流设计

### 3.1 共用主干

两个模板采用相同节点编号，便于稳定映射进度：

| 节点 | 类型 | 作用 |
| --- | --- | --- |
| `1` | `UNETLoader` | 加载 `minimax_h3_fl2va_pruned_fp8_scaled.safetensors` |
| `2` | `CLIPLoader` | 加载 Qwen3-VL H3 文本编码器 |
| `3` | `VAELoader` | 视频 VAE |
| `4` | `VAELoader` | 音频 VAE；关闭音频时移除 |
| `5` | `MiniMaxH3TurboLoRA` | 加载 `minimax_h3_turbo_v4_step600_ema.safetensors` |
| `6` | `MiniMaxH3ImageToVideo` | 生成条件和 AV Latent；文生时没有首帧输入 |
| `7` | `RandomNoise` | Seed |
| `8` | `BasicGuider` | 模型与 Conditioning |
| `9` | `MiniMaxH3TurboSampler` | H3 Turbo 专用采样器 |
| `10` | `BasicScheduler` | `simple` 调度与 4/6/8 步 |
| `11` | `SamplerCustomAdvanced` | 执行采样并产生真实步数事件 |
| `12` | `VAEDecode` | 视频帧解码 |
| `13` | `VAEDecodeAudio` | 音频解码；关闭音频时移除 |
| `14` | `CreateVideo` | 24 fps 音视频封装 |
| `15` | `SaveVideo` | 保存 MP4 |
| `16` | `LoadImage` | 仅图生视频存在，接到 `6.first_frame` |
| `17` | `LoadImage` | 图生视频可选末帧，存在时接到 `6.last_frame` |

模板不包含 Markdown、数学表达式、分辨率选择器或其他 UI 节点。前端选项由服务端直接映射到确定值，降低 Custom Node 漂移和任意工作流执行风险。

### 3.2 产品预设

| 选项 | 映射 |
| --- | --- |
| 8GB 稳定预览 | 4 步，`low_vram: true`，608×352 基线已在 RTX 4060 8GB 实测 |
| 8GB 细节 | 6 步，`low_vram: true`；依据 Turbo v4 作者说明改善 4 步快速运动拖影，当前已通过契约检查 |
| 8GB · 720P 交付 | 与 8GB 细节共用原生生成尺寸，完成后用 FFmpeg Lanczos 输出 1280×720、720×1280 或 720×720；不宣称原生 720P 细节 |
| 原生高清实验 | 736×416、416×736 或 544×544，8 步，建议最低 12GB；8GB 设备前端禁用提交，尚未进行本机真实推理 |
| 16:9 | 608×352 |
| 9:16 | 352×608 |
| 1:1 | 448×448 |
| 5 秒 | 124 帧 |
| 10 秒 | 243 帧 |
| 15 秒 | 362 帧 |
| 音频关闭 | 删除 `CreateVideo.audio`，并移除音频 VAE 与解码节点 |

H3 固定按 24 fps 生成，合法帧数遵循 `17k+5`。播放器 fps 不是节省推理成本的入口。

### 3.3 图生首帧

`normalizeVideoFirstFrame()` 在浏览器 Canvas 2D 中按目标宽高执行中心 cover 裁切，填充黑底并导出 PNG。首帧和可选末帧均使用这条规范化路径；桥接服务分别写入 `.runtime/inputs/`，再通过 `/upload/image` 送入 ComfyUI。

这一处理是必要约束：当前 H3 首帧节点对第一帧使用直接缩放，若把任意比例原图直接连接，会改变主体比例。

## 4. 本地 API

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/health` | 桥接服务存活 |
| `GET /api/runtime/status` | ComfyUI、GPU、显存、队列、必需节点与模型检查 |
| `POST /api/runtime/start` | 按策略启动或复用 ComfyUI，等待健康检查完成 |
| `POST /api/runtime/stop` | 仅在队列为空且进程由 AEONQUILL 创建时关闭 ComfyUI |
| `POST /api/runtime/policy` | 设置 `persistent | idle | manual` 与空闲秒数 |
| `GET /api/workflows` | 当前模式、画幅、时长和质量目录 |
| `GET /api/scheduler` | CPU/GPU 容量、活动和等待任务 |
| `GET /api/jobs` | 持久化任务列表 |
| `GET /api/jobs/events` | SSE 快照与增量任务事件 |
| `POST /api/jobs/video` | 创建受控文生或图生任务；支持 `Idempotency-Key` 与 `X-MiaoHui-Priority` |
| `GET /api/jobs/:id` | 单任务状态 |
| `POST /api/jobs/:id/cancel` | 删除等待任务或中断当前任务 |
| `POST /api/jobs/:id/retry` | 复制原参数并强制使用快速预设重试 |
| `DELETE /api/jobs` | 清理终态任务记录 |
| `GET /api/assets/:filename` | 私有本地 MP4；支持 Range 请求 |

公开 Job 不包含首帧、临时输出或正式输出的文件系统路径，也不包含 Data URL。页面先通过健康握手取得随机 HttpOnly 会话，后续 API 还会校验回环 Host、Origin/Fetch Metadata；该机制只适用于单机桥接，仍不得直接改成公网监听。

## 5. 状态、进度与错误

任务状态为 `queued | running | completed | failed | cancelled`；阶段为：

```text
queued
→ preparing
→ conditioning
→ sampling
→ decoding
→ encoding
→ saving
→ completed
```

任务先由统一调度器取得唯一 GPU 容量并设置两小时安全超时；桥接再打开带 `clientId` 的 ComfyUI WebSocket 并提交 `/prompt`。`executing` 节点映射阶段，`progress.value/max` 映射真实采样步数；历史轮询作为 WebSocket 断线后的完成兜底。完成后从 `/history/:promptId` 找到 `SaveVideo` 输出，经 `/view` 下载到临时 MP4，原子改名并计算 SHA-256/`outputVersion` 后才提交完成状态。

当前错误至少归一化为：

- `COMFY_OOM`：显存不足，建议快速预设、5 秒和释放其他显存。
- `COMFY_OFFLINE`：8188 不可连接。
- `WORKFLOW_VALIDATION`：节点、模型或输入契约不匹配。
- `COMFY_OUTPUT_STREAM_INVALID`：旧终端启动的 ComfyUI stdout 失效。
- `COMFY_EXECUTION_ERROR`：其他节点执行错误。

错误卡展示代码、用户可读说明、建议、最近日志和重试操作；详细节点 ID、类型与原始消息保存在 Job `error.details`。

## 6. 启动与停止

首次复制配置：

```powershell
Copy-Item config/local.example.json config/local.json
```

填写 `comfyRoot` 与 `pythonPath` 后：

```powershell
npm run app
```

统一启动行为：

1. `server/launcher.mjs` 只启动常驻桥接；页面和 API 立即可用，ComfyUI 可以保持关闭。
2. 提交 Job 或点击“启动”时，`runtime-manager.mjs` 探测 `system_stats`；外部 ComfyUI 存在时只复用，不接管生命周期。
3. 离线且策略不是 `manual` 时，优先使用显式机器配置；未配置时探测 `<runtime>/packages/aeonquill-comfyui-h3-cu129-win-x64-v1`，以其便携 Python 启动 ComfyUI 并等待健康检查。
4. 包内 ComfyUI 的 input/output/user/temp 分别重定向到应用 data/cache，不写入只读模型载荷目录。
5. `idle` 策略在本地 Job 与 ComfyUI 队列均为空后开始倒计时；新任务会取消计时，阈值到达后只关闭 AEONQUILL 拥有的子进程。
6. `persistent` 不自动关闭；`manual` 不自动启动；外部进程的“关闭”操作被禁用。
7. Node 桥接始终从 `dist/` 提供页面和同源 API。

开发时可分别运行 `npm run server` 和 `npm run dev`。Vite 将 `/api` 代理到 8787。

## 7. 实测基线

2026-08-12 建立开发机基线；2026-08-20 又在 RTX 4060 Laptop 8GB 上从 V0.4 staged 运行时与 packaged sidecar 完成发行物验证：

| 验证 | 结果 |
| --- | --- |
| 工作流契约 | 两模板节点必填输入与五个 H3 模型文件通过实时 `/object_info` 检查 |
| 文生视频 | 608×352、124 帧、4 步、原生音频；浏览器读取 5.167 秒并回填画布 |
| 图生视频 | 608×352 规范化首帧上传成功；124 帧、4 步、原生音频；浏览器读取 5.167 秒 |
| 资产服务 | 1KB Range 请求返回 HTTP 206 与正确 `Content-Range` |
| 取消 | 创建后取消，桥接与 Comfy 队列最终均为空 |
| 浏览器 | 1440×900 与 390×844；视频面板、抽屉、任务错误/完成态无框架覆盖层，控制台无 error/warning |
| 按需生命周期 | 休眠状态到 RTX 4060 运行时就绪约 38.7 秒；30 秒测试阈值下队列为空后 8188 端口自动关闭；正式配置恢复为 300 秒 |
| 720P 后处理 | 已有 5 秒 MP4 通过 FFmpeg Lanczos 转为 1280×720，并保留音频；临时产物验证后删除 |
| sidecar 模板闭包 | system-only PATH 下 packaged sidecar 启动前读取内嵌模板；T2V 15 节点、I2V 16 节点均可编译，截图所示 `minimax-h3-i2v.json` `ENOENT` 已不再复现 |
| staged ComfyUI | 包内 Python 3.12.10 / Torch 2.8.0+cu129 / CUDA 12.9 启动 ComfyUI 0.30.2，43.195 秒就绪，15/15 H3 节点与 Impact SAM 节点可见 |
| staged T2V | 608×352、124 帧、4 步，H.264 5.167 秒、199,220 bytes、SHA-256 `b33bc5bde377104b72d2735f8326847f135e3507e9bf9f2e54020d9ec113d6cf` |
| staged I2V | 608×352、124 帧、4 步，H.264 5.166667 秒、92,385 bytes、SHA-256 `8c3eb29adb8a1ac28a88b3155064b80b758b4cb621f26961773fe726a820a828` |

真实生成首次暴露过 `[Errno 22] Invalid argument`：traceback 指向 Turbo 节点打印日志时刷新已关闭的 stdout。改用统一启动器并保留日志句柄后，原任务通过前端“快速模式重试”完整完成。此记录说明启动方式是运行契约的一部分。

## 8. 维护与扩展

- 工作流节点 ID 与阶段映射同时修改；模板变化后运行 `npm run validate:workflows`。
- 新增前端参数时，先在 `validateVideoRequest()` 建立白名单，再在 `buildVideoWorkflow()` 注入；不要透传任意节点输入。
- 模型名和 Custom Node 类型不得只写在 UI；运行时检查必须能报告缺失项。
- `.runtime/releases/offline` 是可再生发行 staging，不是用户资产数据库；安装态项目、Job、输入/输出和临时目录继续写入应用 data/runtime/cache，卸载默认保留用户创作数据。
- 当前取消运行中任务使用 ComfyUI 的全局 interrupt；在多用户或与手工 Comfy 共用时必须改成隔离执行器。
- `comfyLaunchPolicy` 默认 `idle`，`comfyIdleSeconds` 默认 `300`；不得把外部进程标记为 `owned`，也不得在队列不为空时关闭。
- 本机已有 Depth Anything V2 与 OpenPose 预处理节点，但没有 ControlNet 权重；`upscale_models` 也为空。因此当前只登记候选方案，不开放不可执行的“定向调整”或模型超分按钮。
- 图像候选优先级：Real-ESRGAN（BSD-3-Clause，超分）、rembg（MIT，抠图）、SAM 2（Apache-2.0/BSD-3-Clause，交互分割）、Depth Anything V2 Small（Apache-2.0，深度）；Depth Anything V2 Base/Large/Giant 为 CC-BY-NC-4.0，商业默认不得选用。
- 本机阶段分发已有桌面壳、固定模型包、安装目录发现与哈希清单；正式公开分发仍需代码签名、自动/增量更新、完整 SBOM/法务、MiniMax H3 地域与下游条款执行、扩大驱动/系统矩阵和崩溃回滚。
