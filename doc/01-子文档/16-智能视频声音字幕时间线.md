# 光阴砚 AEONQUILL — 智能视频声音与字幕时间线

> 该文档隶属于[01-开发者文档](../01-开发者文档.md)，用于说明声音、字幕、混音与最终剪辑时间线。
> 本文回答：对白、旁白、音乐、环境声、音效和字幕如何编辑、审批、生成、混音并进入最终成片。

**最后一次更新时间**：2026-09-23

**更新者**：音频组、智能视频组、文档专项组

---

## 1. 用户操作路径

1. 在智能视频“声音字幕”节点打开时间线。
2. 在“声线”页为每个角色配置 provider、voice ID、语言和语速。
3. 试听后人工批准声线。
4. 在“音频”页编辑文本、时间、增益和淡入淡出。
5. 对对白/旁白执行批量 TTS，或从资源库绑定音频。
6. 试听并逐条批准音频。
7. 在“字幕”页校对文字与入出时间并批准。
8. 在“样式/混音”设置字幕安全区、目标响度、真峰值和对白闪避。
9. 执行混音，下载 WAV、SRT、VTT；ASS 交给成片器烧录。
10. 将完成的声音 Job ID 绑定到 final-cut。

入口：`src/modes/video/SoundTimelinePanel.tsx`。

## 2. 开箱状态

| 能力 | 无外部 Adapter | 说明 |
| --- | --- | --- |
| 自动建立时间线 | 可用 | 从 StoryProject 镜头与对白确定性编译 |
| 编辑/审批声线配置 | 可用 | 只保存配置，不生成音频 |
| 手动绑定 MP3/WAV | 可用 | 资源必须在当前项目可见 |
| TTS | 不可用 | 需要已配置的 speech Adapter |
| 字幕编辑与导出 | 可用 | SRT/VTT/ASS 由本地服务渲染 |
| 混音 | 可用 | 需要 FFmpeg 和所有必需音频已批准 |
| 最终烧录 | 可用 | 需要已完成视频与声音 Job |

TTS 自动回填不等于批准。用户必须试听生成结果并显式批准后，混音门才会放行。

## 3. SoundTimeline schema v1

实现：`src/lib/story/soundTimeline.mjs`。

```ts
type SoundTimeline = {
  kind: 'aeonquill.sound-timeline'
  schemaVersion: 1
  storyProjectId: string | null
  storyRevision: number | null
  durationMs: number
  voiceProfiles: VoiceProfile[]
  audioCues: AudioCue[]
  subtitleCues: SubtitleCue[]
  subtitleStyle: SubtitleStyle
  mix: MixSettings
  revision: number
}
```

限制：

| 项目 | 限制 |
| --- | --- |
| 总时长 | 30 分钟 |
| 声线 | 64 |
| 音频 cue | 2048 |
| 字幕 cue | 2048 |
| 单条文字 | 2000 字符 |

## 4. 声线

VoiceProfile 字段：

| 字段 | 含义 |
| --- | --- |
| characterId | 对应故事人物，可为空（旁白等） |
| speaker | 显示名称 |
| providerLabel | 当前语音提供方 |
| voiceId | 提供方声线 ID |
| language | 语言 |
| speed | 0.5—2 |
| status | draft / configured / approved |
| revision | 声线修订号 |

状态：

```text
draft --填写 provider + voiceId--> configured --试听并批准--> approved
```

修改已批准声线会回到 configured，并使依赖该声线的旧语音输入 fingerprint 失效。

---

## 5. 音频 Cue

支持五种 kind：

```text
dialogue / narration / music / ambience / sfx
```

每条 cue 保存：

- sceneId、shotId。
- 对白角色和声线引用。
- 文本/生成提示。
- startMs、endMs。
- gainDb：-60—12 dB。
- fadeInMs、fadeOutMs。
- required。
- 不可变音频资产绑定。
- planned / ready / approved 状态。
- 输入 fingerprint 与 revision。

约束：

- 淡入 + 淡出不能超过 cue 时长。
- 对白/旁白必须引用有效声线和 speaker。
- 非语音 cue 不能绑定角色声线。
- 当前接受 `audio/mpeg` 和 `audio/wav`。
- 音频资产绑定包含 library item/version、SHA-256、MIME、scope 和时间。

---

## 6. 字幕

字幕从 dialogue/narration cue 派生，并绑定原 audioCueId、shotId 与角色。每条字幕状态为 draft 或 approved。

UI 支持：

- 修改文字。
- 修改入点/出点。
- 单条批准。
- 批量批准。
- 每页 8 条浏览。

字幕样式：

| 字段 | 范围 |
| --- | --- |
| position | top / bottom |
| maxLines | 1—2 |
| safeMarginPercent | 5—20 |
| fontScalePercent | 70—140 |
| background | shadow / box / none |
| status | draft / approved |

字幕不交给 H3 生成；最终在后处理阶段确定性渲染。

---

## 7. 混音规格

固定格式：

```text
48000 Hz / stereo
```

可调参数：

| 参数 | 范围 | 用途 |
| --- | --- | --- |
| targetLufs | -24—-9 | 综合响度 |
| truePeakDbtp | -3—-0.1 | 真峰值限制 |
| dialogueDuckingDb | -18—0 | 对白窗口压低音乐/环境声 |

混音实现 `server/sound-renderer.mjs`：

1. 按时间对每条 cue 做 delay/trim。
2. 应用 gain 与淡入淡出。
3. 计算对白窗口并对其他轨道 ducking。
4. `amix normalize=0`。
5. `loudnorm` 到目标 LUFS/TP。
6. limiter 防止峰值超限。
7. 输出 48 kHz 双声道 WAV。
8. ffprobe 复核流、声道、采样率和时长。

## 8. TTS 准备与执行

`compileSpeechSynthesisPlan()` 只选择：

- kind 为 dialogue/narration。
- 当前没有音频资产。
- 对应声线 status 为 approved。

请求由服务器读取当前 WorkspaceStore 时间线编译；前端不能直接传任意媒体路径或篡改旧时间线。

Adapter 边界：

- API Key 只在 sidecar 内存。
- 每条产物写入 ProjectStore。
- 自动绑定后 status 为 ready。
- 用户试听批准后才变成 approved。
- 文本、密钥和供应商错误在公开日志中脱敏。

---

## 9. 混音放行门

`compileSoundMixPlan()` 要求：

- 全部 voice profiles 已批准。
- 全部 required audio cues 已绑定且批准。
- 全部字幕已批准。
- 字幕样式已批准。
- 混音参数已批准。
- 时间线 revision 与提交绑定一致。

任一条件不满足时返回 `SOUND_TIMELINE_NOT_APPROVED`，不启动 FFmpeg。

执行时再次解析每个音频 binding：

```text
library item/version
→ 当前项目可见性
→ content hash 和 MIME 一致
→ 本机受管文件
```

身份不一致返回 `SOUND_ASSET_IDENTITY_MISMATCH` 或 `SOUND_ASSET_HASH_MISMATCH`。

## 10. 字幕文件

服务端从同一批准时间线生成：

| 文件 | 用途 |
| --- | --- |
| SRT | 通用字幕交换 |
| VTT | Web 播放器 |
| ASS | 带样式烧录到最终视频 |

时间戳和文本转义由 `server/sound-renderer.mjs` 统一实现。浏览器不拼接字幕文件，避免预览与交付不一致。

---

## 11. Job 与最终剪辑

声音 Job 支持 queued、running、completed、failed、cancelled，UI 提供取消和按原输入重试。

完成结果包含：

- 受管 WAV。
- SRT URL。
- VTT URL。
- 内部 ASS。
- 输入时间线 revision 与摘要。
- 输出探针和质量信息。

`server/video-finalizer.mjs` 只接受完成的声音 Job ID，并再次核对项目、timeline revision 与摘要。旧混音不能静默烧入更新后的画面/字幕版本。

---

## 12. 修改时间线的后果

| 修改 | 失效范围 |
| --- | --- |
| 声线 provider/voiceId/speed | 对应未重生语音与其批准状态 |
| 对白文字 | 对应音频 fingerprint、字幕和旧混音 |
| cue 时间 | 字幕同步与旧混音 |
| 绑定新音频 | 该 cue 需重新批准 |
| 字幕文字/时间 | 该字幕与旧混音 |
| 字幕样式 | 旧 ASS 与 final-cut |
| LUFS/TP/ducking | 旧 WAV 与 final-cut |

重新编译 StoryProject 时，只有 fingerprint 一致的旧资产和审批可保留。

## 13. 新增音频 Adapter

1. 在 generation adapter 层定义 provider、模型和 capability。
2. 凭据只保存进程内存。
3. 输入只来自 `compileSpeechSynthesisPlan()`。
4. 限制响应大小、MIME、时长和超时。
5. 输出先写临时文件，经 ffprobe 后提升为不可变资产。
6. 回填精确 library item/version/hash。
7. 不自动批准。
8. 增加取消、部分失败、重试、刷新恢复和日志脱敏测试。

### 14.1 强制对齐与局部试听

在“音频”页选择已绑定音频的对白，点击“对齐片段”。确认调用后，服务端从当前正文读取已知文字和不可变音频，经实际音频时长探测后排入 CPU Job。WhisperX 只对齐给定文字，不替用户重新转录或自动批准。预览提供逐词入出点；明确应用后只修正关联字幕时间。文本、音频哈希或时间窗不再匹配时，旧候选不能应用。刷新后再次调用会恢复当前输入的已有完成结果。

安装入口：`node scripts/setup-speech-alignment.mjs --install --download-model --download-nltk`；仅验证为 `--verify-only`。更换机器时通过 `--python-path`、`--ffmpeg-path`、`--ffprobe-path` 指定兼容的绝对工具路径；隔离 venv 复用的基础环境需满足 WhisperX 的 PyTorch 依赖。默认 venv 位于 `.runtime/tools/speech-alignment/venv`，模型位于 `.runtime/models/speech-alignment/zh`。运行配置支持 `audioTools.pythonPath/modelDirectory`，或 `AEONQUILL_ALIGNMENT_PYTHON` / `AEONQUILL_ALIGNMENT_MODEL`。安装器固定模型 revision 与 SHA；执行器使用本地模型、离线模式和 CPU，不在执行时下载依赖。Tauri sidecar 将 runner 按内容哈希物化到受管 runtime 缓存。

接口：`GET /api/speech-alignment/status`、`POST /api/jobs/speech-alignment`、`GET /api/jobs/:id/alignment`。对齐词表只存在私有结果文件和按需结果接口中；公共 Job/SSE 只带身份、进度与词数。核心模块为 `soundAlignment.mjs`、`speech-alignment.mjs`、`speech-alignment-jobs.mjs`、`ConnectedSoundTimelinePanel.tsx`。

“样式/混音”提供两个相邻同类已批准片段的交叉淡化试听。`sound-render` 的 `render-local` 动作仅渲染选中的两条受管音频，输出 48kHz 双声道 WAV，保留原正文和其他片段；成片继续使用明确批准的完整混音。原有对白闪避、字幕审批和版本失效规则继续生效。

验证入口：`scripts/validate-local-sound-remix-api.mjs` 使用真实 FFmpeg 检查段长度、音频规格、幂等、跨项目/旧 revision 拒绝和无关片段保护；`scripts/validate-speech-alignment-ui.mjs` 必须使用安装完成的真实模型，依赖缺失时报告 unavailable，不计为通过。

## 15. 当前限制

- 字/词强制对齐通过本地 WhisperX 执行，必须先安装完整模型并通过预检；模型下载、真实样本偏差和人工听感验收状态见 02 的 AUDIO-001。音素与口型同步不在当前实现内。
- 当前没有口型同步。
- TTS 依赖用户选择并配置的 Adapter。
- `audio/mpeg` 与 `audio/wav` 是当前绑定白名单；其他格式需先规范化。
- 长音乐的智能结构化剪辑仍以人工 cue 和确定性混音为主。
