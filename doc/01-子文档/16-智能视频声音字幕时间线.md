# 光阴砚 AEONQUILL — 智能视频声音字幕时间线

> **文档梗概**：说明智能视频 `VideoProductionProject schema v4` 中声线、音频轨、字幕、样式与混音规格的权威数据结构、受控命令、审批门、迁移规则和当前执行边界。
>
> **最后一次更新时间**：2026-09-03
>
> **对应检查点**：`VIDEO-006 / V0.7.38`

---

## 1. 目标与边界

声音时间线把剧本中的对白、可识别旁白和镜头声音提示编译为可编辑、可复核、可迁移的生产事实。它解决的是“声音与字幕怎样被明确安排和批准”，而不是假装已经自动完成配音、强制对齐或最终混音。

当前检查点已经完成：

- 从 `StoryProject` 生成绝对时间码的对白、旁白、环境声、音效和音乐槽位；
- 角色声线配置与显式批准；
- MP3/WAV 项目资源或全局固定引用的不可变版本绑定；
- 对白/旁白音频、字幕文本与时间码、字幕安全区与样式、48kHz 双声道混音目标的独立审批；
- 故事、声线、文本、时间或混音变化后的精确失效；
- `sound-director` 生产节点的失败关闭门；
- SQLite 智能视频正文、`.aeonquill` 项目包和旧生产图迁移。

当前尚未完成：

- 根据声线和对白自动调用 TTS Adapter；
- 从真实音频分析时长并自动对齐字幕；
- 把音乐、环境声、音效和对白交给 FFmpeg 生成可播放混音；
- 把字幕作为软字幕或烧录字幕写入最终成片；
- 自动响度实测、口型同步和多语言翻译。

这些执行能力必须消费本时间线的已批准版本，不得建立第二套旁路状态。

## 2. 权威对象关系

```text
VideoProductionProject schema v4
├── continuityGraph schema v1             # 视觉连续性事实
└── soundTimeline schema v1               # 声音与字幕事实
    ├── voiceProfiles[]                    # 角色声线约束/批准
    ├── audioCues[]                        # 对白、旁白、音乐、环境声、音效
    │   └── asset ───────────────────────> 资源库不可变音频版本
    ├── subtitleCues[]
    │   └── sourceAudioCueId ────────────> 对白或旁白轨
    ├── subtitleStyle                      # 安全区、字体、颜色、描边
    └── mix                                # 48kHz/双声道/响度/真峰值/闪避
```

时间线以 `storyProjectId + storyRevision` 绑定故事。所有音轨和字幕使用从全片起点计算的毫秒绝对时间，避免按场景分别计时造成拼接漂移。ID 与输入指纹由规范化故事事实确定；重新同步故事时，内容与身份未变化的音频绑定可以保留，但所有受时间、样式或混音影响的批准会重新打开。

## 3. 音轨、声线与字幕

音轨类型限定为：

| 类型 | 来源 | 是否阻断声音导演批准 |
| --- | --- | --- |
| `dialogue` | 角色对白 | 必需；必须绑定并批准真实音频 |
| `narration` | 可识别旁白 | 必需；必须绑定并批准真实音频 |
| `music` | 全片情绪音乐床 | 可选；允许在后续执行版本补齐 |
| `ambience` | 每场连续环境声场 | 可选 |
| `sfx` | 从镜头动作中确定性提取的音效提示 | 可选 |

每个故事角色拥有一个声线档案。档案只保存供应方、声线 ID、语言、语速、音高和描述等有界文本/数值，不保存 API Key。声线参数变化会撤销该角色相关对白音频及其批准，防止旧音频被错误解释为新声线结果。

每条对白或旁白自动生成一条关联字幕。用户可以编辑字幕文字和时间码，并独立批准；修改对白文本会同时撤销对应音频和字幕批准，修改音轨时间会同步关联字幕的时间并重新打开批准。字幕样式使用相对安全区和有限视觉参数，不允许任意 CSS、文件路径或字体载荷。

## 4. 耐久音频绑定

音频槽只保存以下内容身份：

```ts
type SoundAssetBinding = {
  libraryItemId: string
  libraryVersionId: string
  contentHash: string       // 64 位小写 SHA-256
  mimeType: 'audio/mpeg' | 'audio/wav'
  scope: 'project' | 'global-reference'
  boundAt: number
}
```

禁止保存临时 URL、Data URL、本机绝对路径或凭据。资源选择由共享资源库返回当前项目可见的明确版本；绑定只进入 `ready`，用户还需检查内容哈希并执行“批准”。替换或移除资源会撤销批准。视频模式现在允许音频资源投递到声音时间线；均衡/像素模式不会把音频误当图片节点。

## 5. 受控命令与失败关闭

界面和后续 Agent 共用 `VideoProductionCommand`，声音域提供：

| 命令 | 作用 |
| --- | --- |
| `sound.voice.configure` / `sound.voice.approve` | 修改并批准角色声线 |
| `sound.asset.bind` / `approve` / `unbind` | 绑定、批准或移除音频版本 |
| `sound.cue.patch` | 修改文本、时间、增益和淡入淡出 |
| `sound.subtitle.patch` / `approve` | 修改并批准单条字幕 |
| `sound.subtitles.approve-all` | 批准当前全部字幕文本和时间码 |
| `sound.subtitle-style.patch` / `approve` | 修改并批准字幕安全区与视觉样式 |
| `sound.mix.patch` / `approve` | 修改并批准混音目标 |

命令携带生产项目 `baseRevision`。未知字段、过期 revision、重复 ID、越界时间、非法 MIME、伪造 SHA、路径泄露、跨角色声线引用、错误字幕关联、陈旧输入指纹和手工伪造批准均失败关闭。

`sound-director` 只有在以下条件同时满足时才能批准：

1. 所有对白/旁白拥有已批准音频版本；
2. 所有对应字幕已批准；
3. 字幕样式已批准；
4. 混音规格已批准。

可选音乐、环境声和音效不阻断当前管理门，避免在自动生成能力尚未接通时伪造资产；未来最终成片模板可以按交付档位把其中部分提升为必需。

## 6. 前端操作路径

1. 在多智能体制片工作室选择“声音字幕”节点；
2. 在“声线”页配置角色音色并批准；
3. 在“音频”页按类型筛选轨道，编辑时间/增益/淡入淡出；
4. 点击“选择音频”，从项目资源或全局固定引用中投递 MP3/WAV，再检查 SHA-256 并批准；
5. 在“字幕”页编辑文本与时间码，逐条或批量批准；
6. 在“样式/混音”页设置字幕安全区、视觉样式、响度、真峰值和对白闪避，并分别批准。

音频轨与字幕每页最多展示八项；长片不会一次挂载全部表单。桌面右侧检查器和 390×844 堆叠布局均复用智能视频统一视觉骨架。

## 7. 迁移、同步与恢复

`VideoProductionProject` 从 schema v3 升级到 v4：

- v1 仍先迁移到 v2 的策略、人物档案和变更卡；
- v2 迁移到 v3 连续性资产图；
- v3 新建 sound timeline；调用方持有 StoryProject 时直接编译声线、音轨与字幕；
- 没有 StoryProject 的旧独立导出建立同片长空时间线，并沿用连续性图的故事身份，不伪造对白资产；
- 节点状态、事件、审批、策略、人物档案和连续性资源不丢失。

`SmartVideoWorkbench` 建立生产图时会立即用当前 StoryProject 同步视觉和声音两张图，而不是先保存通用占位图再等重载迁移。智能视频外层仍为 schema v2，内层 production 为 schema v4；声音时间线随 SQLite 正文、恢复点和 `.aeonquill` 完整项目包一起往返，音频字节继续由内容寻址资源库外置管理。

## 8. 验证证据与后续执行

单元契约覆盖编译、门禁、修改失效、有界编辑、严格篡改拒绝、故事同步及 v1/v2/v3→v4 迁移。全仓 `269/269` 单元契约、TypeScript 和生产构建通过。后台 WebView 纵切实际完成：TTS Adapter 生成 MP3 → 项目资源库 → 第一条必需对白轨绑定 → 人工批准 → SQLite 自动保存 → 页面重载后哈希和批准状态恢复；桌面与 390×844 无页面级横向溢出，应用控制台问题为零。

本检查点没有启动 ComfyUI、没有执行 H3、没有声称已经产生最终混音或字幕成片，也没有修改 D 盘正式桌面。下一执行检查点应让 TTS/本地音频适配器按已批准声线与文本生成受管资产，再由 FFmpeg 消费同一时间线形成代理混音、字幕文件和最终交付输入。
