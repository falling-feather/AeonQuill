> **具体规划法则**：
>
> 1. 提交标题必须与实际 Git 提交标题完全一致。
> 2. 一次提交只对应一个版本号和一个任务编号。

> 4. 既有历史不因后续修改、清理或回滚删除。

## 4. 未纳入提交历史的当前基线

`V0.1.0` 之前已经存在无限画布、本地图像/视频桥接和 ComfyUI 工作流原型，但原 `.git` 目录为空，无法确认其原始提交日期或还原独立版本。首次提交只记录 2026-08-14 当天的整体快照；各模块更早的形成过程仍不在本历史文档中伪造成独立提交。

可核实的现状包括：

- `package.json` 声明版本 `0.1.0`。
- React、TypeScript 与 Vite 源代码位于 `src/`。
- 当前构建脚本是 `npm run build`。
- 当前已经存在 `server/` 本地桥接、CPU/GPU 持久化资源调度、固定 MiniMax H3 文生/图生模板、`config/` 机器配置，以及 `.runtime/` 下的执行期 Job/资产与正式 SQLite 项目/内容寻址资产目录。
- `FE-001` 已形成图片实验室、处理任务、派生节点、可变尺寸像素编辑和浏览器草稿处理器，并通过类型检查、构建与桌面/移动端浏览器验收。
- `DEV-001` 已形成文生/图生视频、本地 ComfyUI 适配、真实进度、日志、错误、取消、重试、MP4 回填和统一启动器，并在本机完成两种真实生成与浏览器验收。
- `DEV-002` 已形成 ComfyUI 按需生命周期、空闲安全关闭、导演控制、首末帧、任务参数复用、8GB 分层流水线、720P 确定性交付与高显存档位保护；类型、构建、实时工作流契约、生命周期、FFmpeg 和浏览器交互均完成验证。
- `DEV-003` 已形成六种可探测本地图像处理器、统一图片 Job/SSE/取消/重试、离线模型校验、资产下载与画布派生回填；u2netp 去背景、Real-ESRGAN Vulkan 超分和四种 FFmpeg 处理器均完成真实执行，图片模型与 H3 视频任务通过共享 GPU 闸门串行。
- `PM-001` 已建立从基线治理、产品级创作内核、专业创作链路、受控 Agent、商业 Beta 到证据驱动规模化的中长期优化路线，并定义阶段退出门禁、质量矩阵、专项优化、主要风险和决策点；详见[02-项目规划.md 第 7 节](02-项目规划.md#7-中长期优化路线)。
- `QA-001` 已形成 `quick`、默认安全基线和可选实时 H3 三层一键回归；初始覆盖 13 项单元/离线契约，后由 `SEC-001` 扩展为 18 项，并持续覆盖类型与构建、四种真实 FFmpeg 处理、隔离 API/SSE/PNG/Range、系统 Edge 桌面/移动烟测、Job 重启恢复和完成资产保留；机器可读结果写入 `.runtime/qa/latest.json`。

- `ARCH-001` 已建立 `CanvasDocument` schema v1、v7/version 2 迁移、严格文档与命令校验、actor 权限、工具注册表和 revision 冲突草稿；App 改为文档权威状态，手势预览不落盘且结束只提交一次修订，系统 Job 回填不污染用户撤销栈。当前 24/24 契约与完整 24 层门禁通过，Edge 已实际验证拖拽/撤销/重做与响应式；因无 Git 元数据，本条仍只登记未提交基线而非提交历史。
