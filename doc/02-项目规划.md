### 0.2 产品成熟度结论

当前产品已经是**功能较完整、可在本机真实执行的内部 Alpha**，不是概念 Demo；已形成可交用户验收的本机工程候选；完整Beta质量仍需素材校准和人工复核。当前差距不是功能数量不足，而是以下四个闭环尚未同时成立：

## 1. 产品目标与范围

### 1.1 产品定位

光阴砚 AEONQUILL 的目标是成为一个本地优先、API 可扩展的多 Agent 视觉创作平台。它以项目和共享资源库为底座，将三种创作方式组织在一个产品内：

| 模式 | 核心任务 | 目标体验 |
| --- | --- | --- |
| 均衡模式 | 无限画布、图像编辑、图像/视频元件、语义化处理和跨资源编排 | 从素材整理到视觉方案和生成结果的综合工作台 |
| 像素模式 | 像素绘制、图层、帧动画、调色板、Sprite/Tileset 与引擎交付 | 接近专业像素编辑器的可控生产链 |
| 智能视频 | 灵感/剧本拆分、角色与分镜、图像/视频生成、声音、剪辑和成片 | 可暂停、可修改、可重做节点的一站式多智能体制片 |

三种模式不是三个孤立应用。它们共享：

- 多项目目录与恢复点；
- 项目资源库和全局资源库；
- 不可变资产版本、来源和引用关系；
- CPU/GPU 任务调度、ComfyUI 生命周期与外部 API Adapter；
- 统一导入、输出目录、诊断、安全和发行策略。

### 1.2 目标用户与优先场景

近期优先服务个人创作者和小型工作室，覆盖：

1. 广告、商品、社媒和一般视觉视频创作；
2. 独立游戏像素角色、动画和资产包制作；
3. 解说、叙事、短剧及更长内容的镜头化生产。

产品不局限于短剧，也不把“全自动”作为唯一体验。快速模式强调低等待和早预览；专业/质量模式允许角色三视图、服饰/场景状态、首尾帧、关键帧、多候选和返工。

### 1.3 当前不承诺

- 尚不承诺公开商业签名、自动更新、跨机器完全兼容或任意第三方工作流可运行。
- 尚不承诺专业影视级角色锁、口型、声音导演或十分钟长片无人干预一次成功。
- 尚不承诺账号、订阅、云端多租户、团队协作和公共 GPU 服务。
- 用户导入的模型、节点、工作流和 API 必须单独核对许可、隐私、成本和安全边界。

## 4. 已批准的中期更新规划

### 4.1 中期目标

用户已批准下一中期目标定义为：

> **把当前“功能较全的本机 Alpha”收束成“事实可信、项目可携带、工作流可扩展、创作质量可复现的单机 Beta 候选”。**

这份目标优先解决产品真实性和全链路闭环，不以继续增加入口数量为主要成绩。

### 4.2 路线 A：运行时事实层

目标：用户看到的安装、模型、节点、状态、版本和实际执行环境完全一致。

主要设计：

1. 建立统一 `RuntimeRegistry`，登记 ComfyUI 根、Python、节点根、内置模型根、额外模型根、版本、哈希和反向引用。
2. 解析受支持的 `extra_model_paths.yaml`，把每个依赖的实际命中来源返回前端；下载前按内容哈希和逻辑模型 ID 去重。
3. 将能力状态拆成“未安装、已安装未启用、已启用休眠、正在唤醒、可执行、异常”。
4. 把产品 SemVer、功能轨版本、构建 SHA、运行时包 ID 和模型注册表版本统一放入设置、诊断和任务回执。
5. 清理或迁移旧运行时前先执行反向引用检查；没有确认不得删除仍被新运行时共享的模型。

退出门：

- 当前电脑上的 H3、SeedVR2、SAM 均被正确识别且不产生重复下载建议；
- 软件目录或运行时目录移动后，注册表可修复或给出明确引导；
- 正式桌面功能轨与 clean 源码一致，并完成单实例、退出、数据不变和真实工作流唤醒回归。

### 4.3 路线 B：项目、资源与工作流闭环

目标：项目可以完整带走，自定义工作流可以安全真执行，大文件增长可控。

主要设计：

1. 将均衡画布、像素正文、智能视频正文、生产状态、恢复点、项目资源引用和 provenance 纳入统一项目 manifest。
2. 导出前展示覆盖内容、模型是否随包、预计体积和缺失引用；导入时先检查版本、哈希、许可提示和冲突策略。
3. 为自定义 ComfyUI JSON 建立“安全导入 → 节点/模型检查 → 输入输出映射 → 参数 Schema → 沙箱执行 → 输出资产识别”的适配向导。
4. 自定义工作流只能使用批准节点、受控文件和资源 Job；不得向模型暴露任意本机路径或任意命令。
5. 建立空间仪表和保留策略：模型、Comfy input/output、中间帧、代理媒体、源片、失败候选、最终成片分别管理。

退出门：

- 一个包含三种模式正文和跨模式资源的项目可在干净用户目录完整恢复；
- 至少一条用户自定义图像工作流和一条视频工作流完成真实端到端 Job；
- 低磁盘、缺文件、移动目录、取消和崩溃恢复均不破坏原项目；
- 自动清理前可证明目标无引用，用户可查看并撤销尚在回收期内的删除。

### 4.4 路线 C：均衡与像素创作精进

均衡模式：

- 统一裁剪、调整、滤镜和蒙版为可重排的非破坏性效果栈；
- 把 SAM 元素提取扩展为区域编辑、定点修改、人像调整四个真实模板；
- 建立商品、人物、毛发/半透明、文字海报和复杂遮挡五类固定样本；
- 增加蒙版笔刷、前后对比、参数复用、批量处理和失败后局部返工。

像素模式：

- 动画标签、区间、帧持续时间批量编辑与跨帧复制已由 V0.7.40 完成，受控调色板循环、动画事件和活动片段包已由 V0.7.43 完成；

### 4.5 路线 D：智能视频旗舰链

目标：从灵感或剧本到成片形成可暂停、可修改、可局部重做的一站式生产线，并让质量模式显著优于当前末帧接力。

资产与 Agent 设计：

1. 编剧 Agent：结构化剧情、对白、节奏和预计时长。
2. 导演 Agent：风格、镜头语法、节奏、转场和质量/成本策略。
3. 角色 Agent：角色圣经、三视图、服饰/伤痕/道具状态、声音身份和镜头引用。
4. 分镜 Agent：镜头目的、构图、机位、动作、首尾/关键帧和连续性约束。
5. 生成监督 Agent：候选生成、清晰度/身份/运动/画面安全评分和定向重生。
6. 剪辑/声音 Agent：时间线、对白、旁白、字幕、BGM、环境声、响度与交付规格。

执行策略：

- 极速模式：低步数和代理分辨率，尽快得到全片可审预演。
- 质量模式：角色/场景参考、多候选、分段 Base、时序超分、镜头评分和失败重生，接受更长耗时。
- 快速人物：单张角色立绘和基础引用。
- 专业人物：三视图、服饰/场景状态、多角度引用与镜头级一致性检查。
- 任意节点允许暂停、替换输入、局部重跑；替换单镜不得强制重做全片。

固定样片建议：

| 样片 | 目的 | 最小产物 |
| --- | --- | --- |
| 视觉广告 | 验证产品图、文字安全区、节奏、声音和品牌交付 | 20—30 秒 720P，含旁白/字幕/BGM |
| 人物叙事 | 验证角色、服饰、场景、动作和镜头连续性 | 30—60 秒 720P，至少 6 镜 |
| 长片压力样本 | 验证断点、代理媒体、局部替换和最终成片 | 3—10 分钟低成本预演；质量片段单独重渲染 |

退出门：

- 从灵感/剧本到最终 MP4 的状态、输入、审批、费用/本机耗时和来源全程可追踪；
- 角色与声音质量采用固定样本、机器评分和人工盲评共同决定，不预先虚构阈值；
- 成片通过尺寸、帧率、编码、响度、黑帧、静帧、字幕安全区和抽帧门；
- RTX 4060 8GB 给出实测显存峰值、单镜耗时和失败恢复，不把单机结果外推到未测试硬件。

### 4.6 路线 E：本机工程与测试收口

目标：让当前开发成果可在 `D:/AEONQUILL/App` 稳定复现，并为后续每轮本机测试提供可回滚、可诊断、不会破坏用户数据的更新路径。

主要设计：

1. 每次本机更新从 clean Git 提交构建，界面、健康接口和任务回执统一显示产品版、功能轨和 source commit。
2. 应用二进制与 `UserData`、`output`、ComfyUI、模型和缓存严格分层；仅替换 `App` 内程序文件，更新前后复核配置、SQLite、项目资产和输出摘要。
3. 保留模式拆包、任务归档、脱敏诊断、崩溃恢复、单实例和进程退出门；失败时恢复上一组本机二进制，不回滚用户正文。
4. 工作框架、运行时和模型继续分层；工作流中心负责检测、下载提示、启用和错误说明，本机 App 更新不复制或删除大模型。
5. 本轮只服务当前电脑上的开发与手动测试；对外安装包、公共可信签名、许可证/SBOM 审计和真实用户验证不在当前计划中。

退出门：

- 最新本机 App 的功能轨与 clean source commit 可核对；
- 隐藏生命周期、四启动单实例、三模式关键纵切和退出后端口清理通过；
- 更新前后 `UserData`、正式 output、ComfyUI 与模型目录不变；
- 本机更新失败可恢复上一组程序文件，且不触碰项目正文和资产。
