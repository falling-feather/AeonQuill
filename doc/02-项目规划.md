### 0.2 产品成熟度结论

当前产品已经是**功能较完整、可在本机真实执行的内部 Alpha**，不是概念 Demo；但还不是可向外部用户承诺“稳定、完整、商业可用”的正式产品。原因不是功能数量不足，而是以下四个闭环尚未同时成立：

1. **事实可信**：工作流中心必须准确判断模型、节点、休眠和可执行状态，正式桌面必须能证明对应哪一份源码。
2. **数据可携带（V0.7.32 已闭环）**：`.aeonquill` 已能完整恢复均衡、像素、智能视频正文、资源引用、生产状态、恢复点与来源；旧 `.miaohui` 仅保留为明确不完整的均衡兼容输入。
3. **能力真执行（V0.7.33 已闭环）**：已导入并启用的自定义 ComfyUI 工作流能够经节点、模型、映射和受管文件复检安全提交统一 Job，支持取消并回填不可变资产，不再只是清单。
4. **质量可复现**：空间生命周期、四类语义图像功能纵切、可逆蒙版 v2、严格语义画质协议，以及角色/服饰/地点/首尾帧连续性资产图、逐镜真实视频候选版本和人工复核门已经具备；当前仍只有合成图像协议烟测与候选审批纵切，Qwen 三类真实素材画质、真实 H3 人物候选比较、盲审和长片声画仍需要固定样本及可重复实测。

## 1. 产品目标与范围

### 1.1 产品定位

光阴砚 AEONQUILL 的目标是成为一个本地优先、API 可扩展的多 Agent 视觉创作平台。它以项目和共享资源库为底座，将三种创作方式组织在一个产品内：

| 模式 | 核心任务 | 目标体验 |
| --- | --- | --- |
| 均衡模式 | 无限画布、图像编辑、图像/视频元件、语义化处理和跨资源编排 | 从素材整理到视觉方案和生成结果的综合工作台 |
| 像素模式 | 像素绘制、图层、帧动画、调色板、Sprite/Tileset 与引擎交付 | 接近专业像素编辑器的可控生产链 |
| 智能视频 | 灵感/剧本拆分、角色与分镜、图像/视频生成、声音、剪辑和成片 | 可暂停、可修改、可重做节点的一站式多智能体制片 |

三种模式不是三个孤立应用。它们共享：

- 多项目目录与恢复点；
- 项目资源库和全局资源库；
- 不可变资产版本、来源和引用关系；
- CPU/GPU 任务调度、ComfyUI 生命周期与外部 API Adapter；
- 统一导入、输出目录、诊断、安全和发行策略。

### 1.2 目标用户与优先场景

近期优先服务个人创作者和小型工作室，覆盖：

1. 广告、商品、社媒和一般视觉视频创作；
2. 独立游戏像素角色、动画和资产包制作；
3. 解说、叙事、短剧及更长内容的镜头化生产。

产品不局限于短剧，也不把“全自动”作为唯一体验。快速模式强调低等待和早预览；专业/质量模式允许角色三视图、服饰/场景状态、首尾帧、关键帧、多候选和返工。

### 1.3 当前不承诺

- 尚不承诺公开商业签名、自动更新、跨机器完全兼容或任意第三方工作流可运行。
- 尚不承诺专业影视级角色锁、口型、声音导演或十分钟长片无人干预一次成功。
- 尚不承诺账号、订阅、云端多租户、团队协作和公共 GPU 服务。
- 用户导入的模型、节点、工作流和 API 必须单独核对许可、隐私、成本和安全边界。

## 4. 已批准的中期更新规划

### 4.1 中期目标

用户已批准下一中期目标定义为：

> **把当前“功能较全的本机 Alpha”收束成“事实可信、项目可携带、工作流可扩展、创作质量可复现的单机 Beta 候选”。**

这份目标优先解决产品真实性和全链路闭环，不以继续增加入口数量为主要成绩。

### 4.2 路线 A：运行时事实层

目标：用户看到的安装、模型、节点、状态、版本和实际执行环境完全一致。

主要设计：

1. 建立统一 `RuntimeRegistry`，登记 ComfyUI 根、Python、节点根、内置模型根、额外模型根、版本、哈希和反向引用。
2. 解析受支持的 `extra_model_paths.yaml`，把每个依赖的实际命中来源返回前端；下载前按内容哈希和逻辑模型 ID 去重。
3. 将能力状态拆成“未安装、已安装未启用、已启用休眠、正在唤醒、可执行、异常”。
4. 把产品 SemVer、功能轨版本、构建 SHA、运行时包 ID 和模型注册表版本统一放入设置、诊断和任务回执。
5. 清理或迁移旧运行时前先执行反向引用检查；没有确认不得删除仍被新运行时共享的模型。

退出门：

- 当前电脑上的 H3、SeedVR2、SAM 均被正确识别且不产生重复下载建议；
- 软件目录或运行时目录移动后，注册表可修复或给出明确引导；
- 正式桌面功能轨与 clean 源码一致，并完成单实例、退出、数据不变和真实工作流唤醒回归。

### 4.3 路线 B：项目、资源与工作流闭环

目标：项目可以完整带走，自定义工作流可以安全真执行，大文件增长可控。

主要设计：

1. 将均衡画布、像素正文、智能视频正文、生产状态、恢复点、项目资源引用和 provenance 纳入统一项目 manifest。
2. 导出前展示覆盖内容、模型是否随包、预计体积和缺失引用；导入时先检查版本、哈希、许可提示和冲突策略。
3. 为自定义 ComfyUI JSON 建立“安全导入 → 节点/模型检查 → 输入输出映射 → 参数 Schema → 沙箱执行 → 输出资产识别”的适配向导。
4. 自定义工作流只能使用批准节点、受控文件和资源 Job；不得向模型暴露任意本机路径或任意命令。
5. 建立空间仪表和保留策略：模型、Comfy input/output、中间帧、代理媒体、源片、失败候选、最终成片分别管理。

退出门：

- 一个包含三种模式正文和跨模式资源的项目可在干净用户目录完整恢复；
- 至少一条用户自定义图像工作流和一条视频工作流完成真实端到端 Job；
- 低磁盘、缺文件、移动目录、取消和崩溃恢复均不破坏原项目；
- 自动清理前可证明目标无引用，用户可查看并撤销尚在回收期内的删除。

### 4.4 路线 C：均衡与像素创作精进

均衡模式：

- 统一裁剪、调整、滤镜和蒙版为可重排的非破坏性效果栈；

像素模式：

### 4.5 路线 D：智能视频旗舰链

目标：从灵感或剧本到成片形成可暂停、可修改、可局部重做的一站式生产线，并让质量模式显著优于当前末帧接力。

资产与 Agent 设计：

1. 编剧 Agent：结构化剧情、对白、节奏和预计时长。
2. 导演 Agent：风格、镜头语法、节奏、转场和质量/成本策略。
3. 角色 Agent：角色圣经、三视图、服饰/伤痕/道具状态、声音身份和镜头引用。
4. 分镜 Agent：镜头目的、构图、机位、动作、首尾/关键帧和连续性约束。
5. 生成监督 Agent：候选生成、清晰度/身份/运动/画面安全评分和定向重生。
6. 剪辑/声音 Agent：时间线、对白、旁白、字幕、BGM、环境声、响度与交付规格。

执行策略：

- 极速模式：低步数和代理分辨率，尽快得到全片可审预演。
- 质量模式：角色/场景参考、多候选、分段 Base、时序超分、镜头评分和失败重生，接受更长耗时。
- 快速人物：单张角色立绘和基础引用。
- 专业人物：三视图、服饰/场景状态、多角度引用与镜头级一致性检查。
- 任意节点允许暂停、替换输入、局部重跑；替换单镜不得强制重做全片。

固定样片建议：

| 样片 | 目的 | 最小产物 |
| --- | --- | --- |
| 视觉广告 | 验证产品图、文字安全区、节奏、声音和品牌交付 | 20—30 秒 720P，含旁白/字幕/BGM |
| 人物叙事 | 验证角色、服饰、场景、动作和镜头连续性 | 30—60 秒 720P，至少 6 镜 |
| 长片压力样本 | 验证断点、代理媒体、局部替换和最终成片 | 3—10 分钟低成本预演；质量片段单独重渲染 |

退出门：

- 从灵感/剧本到最终 MP4 的状态、输入、审批、费用/本机耗时和来源全程可追踪；
- 角色与声音质量采用固定样本、机器评分和人工盲评共同决定，不预先虚构阈值；
- 成片通过尺寸、帧率、编码、响度、黑帧、静帧、字幕安全区和抽帧门；
- RTX 4060 8GB 给出实测显存峰值、单镜耗时和失败恢复，不把单机结果外推到未测试硬件。

### 4.6 路线 E：工程与商业 Beta

| H3、SeedVR2、SAM 与自定义节点 | H3/SeedVR2 已由当前根识别；SAM 模型已命中但 cu130 缺 Impact Pack | 补齐节点必须经固定来源/哈希/许可复核，商业许可仍需审计 |
| 外部文本/图像/视频/TTS API | BYOK Adapter 已有基础 | 真实服务差异、价格、隐私和错误语义需逐家适配 |
| D 盘空间 | V0.7.34 已提供分类空间仪表、低空间预算和安全清理 | 长片、多候选和重复模型仍会迅速放大；模型/节点/最终交付不自动删除，需用户依据仪表单独治理 |

### 7.2 主要风险

- 检测与迁移已完成，但旧 cu129 根仍承载 6 类共享模型引用；在引用归零和独立删除验收前清理仍会破坏 H3/SeedVR2。
- 继续只提升功能入口而不补数据包和执行闭环，会扩大“看起来能用、实际不能完整交付”的差距。
- 视频质量如果只用单条样片和机械指标判断，会掩盖身份漂移、服饰变化、声音割裂和叙事问题。
- 自签名只能证明测试包内文件一致性和主体标识，不能替代公共可信签名。
- 商业发行前若不核对模型/节点/API 许可、用户素材隐私和内容安全，盈利计划存在实质合规风险。

### 7.3 后续决策门

W1 → W2 → W3 → W4 的主顺序和“事实可信优先”已经由用户批准。W1 已完成；以下决策保留到对应波次入口，不阻塞已登记的 W2 任务：

1. `AI-002` 已于 V0.7.58 完成并迁入历史：三模式安全工具目录、草稿预览、统一审批、权威提交和执行回执均已进入固定回归；后续接入真实文本模型时必须复用该协议，不得恢复任意 JSON 写入。
2. W3 已完成 `IMG-001` 四类语义编辑功能纵切、V0.7.36 `AI-001` 协议/确定性返修检查点、V0.7.37—V0.7.39 连续性与声音执行链、V0.7.49—V0.7.52 逐镜真实视频候选/局部替换/本地 H3 单镜头及连续长片逐镜自动回填与可信断点复用/固定 720P 机器交付门，以及 V0.7.40—V0.7.48 像素动画/跨帧编辑、图层组/确定性混合、逐帧游戏元数据、调色板循环/动画事件、活动片段、Terrain 九宫格、三引擎单向桥接、跨帧/跨图层选区剪贴板、持久化任意尺寸与多 Terrain Map 交付；W4 已由 V0.7.53 的三模式动态拆包、V0.7.54 的可追溯任务归档、V0.7.55 的一键脱敏诊断包和 V0.7.56 的产品性能机器门继续推进。待真实模型与样片条件具备时继续图像/视频定型，并按独立检查点登记原生编辑器往返、地形层/对象层、缺失图块建议或 Worker 化任务；Tauri/跨硬件性能纳入发行矩阵。
3. 下一正式产品 SemVer 是否在下一次发行时提升，而不是继续沿用 `0.7.1`。

W1—W4 已成为当前长期路线；截至 V0.7.58，W1—W2 已关闭，跨模式受控计划检查点已经完成，其他 W3 与 W4 项按独立任务推进。只有第 6 节已登记并认领的任务可以执行；路线本身不授权自动下载模型、改动正式桌面或删除旧运行时。

## 8. 商业化与发行边界

技术上可以把本产品做成可盈利的桌面创作工具，本地 Node/Python/ComfyUI、按需模型和外部 API 的混合架构也能够由服务器端或本机端支持。但商业可行不等于当前已具备发行条件。

商业 Beta 至少需要：

1. 明确软件授权方式、离线使用、设备迁移和退款/支持边界；
2. 对 ComfyUI、自定义节点、模型、字体、素材、FFmpeg/Python 依赖和 API 服务逐项建立许可证/SBOM；
3. 公共可信代码签名、更新、回滚、崩溃诊断和干净 Windows 兼容矩阵；
4. BYOK 密钥、本机素材、外部 API 上传和可选日志上报的隐私说明；
5. 本地 GPU 耗时、云端 API 费用、磁盘占用和失败重试对用户可见；
6. 以真实设计伙伴证据证明核心链路节省时间或提高质量，而不只证明可以运行。
